# 灵犀 AI 助手

服务器部署的个人助手。当前提供 React／TypeScript Web、FastAPI Core、持久化 worker、PostgreSQL 权威记录，以及 Hindsight 长期记忆适配器。沿用午夜蓝主题、四字菜单、47 个路由和十阶段开机动画。

**当前状态：代码与本机 Docker 已更新至 v1.82／schema0060；真实模型接入、跨会话召回和 150 题中文质量仍待验证，尚不能标记“聊天与记忆闭环已交付”。** 完整目标见[设计方案](./灵犀AI助手设计方案.md)，本文件说明实际代码。

## 长会话原文检索（v1.82）

“历史原文”改为分批扫描和加密游标分页，每页十条；先按冻结分支前缀、再按本会话顺序读取，不预载全量历史，不计算总数。预览定位关键词附近，支持中文与 Unicode 忽略大小写的字面匹配。删除上一页锚点不会跳过后续消息，重新检索可纳入新消息；查询截止时刻不冻结权限与事实。

补读按单条来源读取并携带原文指纹，内容／角色变化、来源删除或工作区失配时清除旧片段；分页绑定身份、查询和分支，过期须重新检索。页面慢请求不叠加，迟到响应不覆盖新查询，结果翻页焦点可达。同步补上核心历史读取的消息工作区过滤，既有午夜蓝、47 路由及开场不变。旧偏移与精确计数接口兼容，无新增迁移或模型调用，操作见[上下文使用说明](./deploy/上下文使用说明.md)。

合成固定服务／语音配置／人格音色快照，复用系统代理与每分钟共享语音预算；worker 先提交 `calling` 屏障再付费调用，崩溃恢复不自动重放。文字回执后才发送单独的 `record` 消息；未知发送不重发，协议接受不等于听到或已读。加密临时波形在发送意图、撤权／删除、恢复隔离或一小时过期时清理；恢复检查点保留无正文／无波形的调用、投递与外部消息 ID 屏障，旧备份按删除记录与隔离流程恢复后再启用。此开关不用于主动消息，不创建浏览器语音会话。

迁移 `0030`；已有语音回复记录时禁止直接丢弃调用／投递屏障降级，回退使用升级前备份及配套镜像。实际 QQ 登录、NapCat 音频收发和供应商音质仍待验证，不将隔离协议测试等同于这些验收。操作与证据见 [QQ 接入说明](./deploy/QQ接入说明.md#语音回复v135) 和 [QQ 语音回复验证记录](./deploy/QQ语音回复验证记录.md)。

## QQ 语音（v1.34）

“平台接入 → 渠道规则 → 编辑规则 → 语音接收”提供独立、默认关闭的开关，需预览确认。先在“语音配置”启用并验证 ASR，QQ 与浏览器共用模型配置、系统代理及每分钟 30 次语音请求预算；QQ 输入不会开启浏览器麦克风、实时会话或扬声器。

接收 OneBot `record.data.file` 的受支持 NapCat 缓存标识（32 位十六进制，可带 amr／silk／slk／wav 后缀），忽略其 `path` 和 `url`。固定版本 NapCat 的 `get_record` 负责转换，使用已认证反向连接的匹配回执读取 WAV base64，不访问协议端磁盘或任意直链。每条最多一段语音，转换最长 60 秒；音频限 0.1–60 秒、6 MiB、16 位 PCM WAV，并计入单消息附件总量。其他缓存键格式明确报不支持，真实账号上报仍需验证。

WAV 与识别结果按上传语音附件管理，关联原会话、发送者和版本来源，支持查看／下载／删除；与浏览器临时麦克风录音分开。持久化 worker 识别后统一聊天，只向原 QQ 会话回复文字。转写明确标注“未经确认”，不是个人事实或工具授权；含语音的整条消息不自动抽取记忆，后续用文字重新明确表达后才走正常记忆规则。本人私聊可按已有绑定共享记忆检索，群聊始终隔离。

付费识别前先持久化调用屏障，错误、超时或崩溃不盲目重复调用；断线的未完成转换不自动重发。删除／撤权／原会话删除及识别期间配置变化会丢弃失效结果，全部附件就绪前不忽略部分资料作答。迁移 `0029`；已有语音记录时禁止直接降级，使用升级前备份及配套镜像回退。

## 固定 API 插件（v1.26）

插件经原有目录、审核、签名及安装预览流程提供固定 HTTP(S) API。每项能力独立配置无密钥／Bearer／API Key 连接，密钥加密存储且不回填；服务器内网需要明确允许。只读 GET 与外部写请求使用不同权限，不能动态拼接地址或执行脚本。

在“技能工具”填写受限 JSON 字段，先生成 5 分钟有效且绑定当前登录的预览，核对端点、方法、数据、连接、版本、费用后勾选确认。预览不发送业务请求。确认与作业同事务保存，worker 在网络发送前保存发送标记；重复确认、重启与租约接管不能重发已进入发送阶段的请求。外部写请求在同能力已有在途或待核对调用时被阻止。

“请求成功”只表示 HTTP 2xx 与有界 JSON，不证明第三方业务操作完成。超时、错误、撤权、取消或发送中崩溃进入“结果待核”；到第三方核对后在运行记录登记依据，明确为用户报告，系统不自动重试。停用阻止新调用，卸载撤销专用凭据。API 不直接读取记忆、调用模型或自行联系用户，尚未加入聊天／子助手的自动执行链。

在“系统设置 → 语音配置”启用语音，分别选择服务连接与供应商模型，保存后录音验证转写、生成合成示例。接口为 OpenAI 兼容 `audio/transcriptions`（multipart／JSON 转写）和 `audio/speech`（PCM WAV）；使用原样保存的接口根地址及系统代理，不自动补 `/v1`。模型目录自动从供应商读取，音色标识按服务支持情况填写。密钥继续使用现有加密连接，不下发到浏览器。

新建或打开聊天后点击“开启语音”，再点“开始录音”；结束后先核对／修改转写，再“确认发送”。临时转写不生成消息或记忆；确认后才进入原有持久化聊天与抽取流程。回复完成后逐句合成并播放；声音为 AI 合成，浏览器阻止自动播放时需点击“继续播报”。默认采用**手动核对链式流程**；可按 v1.37 明确开启连续模式，本地停顿自动发送。原生双向实时会话仍未接入。完整说明见[语音使用说明](./deploy/语音使用说明.md)。

录音最长 58 秒，浏览器输出 16 kHz／单声道／16 位 PCM WAV；服务器上限 60 秒、6 MiB。采集、转写和合成缓冲只驻内存，不写文件、普通日志或长期记忆。一次语音会话最长 15 分钟，20 秒心跳，60 秒未续约停止新请求；页面隐藏、切换对话、离线或结束会话时释放音轨并停止播音。结束语音不等于取消服务器任务。每位所有者每分钟最多 30 次音频请求；上游费用不因取消而撤销。

播放回执以**已完整播完的短句**保守记录；被打断的半句不计入下一轮语音上下文，全文仍可在聊天阅读。新语音消息固定此前播放边界，迟到回执不能扩大它。删除来源使关联回复失效，合成返回前重新检查，前端按消息状态停止失效播音；已传给上游、播放或下载的内容无法收回。浏览器回执只能表示浏览器完成播放，不代表用户实际听见。

数据库迁移 `0010` 增加语音配置、有效会话和播放回执。接口契约见 OpenAPI 的 `/api/voice/config`、`/api/voice/sessions`、`/api/voice/playbacks`。配置和服务版本变化后重新验证；录音验证只检查非空转写与协议，不证明识别准确度。当前测试使用隔离的真实 HTTP 协议服务及合成音源，**实际供应商、物理麦克风、中文质量、延迟目标和 30＋10＋10 语音专项仍待验证**。QQ 语音输入与短回复音频输出增量见 v1.34／v1.35；连续对话本地分段见 v1.37；原生双向适配及音频保留选项仍待开发；手动模式实时字幕输入见 v1.57；会话内主动语音见 v1.49。人格音色联动见下节。

## 人格音色联动

在“助手管理 → 人格管理”填写供应商支持的默认音色标识；在“系统设置 → 语音配置”保存“跟随人格默认音色”，选择人格并点击“验证音色”。默认关闭，既有语音配置保持原样。验证会请求当前 TTS 服务，可能计费；播放器需主动点击试听，不开启麦克风或自动播放。人格未填写音色时使用已验证的系统默认；自定义音色未验证或已失效时，停止播报并保留文字，不静默替换。

语音提交时固定人格版本和实际音色；修改或切换人格只影响后续新回合，重复提交保留原快照与播放进度。停用人格、失效来源、撤销会话或变更服务会拦住后续及迟到音频。音色验证按连接版本、TTS 模型、语速和音色绑定，相同音色可复用验证；最多保留 100 项自定义音色验证，超出后旧项需重新验证。调用记录保存实际音色；不保存音频或人格指令。新增 `/api/voice/personas` 和 `/api/voice/personas/{id}/test`，本批复用 JSON 配置，schema 仍为 `0020`。旧版 Core 会忽略联动，因此使用新能力后不应只换回旧镜像。详见[语音使用说明](./deploy/语音使用说明.md)。

本批验证（2026-10-29）：Linux＋独立 PostgreSQL 完整后端 **668 项**、Windows 语音与人格音色专项 **62 项**、前端 **144 项**通过；类型、静态检查及构建通过。隔离 HTTP 验证核心聊天、逐音色合成、回执、重试去重、版本固定和重启保留；页面完成手动音色验证及四档无横向溢出检查，矮屏可滚动、键盘可提交。使用合成模型及音频，真实供应商、物理设备、中文发音质量与延迟仍待验证。

本机 `http://localhost:8080` 已保存升级前数据库备份与 `pre-v125` 配套镜像，更新 Core／worker／Web；schema 保持 `0020`。原业务数量、模型／连接／用途全字段（含加密凭据）、人格和语音配置摘要保持一致；认证门禁、OpenAPI、实际 Web 构建及 worker／Core／数据库／Hindsight 健康核对通过，未导入 QA 数据或修改真实音色设置。

## 助手与支持偏好

在“助手管理”可维护人格、执行角色、助手组合及支持偏好，预置并肩伙伴、资料研究、项目规划和文件执行四类人格／角色。编辑采用版本检查，发生冲突时保留草稿并提示重新加载；复制生成停用副本，停用须确认。版本记录每页最多 50 条，可继续加载。配置不能扩大工具、模型或记忆授权。

新建或打开对话后，在“会话人格”选择并点击“切换人格”。未显式选择时采用内置并肩伙伴；选择已保存人格后，新回合使用该人格最新有效版本，已提交回合保留原快照，切换不另建记忆档案。生成中暂不允许切换。偏好模型必须为当前连接版本验证通过的日常对话模型；不设置则沿用对话用途模型。停用或失效时如实报错，不静默冒用其他配置。

支持偏好从下一次生成开始使用。当前感受仅来自用户明确填写的自述，可设置 1–24 小时有效期；相同自述重复保存不延长时限，清空并保存可撤回。关闭适配需确认并保存，将清除当前自述；不会推断未回应的心情。版本与支持方式记录在回合配置中，自述不进入长期记忆或审计正文。此功能尚不包含语音情绪识别、心理诊断或自动分析。

管理接口为 `/api/personas`、`/api/agent-roles`、`/api/agent-profiles`（查询、新增、版本检查修改、复制及版本历史）、`/api/conversations/{id}/persona` 和 `/api/support-preferences`。全部复用登录、工作区隔离、CSRF、审计及服务端检查；契约见 [OpenAPI](./backend/openapi.json)。数据库通过增量迁移 `0004` 增加配置、不可变版本、会话人格和偏好四张表。

## 任务、Skills 与一次性提醒

“任务中心 → 任务列表”可提交项目规划或资料清单。项目规划使用当前已验证的对话模型，任务固定模型与连接版本；输出含 1–8 个行动步骤及完成条件，仅校验结构，不声称计划已执行。资料清单通过 Linux `openat`／`O_NOFOLLOW` 读取服务器授权资料卷的当前目录，最多返回 200 项、最多扫描 1000 个条目，跳过符号链接和特殊文件；不读取文件正文、不执行脚本、不接收电脑绝对路径。目录变化或达到限制会如实报告。

任务创建与数据库作业同事务提交，同一请求编号不重复创建任务。worker 使用租约与 fencing 防止旧执行写回，记录 attempt 和状态事件；当前无外部写入的 Skill 最多自动尝试 3 次，明确失败后可确认重试。中断恢复可能重新产生模型调用费用，不重复已提交的结果与会话消息。取消先阻止结果提交，运行中的请求须等执行器确认，不能撤销已产生费用。任务与列表采用游标分页（默认 50、最多 100），详情显示固定配置与真实回执。

“待办提醒”支持未来 366 天内的一次性提醒，按浏览器时区输入并保存绝对时间与 IANA 时区。提醒记录与定时作业同事务保存；修改或取消后旧版本作业不能触发。浏览器关闭时服务器仍可执行，服务停机错过时刻后会在恢复时补存一次，并保留实际存入时间。默认写入站内及明确选择的 Web 会话；v1.74 可逐条确认 QQ 私聊投递（见上方说明），不调用浏览器推送或自动播音；“已存站内”不等于已读，只有点击“标记确认”才记录确认。到期写入最多尝试 5 次，最终失败单独显示，可重新安排。

“插件中心 → 技能工具”提供 `lingxi.builtin` 的三类能力清单及输入约定。第一方能力已有固定版本与服务端检查，第三方目录可经独立商店验证接入，账号连接已有固定 API／MCP／OAuth，聊天协作需明确选工具并逐次确认；第一方安装管理与子助手依赖编排已分别提供。管理接口为 `/api/tasks`（创建／列表／详情／取消／明确重试）、`/api/skills`、`/api/reminders`（创建／列表／修改／取消／确认）。数据表通过迁移 `0005` 增加，全部接口检查登录、工作区、真实所有者与 CSRF；不将任务输出自动写入长期记忆。

默认 Compose 以只读卷 `server-resources` 提供 `/app/resources`，初始为空。可由部署管理员通过 override 将已有服务器目录分别挂到 Core 和 worker 的同一路径，例如：

```yaml
# compose.resources.yaml；请先准备 /srv/lingxi-resources，确保 UID 10001 可读
services:
  core:
    volumes:
      - /srv/lingxi-resources:/app/resources:ro
  worker:
    volumes:
      - /srv/lingxi-resources:/app/resources:ro
```

使用 `docker compose -f compose.yaml -f compose.resources.yaml up -d` 应用。只挂载计划授权的资料目录，不能把服务器根目录或凭据目录当作资料卷；挂载后还须在“系统设置 → 资源授权”明确预览和确认目录，默认无访问许可。worker 默认有 2 个执行槽位，可用 `LINGXI_WORKER_CONCURRENCY=1..8` 调整；这与未来每个父任务的子助手并发上限分别管理。

## WSL＋Docker 部署

在 Ubuntu 终端操作，Linux x86_64 为部署目标：

```bash
cd /mnt/c/project/project3
```

需要 Docker Engine、Compose v2。以下示例使用 `sudo docker`；已有 Docker 权限可去掉 sudo。基础镜像为：

```bash
sudo docker pull groonga/pgroonga:4.0.8-debian-17
sudo docker pull python:3.13.15-slim-bookworm
sudo docker pull node:24.20.0-bookworm-slim
sudo docker pull nginx:1.28.3-alpine
sudo docker pull ghcr.io/vectorize-io/hindsight:1.1.0-slim
```

使用 slim Hindsight，通过 Core 私有网关调用模型，不在容器里加载本地模型。数据库构建另安装固定 pgvector 扩展；构建仍需联网安装 npm、pip 和 apt 依赖。

首次生成 `.env`，**已有文件不要覆盖**：

```bash
sudo docker run --rm -v "$PWD:/app" -w /app python:3.13.15-slim-bookworm \
  sh -c 'pip install --no-cache-dir cryptography==46.0.5 && PYTHONPATH=backend python -m lingxi.cli configure'
sudo docker compose config --quiet
sudo docker compose build
sudo docker compose up -d
sudo docker compose ps
```

也可在已安装后端依赖的 Python 3.13.15 环境运行 `PYTHONPATH=backend python -m lingxi.cli configure`。命令独立生成数据库密码、Fernet 主密钥及内部 token；模型密钥不在模板内。不要分享 `.env` 或未脱敏的 `docker compose config`。

迁移由 Compose 自动执行；Core 就绪后启动其余服务。Hindsight 跳过启动时的外部 LLM 检查，允许先配置模型，**不代表模型可用**。

初始化唯一所有者，在终端交互输入用户名、密码：

```bash
sudo docker compose run --rm core python -m lingxi.cli init-admin
```

密码至少 12 字符，没有默认管理员密码；已有所有者时拒绝覆盖。打开 **http://localhost:8080** 登录，主机名须与 `.env` 中 `LINGXI_PUBLIC_ORIGIN` 一致；改用 127.0.0.1 时应同步修改配置并重建服务环境。

登录位于开机动画的“身份确认”阶段：未登录时输入用户名和密码；有效会话显示真实用户名，点击“确认进入”后才加载业务页面。每次打开、刷新、退出、会话失效或手动重播，都先检查服务器会话：未登录（401）从品牌序幕完整播放，有效会话直接进入身份确认；原 Hash 页面地址保留。动画重播同样遵循登录状态，并要求重新点击身份确认。跳过和 Escape 只跳过视觉过场，不能跳过身份步骤。会话检查期间显示“正在检查登录状态”，检查失败停留在静态身份页并提供“重试连接”；网络异常不视为未登录，重试成功后再决定播放起点。动画脚本或样式加载失败时显示相同身份组件的静态全屏页面。

等待输入不计入动画停滞超时；认证请求 15 秒超时后可重试。密码仅随登录请求发送，不写入动画参数、浏览器存储或日志；首次使用说明仍指向终端初始化。播放规则不再依赖标签页已播放标记，已有 lingxi.boot.seen 标记会被忽略。每次开场只确定一次起点，密码错误、登录成功或确认时会话失效都不会重启序幕。

默认仅绑定 `127.0.0.1:8080`。数据库、Core、Hindsight 不发布宿主端口；Hindsight 自带管理台关闭。生产访问需配置可信 HTTPS 反向代理、实际 `LINGXI_PUBLIC_ORIGIN`、`LINGXI_COOKIE_SECURE=true`，并配置 Web 监听及网络边界。当前 Compose 不自动申请证书，不默认公开服务。

## 配置模型与记忆验证

1. “模型管理 → 服务连接”：添加兼容基址与密钥。公网要求 HTTPS；可信内网服务才勾选内网授权；不跟随重定向。
2. “模型目录 → 添加模型”：选择服务连接后，自动从该连接的 `/models` 获取模型清单，可筛选并从下拉框选择；切换连接会清空旧选择，迟到的旧请求不会覆盖新列表。仅支持从供应商列表选择，已移除“刷新列表”和“手动填写模型标识”；读取失败时检查服务地址，再重新打开添加窗口。停用的连接不可选。模型用途与上下文窗口仍需填写，目录不代表具体能力已验证。
3. 分别登记日常对话、记忆抽取、向量嵌入、检索重排，再点击“验证能力”。同一文本模型可分别登记两个用途；兼容地址不代表支持全部用途。验证会向提供商发送少量固定测试文本，可能按其规则计费。
4. “路由策略”：通过“配置检查”查看缺口，选择各用途验证通过且连接已启用的模型。文本使用 `/chat/completions`，嵌入使用 `/embeddings`，重排需要 Cohere／SiliconFlow 兼容 `/rerank`。只登记或验证模型还不等于选用了该模型。
5. 嵌入默认 1024 维，需中文多语言模型，重排也需中文能力。`BAAI/bge-m3`、`BAAI/bge-reranker-v2-m3` 仅为可替换示例，实际以服务支持为准。
6. “长期记忆”手动保存明确事实，或对话后核对候选。持久化成功与索引成功分开显示；索引失败可重试。
7. 新建其他会话询问该事实，查看实际记忆来源；再纠正／删除并复验。来源失效会取消在途生成，并使相关回复和事件失效。

模型目录不会自动补 `/v1`。根地址为空或为标准 `/v1`（不区分此处大小写）时，优先访问同源 `/models`；只有根目录返回 404 或 HTML 网页，才尝试用户已经配置的版本路径，不创造新版本路径。自定义网关前缀保持原样；401／429 等错误不切换路径。路径大小写在上游可能有区别，聊天等其他用途仍使用原配置地址。

目录接口为认证后的 `GET /api/providers/{provider_id}/models`，只允许当前工作区可访问、已启用的连接。服务端读取加密凭据，复用地址检查、DNS 固定和禁止跳转的传输；浏览器不接触明文密钥。响应只包含连接 ID／版本与去重后的模型 ID，不转发供应商原始元数据，不自动登记或验证模型。请求设置超时和目录大小上限；不兼容或不完整的目录明确报错。API 契约及前端类型已同步。

按用途的能力验证包括：

| 用途 | 验证内容 |
|---|---|
| 日常对话 | 与实际聊天共用流式解析器，必须收到有效文字及完成标记；普通 JSON 回复、空流或中断不能标为通过 |
| 记忆抽取 | 固定中文偏好样本返回结构化 JSON，检查原文引用、事实主体、类别与证据字段 |
| 向量嵌入 | 响应向量维度与部署一致，数值有限、类型正确且不是全零向量 |
| 检索重排 | 返回文档范围内、不重复的整数 index 和有限数值 relevance_score |

所有实际发出的验证调用都在“调用记录”标为“能力验证”，保留成功／失败、耗时、用量及脱敏提示；费用未知时不估造价格。401、403、404、429、超时和连接失败提供修复方向，不返回上游原始正文、密钥或请求内容。验证失败后刷新模型状态，不能继续选用。旧版本曾验证的模型建议重新执行本轮能力验证。

这些是小样本协议检查，不代替提供商实测、中文记忆评测或 Hindsight 索引／召回联调。“配置就绪”仅指用途配置完备，不代表整个记忆闭环验收通过。

密钥由服务器主密钥加密，前端仅显示掩码。Hindsight 持有内部 token，Core 按用途解析模型并注入提供商密钥；`/internal/model/v1/*` 不经 Web 反代公开。不要把密钥发送到聊天。

仅配置对话模型时仍可文字聊天；记忆模型未配置、检索故障时明确提示，不生成模拟召回。助手回答不直接成为用户事实。自动保存仅允许有原文证据的简单低风险自述；敏感、冲突和其他内容进入候选核对。

## 运维、备份与恢复

```bash
sudo docker compose ps
sudo docker compose logs --tail 80 core worker
sudo docker compose restart core worker
sudo docker compose down
```

`down` 保留卷，普通重启不要加 `-v`。日志需脱敏再分享。索引与清理作业有限重试；中断的生成标记失败，不自动重放模型调用。

| 位置 | 内容 |
|---|---|
| `lingxi_postgres` 卷 | 业务数据、会话、权威记忆、配置、作业；独立 Hindsight 数据库及索引 |
| `lingxi_deletion-ledger` 卷 | 追加且 fsync 的删除记录，不可随旧数据库备份回退 |
| `.env` | 数据库密码、加密主密钥、内部 token，须单独安全备份 |

备份前停止 Core／worker／Hindsight 写入，分别导出两个数据库，另备份删除卷与 `.env`。恢复期间所有旧实例停写。恢复数据库、放回**最新**删除记录，迁移并重放后开放访问：

```bash
sudo docker compose up -d db
sudo docker compose run --rm migrate
sudo docker compose run --rm core python -m lingxi.cli replay-deletions
sudo docker compose up -d
```

Core／worker 启动也会重放；删除记录损坏会阻止启动。导出下载按当前状态重新生成；已下载副本无法远程撤回，备份物理清除依赖部署保留策略。现有备份页面支持定时请求，恢复仍仅在服务器终端确认执行，参见“备份恢复”。

更换嵌入模型：备份，停止 Core／worker／Hindsight，等待作业租约到期，再为通过验证、同维度的新模型建立独立索引代次：

```bash
sudo docker compose stop core worker hindsight
sudo docker compose run --rm --no-deps core python -m lingxi.cli reindex
sudo docker compose up -d core hindsight worker
```

按提示输入模型 ID。新索引完成前不复用旧向量。**改变维度尚未提供自动迁移**，不能只修改环境变量后复用旧库；需专门的 Hindsight 表和索引迁移。旧代索引清理、备份过期由部署端管理。

## 系统代理

在“系统设置 → 系统配置”填写并保存代理，启用后 Core 和 worker 的新 HTTP(S) 对外请求统一使用该配置，包括供应商模型目录、聊天、能力验证和记忆模型网关。HTTP／HTTPS 分别优先使用 `http_proxy`／`https_proxy`，缺省使用 `all_proxy`。例如：

```text
http_proxy  = http://172.20.192.1:7890
https_proxy = http://172.20.192.1:7890
all_proxy   = socks5://172.20.192.1:7890
```

支持 HTTP、HTTPS、SOCKS5／SOCKS5H 代理；当前不支持代理 URL 内嵌账号密码。无需重启，新请求读取已保存版本，在途请求沿用原配置。代理故障明确报错，不自动回退直连；目标地址访问限制和 TLS 证书校验继续生效。

“测试连接”使用当前表单访问公网 HTTPS 测试地址，显示路径、HTTP 状态和耗时，不会保存或启用配置。使用代理测试前勾选启用。`no_proxy` 直连规则可填主机名、`.domain` 后缀、IP、CIDR 或 `*`，逗号分隔；`*` 会令全部请求直连。固定内部服务名与回环地址保持直连，数据库及容器内 Hindsight 通信不经过外部代理。外置 Hindsight 的网络流量由其部署者管理，其通过 Core 网关调用的模型受本配置控制。

地址须从容器视角可达，`localhost` 指当前容器；示例 WSL 宿主地址不保证每台机器一致。配置保存在数据库并加密，受认证、CSRF、版本冲突和审计保护。该设置只作用于应用 HTTP(S)，不修改 Windows、浏览器、Docker 拉取／构建、数据库协议或尚未实现模块的网络行为。停用并保存后，新请求恢复直连。

## 主动交流的当前边界

“主动交流”三个页面已经接入真实后端：待续话题、联系偏好、联系记录。Core 会从本人明确保存的项目／操作经验记忆，以及成功生成的项目计划中建立一次接续，默认一天后检查、七天过期；已有记录不做历史全量补采。也可从授权来源手动新建，或编辑等待中的安排。同一来源版本只建一个话题，不重复追问。默认用有来源的表达模板接续；v1.45 可单独开启受控模型构思，不开放无来源的自由编写，不据此宣称已完成丰富的闲聊、关怀或发现能力。

worker 每约 15 秒检查到时话题，发送前重新核对来源及版本、允许类别、用户暂停、会话忙碌、最近发言间隔、安静时段、每日额度和最短间隔。默认每天最多 2 次、间隔 3 小时、Asia/Shanghai 的 22:00–08:00 安静；可修改，安静起止相同表示不设置安静时段。数据库按所有者串行决定投递，多个 worker／浏览器共享额度与记录。

Web 目标写入站内联系记录，可写回明确选择且仍存在的会话；浏览器打开时轮询显示提示。QQ 目标按 v1.32 的显式授权和协议回执处理，不再显示第二次 Web 主动提示。没有目标时不自动新建对话，用户点击“接续对话”后才创建并写入同一历史，再次点击复用原会话。目标删除后不自动改投。这里不代表浏览器推送、QQ 送达、已读或语音许可。

“有些帮助”“不再提起”“暂缓一天”“只收结果”是明确反馈。聊天中完整发送“先别聊”“暂停主动交流”“以后别主动联系”“直接告诉我结果”“这个以后别问”也能直接生效；这些控制不需要模型、不抽取为个人事实。引用这些词或其他表达不会被猜作控制指令，其他自然说法仍需通过设置页处理。“这个以后别问”只匹配当前会话最近的主动话题；没有对应记录会如实说明，不猜测。

纠正、删除、到期与恢复删除记录影响待续话题、联系内容及对话依据；纠正后旧版本失效，不自动改写原消息为新事实。屏蔽来源跨版本保留，恢复需明确保存，不补发已关闭的旧话题。原提醒与任务结果独立保存，不占普通主动交流额度；未回应不自动催问、不推断心情。

## 故障排查

QQ 的独立 Compose、固定镜像、人工登录、绑定与故障步骤见 [QQ 接入说明](./deploy/QQ接入说明.md)。协议端由账号持有人操作；本机服务更新不会自动登录或向真实 QQ 发送测试消息。

- 不能登录：先初始化所有者；检查 Cookie Secure、HTTPS、实际主机名与 origin。
- 页面可用但不回复：确认对话模型验证且被选中、worker 运行；查看队列和脱敏错误。
- 记忆持续等待／失败：检查三个记忆用途、嵌入维度、Hindsight 与结构化输出，修复后重试索引。
- 镜像标签不一致：当前使用 `1.1.0-slim`，检查 `.env` 的 `HINDSIGHT_IMAGE`，无需重新拉完整镜像。
- 服务地址不通：容器内 localhost 指向容器自己；使用 Docker 可达地址，内网需明确授权。
- 恢复旧内容：停止检索和写入，放回最新独立删除记录，成功重放再开放，不要删除记录绕过错误。

## 附件与多模态聊天

在聊天输入区“上传附件”或“选择文件”，等待“可用附件”后连同文字问题发送。在“数据日志 → 文件管理”可搜索、分页、查看原文位置、下载原件和删除。支持 TXT、Markdown、CSV、含可提取文字的 PDF、DOCX、XLSX 和静态 PNG／JPEG／WebP。上传采用独立幂等编号、服务器权限和持久化作业；失败可重试，同一上传请求不重复生成附件。

单个文件最多 20 MiB，每条消息最多 10 个、合计 50 MiB。图片最多 1600 万像素，解析后去除元数据并转为 JPEG；不静默缩小尺寸。模型输入的单条图片原始数据预算另为 12 MiB，整段历史为 24 MiB，超限明确要求减少图片。图片必须在“模型目录”对实际使用的日常对话模型点击“验证视觉”，六色块顺序探针通过后才可使用。连接版本变化令探针失效；探针只证明该次协议及识别检查，不代表视觉质量、所有图片格式或所有模型限制已经验证。

文档正文最多 16 万字、5000 段，PDF 最多 300 页；解析使用独立进程，Linux 限制内存 384 MiB、CPU 20 秒，父进程最多等 35 秒。加密、损坏、扫描 PDF、含公式的 XLSX 或过大解析结果明确失败。首批不执行公式、不信任公式缓存、不执行宏、不下载文档外部链接；DOCX 只提取正文段落，XLSX 提供原始单元格值，不保留完整版式或解释嵌入图片，日期序列不等同于格式化日期。

对话使用正文及附件 ID／行、段、页、工作表和单元格位置。超出模型上下文预算会要求拆分；近期历史截取继续显示提示。原件、解析结果与长期记忆分开管理，附件正文与模型回答不自动成为用户事实，子助手附件分析见 v1.40；QQ 图片／文档接收及协作见 v1.39／v1.43。

删除先写独立删除记录并停止使用，作废正在生成、已完成及后续引用结果，再由 worker 清理原件、规范化图片与解析临时文件。失败状态可见，可明确“重试清理”。删除会话会删除未被其他有效会话共用的附件，共用附件仍保留。删除整个附件仍影响所有引用会话。已经在客户端显示、下载或已发送给模型的内容无法收回。恢复旧备份前必须保留并重放独立删除记录，不能只恢复数据库后立即开放服务。

文件使用 Core 和 worker 共用的 `deletion-ledger` 持久卷下 `media/` 子目录；原件不映射为公共静态目录，所有内容请求都需要认证。部署迁移必须同时备份附件和独立删除记录，单独 `pg_dump` 不包含文件。单文件写入和数据库不能组成跨存储事务：上传中断可能留下无业务记录的文件，不可被接口读取；v1.68 已提供有界巡检及确认清理，完整容量治理仍待扩展。详见[附件使用说明](./deploy/附件使用说明.md)及[附件存储巡检说明](./deploy/附件存储巡检说明.md)。

## 消息分支（v1.23）

用户消息下的“编辑消息”、助手回复下的“重新生成”均需点击“创建分支”后才提交，可能产生模型费用。原对话不被改写，分支沿用同一工作区、用户与人格选择，并有“返回原话／查看分支”链接。操作要求当前会话无正在生成的回复；QQ 会话与有效实时语音会话暂不支持。

- 编辑继承被编辑消息之前的已完成原文，新增修改后的用户消息，保留该消息的附件；默认关闭任务协助与助手协作，不重新执行联系偏好命令。编辑不纠正已保存的长期记忆，请在记忆列表单独处理。
- 重新生成继承原提问及之前的已完成历史，引用原始用户消息 ID，不复制或再次抽取该提问，不重放任务。已有任务仅按最新服务端记录进入回答依据，不能将生成文字视为任务执行回执。
- 分支通过不可变消息 ID 列表冻结前缀，最多 1000 条，超过时明确拒绝。原会话后续新消息不会自动进入分支；允许继续分支，继承列表展开存储，无递归读取链。
- 删除原会话会使引用其原文的分支回答失效；删除分支只删除该分支独有消息，原话与共享证据继续保留。记忆、附件和任务来源失效同步传播，导出只含当前可访问历史。
- 新增 `POST /api/conversations/{id}/branches`：`request_id`、`message_id`、`mode=edit|regenerate`，编辑时另传 `content`；返回新 `conversation_id` 与 `run_id`。同一请求重投返回同一结果，改动参数须使用新 ID。`GET` 同路径查询原会话和直接子分支。
- 迁移 `0019` 增加 `conversation_branches`，存在分支时禁止降级以免丢失历史范围；回退须恢复升级前备份及配套镜像。构建直接使用正常源码，无需 `.preview` 快照或覆盖文件。Web 的 API 代理按 Docker DNS 动态解析 Core，地址变化后不必重启 Web；短暂连接错误可在服务恢复后重试，写请求仍遵守幂等规则。

操作与限制见 [消息分支说明](./deploy/消息分支使用说明.md)。本批使用合成协议验证，不代表实际模型效果或中文记忆质量达标。

## 上下文压缩与历史补读（v1.24）

长对话保留近期原文、任务回执和证据，同时按当前提问筛选早期候选，再由当前已验证的对话模型选择精确连续引文与原文区间。服务端验证来源 ID、角色、范围、内容和预算；最多 24 条候选、12 段摘录、3 段自动补读。模型不能通过此步骤执行工具、调整授权或写记忆。原文保留，不采用没有依据的自由改写摘要。

- 会话工具栏“历史原文”支持关键词检索、分页与分段读取；助手消息“历史依据”以及最近执行“查看依据”展示当轮快照、覆盖计数、角色和字符范围。
- 长历史最多额外调用一次当前模型，增加延迟与用量；调用记录用途为“历史压缩”，不自动切换供应商。输入输出使用保守 UTF-8 字节启发式预算，不宣称精确 token 计量或完整历史阅读。
- 摘录与长期记忆分开存储；记忆抽取仍只分析原始用户消息。压缩失败、无预算或返回非法引文时保留近期文字聊天，快照显示暂不可用；找不到证据时不得猜测。
- 摘录快照记录版本、来源哈希与当前分支范围。纠正、删除、撤权与取消沿已有屏障生效，迟到结果不能发布；失败或取消清空摘录内容。恢复旧备份仍须在开放服务前重放独立删除记录。
- QQ 历史继续过滤协议端未接受的助手回复；语音只将已确认完整播完的短句交给压缩器。Web 手动补读可查看其有权访问的完整文字，不扩大语音上下文。
- 迁移 `0020` 新增 `conversation_contexts`。存在快照时禁止直接降级至 `0019`；回退必须恢复升级前备份与配套镜像。

接口、限制与升级见 [上下文使用说明](./deploy/上下文使用说明.md)。合成协议验证通过不代表真实供应商摘要相关性、Hindsight 质量或 150 题中文记忆评测达标。
