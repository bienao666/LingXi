# 插件管理、Skills、远程工具、事件与角色

当前提供第一方目录、安装生命周期与可选独立公开／私有商店。商店含提交、审核、签名制品、固定信任根与撤销同步，部署见[商店部署说明](./商店部署说明.md)。固定 API 已提供独立连接、请求预览与未知结果核对；远程 MCP 已提供 Streamable HTTP 工具发现、授权与执行；事件适配器提供签名 Webhook、独立授权与统一话题入口；角色包提供受控子助手模板与单独配置。OAuth 授权码＋PKCE 已提供固定服务连接，任务范围内逐次确认的 API／MCP 编排见[子助手协作说明](./子助手协作说明.md)。详见[OAuth 连接说明](./OAuth连接说明.md)。

## 使用入口

- **插件商店**：查看随应用发布及当前工作区验证通过的商店版本、许可、兼容范围、能力、权限、数据范围与费用；预览不产生安装，必须勾选并确认。
- **已装插件**：查看版本、授权和依赖锁，启停或卸载。操作前展示依赖者、在途调用、基础任务、待触发提醒及目录协作节点。
- **技能工具**：只展示当前安装版本的能力及前置条件。基础能力跳转任务或提醒；写作伙伴可提交明确资料，固定 API 须先配置连接，再填写 JSON 并确认请求预览。
- **更新回滚**：更新必须预览；回滚仅选择安装历史中使用过的版本，恢复兼容配置和精确依赖锁，不能撤销外部行为或费用。
- **运行记录**：最近 50 次 Skill／API／MCP 的状态、固定版本、结果及回执。API 仅证明 HTTP／JSON 协议成功，未知结果必须先核对。收到非空文字不等于事实已查证或建议已执行，未定价费用显示未知。
- **账号授权**：API／MCP 能力按安装独立授权；无密钥／Bearer／API Key，服务器加密，页面不回填，支持版本检查和撤销。固定服务 OAuth 授权码＋PKCE 见[OAuth 连接说明](./OAuth连接说明.md)，支持加密令牌、刷新与撤销。
- **助手配置 → 插件角色**：选择已安装的角色模板，确认人格、模型、候选工具和记忆类别；配置后参与统一助手协作，执行与结果在任务中心查看。

## 子助手角色包（v1.29）

角色属于插件版本中的声明式配置，不是第三方程序，不另建一套个人档案。经公开或工作区私有商店提交、审核、签名及安装后，仍须在“助手管理 → 助手配置 → 插件角色”配置启用。安装不会自动开始任务、授权记忆或复制成本地可编辑角色；插件指令作为外部配置处理。

1. 核对模板的专长、完成条件、工具和记忆类别，再选择本工作区已启用的人格。模型可选已验证的对话模型，或跟随人格／当前固定对话策略，真实可用性由服务端检查。
2. 候选工具默认仅文字分析。模板声明 `server.files` 时还须具备 `resources.list`、基础插件资源授权、Linux 安全目录以及具体协作任务的“允许读取”设置。不支持脚本、联网研究、第三方 API／MCP、文件写入或再委派。
3. 记忆默认不共享。用户勾选的类别不能超出模板范围；具体任务还需开启共享，实际只提供任务相关 ContextBundle，保留来源与版本。人格、模板、模型输出不能扩大记忆范围。
4. 勾选确认后才启用。主助手在新协作任务中筛选角色、模型和当前权限；是否直接处理或委派仍由统一调度决定，不保证每次使用该角色。入口包括任务中心的协作任务及独立 Web 文字对话的助手协作模式。
5. 主助手统一汇总；子助手不自行联系用户、写长期记忆或执行声明以外的操作。任务详情记录插件、模板、配置、人格、模型及来源版本。

```json
{
  "plugin_id": "sample.roles",
  "publisher": "sample",
  "version": "1.0.0",
  "name": "项目角色",
  "description": "根据明确提供的资料审阅项目风险。",
  "license": "MIT",
  "costs": "使用用户配置的模型可能计费；未知价格不作估算。",
  "data_scope": "仅任务输入与用户允许的相关项目记忆。",
  "capabilities": [{
    "id": "sample.reviewer",
    "name": "风险审阅",
    "kind": "agent",
    "permissions": ["model.chat"],
    "agent": {
      "expertise": "审阅项目交付风险",
      "instructions": "区分事实、建议和待核对项。",
      "completion": "交付附来源及限制的风险清单",
      "tools": ["reason"],
      "context_categories": ["projects", "procedures"]
    }
  }]
}
```

这是清单示例，不会随应用自动安装。`tools` 必须包含 reason，可额外声明 server.files；权限依次为 model.chat，以及需要时的 resources.list。专长／完成条件最多各 1000 字，instructions 最多 4000 字；类别限既有七类且不能重复。不接受远程模型地址、凭据、任意工具标识和可执行代码。

### 版本、撤销与恢复

角色配置绑定安装版本及配置版本；冲突保留草稿并返回 409，不自动覆盖。插件更新后，新派发需重新核对角色并确认。已提交任务保留原模板、模型与依赖锁，只有当前权限、人格及记忆范围仍允许时才可继续，不能因更新扩大旧任务范围。用户缩小工具／类别或更换绑定人格时，旧任务在后续检查处停止；模型或人格的一般风格更新不改写已保存快照。

撤销、插件停用／卸载、依赖停用及商店信任撤销会阻止新派发。执行前和结果提交前检查当前授权；已经发往模型的请求及其费用无法撤回，撤销后不能发布迟到结果。再次启用不使撤销前的旧任务恢复。已完成的分析、用户文件和确认记忆保留，不将未执行的建议标记为完成。

升级预览仍走统一安装流程；角色自身无需 API 密钥。当前每个工作区最多保留 100 个绑定，调度至多读取 30 个已启用插件角色；任务仍限制 8 节点、3 并发和一层委派。恢复旧备份时携带最新绑定及撤销代际，全部撤销，旧任务继续隔离，需重新确认；不替代全损灾备。

迁移 `0024` 增加 `plugin_agent_bindings`。存在角色版本或授权记录时禁止直接降级至 `0023`，应使用升级前备份及配套镜像。接口为 GET／POST `/api/plugin-agent-bindings` 与 POST `/{id}/revoke`，全部复用身份、工作区、CSRF 及版本检查。发现通过 `/api/plugin-capabilities`，自动调度通过 `/api/agents` 复用现有任务引擎。正式工作区不自动接入样例商店或角色。

## 固定 API 使用（v1.26）

1. 发布者提交下面的声明式清单，审核员审核，Core 配置可信商店后同步；安装预览会显示网络权限、依赖、固定入口与费用。无需安装第三方执行程序。
2. 在“账号授权”配置对应能力，填写专用密钥；内网地址必须明确勾选允许。保存仍需授权确认，修改沿用当前版本；冲突保留草稿，不自动覆盖。撤销会清除密钥，不能靠留空恢复。
3. 声明 `health_url` 时可“测试连接”，只发送同源 GET，2xx 仅表示此健康接口可达；未声明时不伪造可用检查。
4. 在“技能工具 → 请求预览”填写声明过的 JSON 字段。预览绑定当前登录、连接及插件版本，有效 5 分钟；再次核对数据、地址、方法、内网与费用后勾选“确认发送”。关闭预览会取消尚未发送的调用。
5. 在“运行记录”查看结果与传输回执。接收有界 JSON 不证明业务语义成功；未知结果到第三方核对后登记依据，系统只记录用户报告，不自动再次执行。

```json
{
  "plugin_id": "sample.records",
  "publisher": "sample",
  "version": "1.0.0",
  "name": "资料登记",
  "description": "仅向固定服务提交本次标题。",
  "license": "MIT",
  "costs": "第三方可能收费，以供应商为准。",
  "data_scope": "仅本次明确输入，不读取长期记忆。",
  "external_services": ["https://api.example.com"],
  "capabilities": [{
    "id": "records.create",
    "name": "登记资料",
    "kind": "api",
    "permissions": ["network.write"],
    "api": {
      "url": "https://api.example.com/records",
      "method": "POST",
      "effect": "write",
      "auth": "bearer",
      "health_url": "https://api.example.com/health",
      "idempotency_header": "Idempotency-Key",
      "parameters": [{"name": "title", "type": "string", "description": "资料标题"}]
    }
  }]
}
```

以上地址仅作清单示例，并非可用服务。可用认证为 none／bearer／api_key；api_key 用 `key_header`（默认 X-API-Key）。只读为 `GET`＋`effect: read`＋`network.read`；POST／PUT／PATCH／DELETE 必须声明 write，GET 也可以声明 write。参数类型为 string／integer／number／boolean／object／array，默认必填。不得用 URL 查询参数或模板藏入凭据，不接受未知字段、重复 JSON key 或可执行说明。

输入最多 12000 字符且 UTF-8 24 KiB、嵌套 8 层、集合 128 项；响应最多 256 KiB，展示 JSON 最多 30000 字符和 12 层。超过预算保留失败／未知回执，不截断后声称完整。响应中的敏感字段及本次密钥会脱敏，原响应正文不入日志；凭据不送入模型或记忆。接口固定、禁止重定向；网络沿用系统代理与 DNS 固定，内网仍需单独授权。每用户 API／健康请求最多每分钟 30 次，预览／排队／执行调用合计最多 16 项。

### 发送状态与恢复

预览不创建执行作业；确认与作业同事务提交。worker 先保存 `in_flight` 再网络发送，即使崩溃在实际发送前，也保守标为 unknown，不能以租约重领自动重发。同一能力的写请求在已有 queued／running／unknown 时阻止再次确认；未知结果未核对不能创建新的写预览。

取消、撤权、停用、卸载不能撤销已发生的外部写入或费用。未发送可取消／失效，已经进入发送阶段的请求进入“结果待核”，迟到响应只保留传输状态和摘要，不能发布已失效正文。HTTP 2xx＋JSON 为 succeeded，其余包括超时、非 2xx、重定向、非法／超预算 JSON 均保守待核。人工 applied／not_applied 只登记用户结论，不能冒充独立核验。

入口不变的旧调用固定原插件版本；入口变化不能继承连接。升级不自动扩大授权。卸载清除专用连接凭据，保留回执与用户长期资产。工作区回退保留回退前最新 API 发送标记和回执，撤销全部 API 连接、隔离旧预览／队列；最新标记仍在时不得重新执行。此机制依赖可读取当前工作区的恢复检查点，不等同于全损灾难恢复。

迁移 `0021` 新增 `plugin_connections`；须先迁移再更新 Core／worker。有 API 清单、连接或调用记录时禁止直接 downgrade，避免旧 Core 遗失授权和发送屏障；应使用升级前备份和配套镜像恢复。正式应用不自动信任测试商店、安装样例或创建第三方连接。

新增接口：GET／POST `/api/plugin-connections`，PUT `/{id}`，POST `/{id}/test` 与 `/revoke`；POST `/api/plugin-invocations/preview`、`/{id}/confirm`、`/{id}/resolve`；取消复用 `/{id}/cancel`。确认绑定登录与摘要，修改／撤销／核对绑定版本，全部复用认证及 CSRF。API 可通过 v1.31 聊天／子助手协作生成提案，仍逐次预览确认；远程 MCP、签名事件与 OAuth 分别见 v1.27、v1.28 及 v1.30 增量。

`lingxi.builtin` 初次登记已有项目规划、服务器只读目录清单和一次性提醒的原权限，不改变原边界。用户停用或卸载后，重启不会重新启用。停用基础能力会阻止未触发提醒入站，这些提醒可能进入失败状态；重新启用后需核对并重新安排。

`lingxi.writing` 默认不安装。`1.0.0` 提供提纲整理，`1.1.0` 增加文字审阅。两版仅将本次明确输入提交到已验证的对话模型，可能计费，不主动读记忆或完整历史，不执行工具、脚本或发布内容，不自动写记忆。

## 生命周期与依赖

预览绑定登录会话、用户、工作区、摘要、安装和授权快照，有效 10 分钟；新预览使旧待确认预览失效。目录、安装或权限变化须重新预览；拒绝、过期、摘要不符或未完整确认权限时不安装。确认在同一事务登记安装、依赖锁与快照；重复确认返回相同操作结果。

稳定语义版本使用 `major.minor.patch`，依赖采用 `>=1.0.0,<2.0.0` 等明确比较式。解析采用有预算的回溯，拒绝冲突、循环及超过 8 层／32 节点的组合；兼容的已安装依赖优先保留。变更不能破坏其他已装依赖者；卸载依赖前须先单独确认卸载依赖者。

第一方目录使用应用随附的不可变规范清单与 SHA-256 校验；商店版本另需固定根、根签名公钥登记、未过期且绑定访问范围的签名快照，以及制品签名／摘要校验。下架停止发现及新装，已有授权可继续；已知撤销阻止新调用和提交并影响依赖者。商店可离线，但新装／更新需要重新同步；连接、令牌或根变化使旧来源访问失效，不扩大工作区可见范围。

安装授权有效不等于 worker 在线或模型就绪。能力目录进一步检查前置条件，执行仍等待 worker 真实确认。

## 执行与数据

调用与数据库作业同事务登记，幂等请求 ID 防重复提交；每位所有者最多 16 个等待／执行中调用。固定插件摘要、版本、依赖锁、模型及连接版本；模型记录关联 invocation ID。重启沿用作业租约及 fencing 恢复，崩溃恢复可能再次产生模型费用，不承诺费用严格一次。

明确失败不自动重试文字 Skill；核对原因后重新提交。取消、停用及卸载阻止尚未提交的结果，不能撤回已经外发的输入与费用。升级影响新调用，旧调用保留原版本；版本固定不固定授权，执行与提交前重新校验启停、撤销、权限、依赖及模型。

内置任务及目录协作也通过同一权限入口。模型或插件文本不能自行安装、授权或读取完整记忆／凭据。卸载清除当前配置及授权，保留用户文件、确认记忆、任务结果、必要版本和审计；不宣称彻底抹去全部历史。

## 远程 MCP 使用（v1.27）

1. 通过独立商店提交、审核、签名分发以下清单。安装仍须在 Core 预览权限、数据范围、固定入口和费用后确认。
2. “账号授权”配置该能力的专用连接。支持无密钥、Bearer 或 API Key；私网端点须明确允许。凭据使用加密库，不返回明文。
3. 点击“工具授权 → 发现工具”：实际执行 `initialize → notifications/initialized → tools/list`，协商版本、使用会话头，并读取完整分页目录。此时没有任何 `tools/call`，没有自动授权。
4. 检查工具名称、说明与输入输出 Schema，选择允许使用的工具，勾选并“确认工具”。工具说明和注解来自外部服务，不是主助手指令。空选后确认可撤销全部工具授权。
5. “技能工具 → 请求预览”选择已授权工具，填写 JSON 输入，查看五分钟有效的调用预览，核对后勾选并确认发送。仅用户明确输入传给远端，不自动共享记忆、附件、完整历史或模型密钥。
6. “运行记录”查看脱敏 JSON、协议版本、工具及制品摘要、状态与执行回执。资源链接、图片／音频数据和嵌入资源作为普通 JSON 展示，不自动下载、播音或执行其中内容。

```json
{
  "plugin_id": "sample.remote-tools",
  "publisher": "sample",
  "version": "1.0.0",
  "name": "远程资料工具",
  "description": "使用固定远程服务处理用户明确提交的资料。",
  "license": "MIT",
  "costs": "以远程服务条款为准，未配置价格时费用未知。",
  "data_scope": "仅发送本次确认的工具输入，不直接访问完整记忆库。",
  "external_services": ["https://mcp.example.com"],
  "capabilities": [{
    "id": "remote.tools",
    "name": "远程资料",
    "kind": "mcp",
    "permissions": ["network.write"],
    "mcp": {
      "url": "https://mcp.example.com/mcp",
      "transport": "streamable-http",
      "auth": "bearer"
    }
  }]
}
```

### 协议与预算

- 固定 HTTP(S) 端点，不接受地址中的账号、查询凭据、片段或模板；无重定向、自动跨地址发现或本地进程。所有请求复用系统代理、DNS／私网授权和 TLS 检查。
- 支持 MCP `2025-11-25`、`2025-06-18`、`2025-03-26`，每次发现或执行建立新会话。POST 同时声明 JSON／SSE Accept，协商后带协议及可选会话头；会话标识不持久化、不进入页面或日志。
- 支持 JSON 与 SSE 响应、UTF-8 分片、LF／CRLF／CR、进度类通知及分页；不建立持续 GET 订阅，不自动重放断开的工具调用或跟随服务给出的地址。会话失效后须重新提交新的用户确认，不重放原调用。
- 最多 8 页／128 个工具，单个定义 16000 字符，单次响应 256 KiB、128 个有效事件、整体会话预算 45 秒，单请求等待不超过 15 秒；展示结果最多 30000 字符。超预算明确失败或待核对，不静默截断后声称完整。
- JSON Schema 使用 `2020-12`；校验必填、类型、枚举、组合及有界无环本地引用。拒绝远程引用、循环引用、动态引用和正则约束；Schema 遍历最多 2048 个节点与 20 层，输入另受 24 KiB／8 层／集合 128 项约束。`format` 按标准作为注释，不声称验证其格式。
- 未协商模型采样、roots、elicitation、异步 task 等客户端能力；收到请求时拒绝，不唤起模型或扩大权限。需要异步 task 的工具不接入。固定服务 OAuth 由 v1.30 连接适配器提供；旧 HTTP+SSE、stdio 和持久订阅尚未实现；v1.31 提供任务范围内逐次确认的协作调用。

### 目录、授权与执行一致性

发现会先撤销旧目录可用性和工具授权，再进行网络读取；失败不恢复旧授权。工具选项绑定连接版本、目录版本和完整摘要。重新授权会使尚未发送的旧预览失效；连接修改、撤销、停用、卸载和版本撤销继续走统一生命周期。

worker 在新会话中重读目录，与已批准快照比对；变化则在 `tools/call` 前使目录及旧预览失效，要求重新发现与授权。收到 `notifications/tools/list_changed` 后也使快照失效。远端可能在检查后改变自身行为，摘要只能核对声明，不能证明远程实现可信。

所有工具保守使用 `network.write`。`readOnlyHint`／`idempotentHint` 不构成授权或业务保证。生成预览不会发送工具调用；确认绑定当前登录、输入、制品、连接、目录与工具版本，且有期限。无范围外记忆读取或后台通知能力。

`tools/call` 之前持久化发送屏障。断线、超时、HTTP／协议错误、`isError`、取消、撤权或崩溃后标为 `unknown`，阻止同能力的新写操作；这些结果均不证明没有部分副作用。运行记录支持人工登记第三方核对依据，不自动重试，也不将人工登记当成系统独立验证。成功只表示收到了有效 MCP 成功结果。

## 签名事件订阅（v1.28）

### 安装与授权

1. 发布者在清单声明 `kind: event`、`permissions: [events.receive]` 和事件约定，提交审核后分发签名版本。
2. 用户确认安装预览；安装不自动创建订阅、不授予直接联系权限。
3. 在“账号授权 → 事件订阅”选择插件，填写与来源共享的专用随机密钥，勾选类型、设置接收额度并明确确认。
4. 页面显示回调地址。用户自行配置来源系统或受控转换器，按照下述约定发送；不要向来源提供灵犀登录密码、模型密钥或其他插件凭据。
5. “接收记录”展示接收结果；“待续话题”和“联系记录”展示核心后续处理。接收成功不表示已通知、已送达或已读。

密钥须为 32–256 位不含空白的 ASCII 字符，仅加密保存在服务器，不回填页面。编辑有效订阅时留空表示保留密钥；撤销后必须重新填写。每个安装能力只有一个订阅，配置修改固定版本并使旧事件／话题失效。密钥不放入 URL、正文或日志；回显当前签名密钥的正文拒绝保存。

清单能力示例（嵌入完整插件清单后按正常审核流程发布）：

```json
{
  "id": "project.updates",
  "name": "项目动态",
  "kind": "event",
  "permissions": ["events.receive"],
  "event": {
    "transport": "signed-webhook",
    "event_types": ["project.updated", "project.completed"],
    "ttl_seconds": 86400
  }
}
```

事件类型为最多 120 字符的命名空间标识，清单最多 16 个且不重复；用户只能选择其子集。清单 TTL 为 60–604800 秒，默认一天。

### 签名与正文

向页面提供的 `POST /api/plugin-events/hooks/{subscription_id}` 发送未压缩 UTF-8 JSON，最多 12 KiB。请求不能包含查询参数或浏览器 Origin；Cookie 不作为事件凭据，反向代理不转发 Cookie。

| 请求头 | 值 |
| --- | --- |
| `Content-Type` | `application/json` |
| `X-Lingxi-Timestamp` | 十位 Unix 秒，服务端误差不超过 300 秒 |
| `X-Lingxi-Event-Id` | 8–100 位字母、数字、下划线、点、冒号或连字符；来源重试保持不变 |
| `X-Lingxi-Signature` | `sha256=` 加 HMAC-SHA256 的小写十六进制摘要 |

签名字节为 `subscription_id + "\n" + timestamp + "\n" + event_id + "\n"` 的 ASCII 字节，再紧接**原始请求正文**。JSON 空格、转义和编码变化都会改变签名；重试同一事件必须保持原正文，但可使用新的签名时间。签名绑定订阅地址，不能转发到另一个订阅。重复签名头拒绝处理。

正文仅有以下五个字段，不接收账号、工作区、接收者、会话、附件地址或执行指令字段：

```json
{
  "type": "project.updated",
  "title": "项目资料更新",
  "summary": "来源系统报告资料新增三页；内容尚未独立核验。",
  "occurred_at": 1793318400,
  "expires_at": 1793322000
}
```

时间为 Unix 秒数；示例时间仅说明格式，实际发送使用当前有效时间。发生时间不能超过未来 30 秒，不能早于清单 TTL；到期时间须晚于接收时刻且不超过发生时间加 TTL。标题最多 200 字符，摘要最多 2000 字符，均为非空文本。重复 JSON 字段、额外字段、非有限数、无效编码和超限正文拒绝。

同一订阅和事件 ID 重投递，只返回原记录的去重回执，不新建话题；同一 ID 的原始正文变化返回 409，不覆盖。删除、到期和订阅修改仍保留去重标记，不能通过重投递复活旧内容。

### 额度、联系与失效

- 每订阅默认每小时 10 条、滚动 24 小时 50 条，可分别调到最多 60／500 条。所有订阅合计滚动 24 小时最多 500 条；工作区保留最多 10000 个去重记录，达到上限停止新接收并提示管理员归档，不静默删除屏障。
- 接收额度与主动联系额度独立。事件形成带来源和有效期的“兴趣分享”话题，核心再次检查来源授权、联系偏好、安静时段、会话忙碌、日额度和间隔。事件没有优先级绕行入口。
- 当前统一出口为站内文字与已授权会话记录，不直接发送 QQ、播放语音或发桌面通知；关闭浏览器不停止接收和 worker 判断。
- “这个以后别问”或关闭并屏蔽话题，会屏蔽整个订阅来源，后续不同事件 ID 也不能继续联系。修改订阅不清除用户的来源拒绝；恢复须在联系偏好中明确移除屏蔽。
- 停用、卸载、更新、回滚、依赖变更／停用及商店信任撤销，使关联订阅撤销、密钥清除、候选话题和衍生内容失效。重新启用插件不自动恢复订阅。
- 删除事件清除标题和摘要，并取消对应序号的话题、主动消息和由其产生的对话来源；保留去重元数据。到期立即停止使用，worker 后续清理正文和派生内容。
- 所有描述和摘要均为外部报告，按文本展示，不执行 HTML、不跟随链接、不创建工具任务、不直接写长期记忆。用户接续交流时，仍使用统一核心及来源有效性检查。

### 接口与恢复

| 接口 | 用途 |
| --- | --- |
| `GET /api/plugin-event-subscriptions` | 查询独立订阅及可用状态，隐藏密钥 |
| `POST /api/plugin-event-subscriptions` | 按当前版本与明确确认新建／修改 |
| `POST /api/plugin-event-subscriptions/{id}/revoke` | 版本检查后撤销并取消衍生来源 |
| `POST /api/plugin-events/hooks/{id}` | 独立签名入口，不使用用户会话认证 |
| `GET /api/plugin-events` | 查询最近接收记录，失效后不展示正文 |
| `POST /api/plugin-events/{id}/delete` | 版本检查后删除正文，保留去重标记 |

迁移 `0023` 新增 `plugin_event_subscriptions` 与 `plugin_events`；先迁移再运行新版 Core／worker。存在事件清单、订阅或去重记录时拒绝直接降级。恢复检查点携带最新订阅身份和事件元数据，不含签名密钥和正文；沿用兼容的 `api_*` 字段保留相关制品与安装。恢复后撤销签名密钥、清除事件正文、重放删除状态并禁止旧作业与事件重新触发，须重新核对授权。

当前实现为本项目约定的签名 Webhook 接收适配器。第三方专有签名、自动创建远端订阅、定时拉取和自动工具执行仍待开发；角色包见 v1.29，固定服务 OAuth 见[连接说明](./OAuth连接说明.md)；接入特定服务需验证其转换、重试及费用行为。
