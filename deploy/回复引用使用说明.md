# 回复引用（v1.64）

普通 Web 聊天可选择一条历史消息继续提问。沿用现有对话窗口、午夜蓝主题和四字按钮，不增加菜单或恢复顶部介绍区。本批没有数据库迁移，schema 保持 `0051`。

## 使用

1. 在已完成、非空的用户消息或助手消息下点击“回复引用”，焦点进入输入框。
2. 输入框上方显示纯文字预览，最多 1200 字符；可“取消引用”。输入新问题后发送。
3. 引用仅用于普通对话。选中时关闭任务协助、助手协作并禁止新开语音；已有有效语音会话中不能选择引用。
4. 可显式添加本次附件。被引用消息原有的附件不因引用而进入本轮上下文；其他历史仍按原有预算与权限处理。
5. 提交后在提问旁“查看引用”。生成摘要显示实际引用覆盖字符数；模型上下文较小时会进一步缩短，片段不等于读完原文。
6. 发送失败保留提问与选择，原样重试使用同一幂等 ID；更换引用使用新 ID。成功或切换会话后清除选择，刷新可查看已提交的引用。

## 来源与失效

服务端只允许当前身份、工作区和会话可见的已完成用户／助手文字，也允许分支冻结历史中的原消息。其他会话即使属于同一用户也不能直接引用。未完成、删除、遮蔽、失效、空白或非对话消息拒绝引用，不凭客户端角色或模型输出授权。

执行配置只保存来源 ID、角色和正文摘要哈希，不复制正文。展示、导出与生成重新解析原记录；来源变化或失效时显示“引用失效”，不恢复旧引文。提交时即建立来源依赖，检索前后及每次持久化流式片段前重新校验；失效后清除派生回复和旧流式事件。

助手历史标为“助手历史输出，不等于用户事实”。引文不能修改联系偏好、支持设置或执行工具。“先别聊”等文字在引用模式下作为本条问题处理，不暗中改变设置；要修改偏好先取消引用或使用设置页面。记忆抽取只接收独立的新用户原文，不把引文拼成用户自述。

编辑消息和重新生成仍创建独立分支，继承原引用及有效性校验，不覆写原始事实或重复执行外部动作。引用来源不在新分支的冻结范围、已改变或已失效时拒绝创建。

## 接口

| 接口 | 增量 |
| --- | --- |
| `POST /api/chat` | 可选 `reply_to_message_id`；参与幂等哈希；不能与任务、协作、QQ 或语音输入混用 |
| `GET /api/messages` | 用户消息新增可空 `reply_to` |
| `GET /api/message-pages` | 同一引用展示，保留原分页规则 |
| `GET /api/conversations/{id}/export` | JSON 含动态引用；Markdown 标注来源角色、截取和附件边界 |
| `POST /api/conversations/{id}/branches` | 编辑／重新生成继承原引用，不接受额外工具授权 |

`reply_to` 包含 `message_id`、`status`、`role`、`content`、`truncated`、`characters`。不可用时仅保留来源 ID 和状态，其余为无正文的默认值。`config.reply_to_coverage` 记录原文字符数、实际提供字符数和截取标记，不含原文。

沿用 Cookie、CSRF、工作区、会话所有权及所有者锁。具体字段以 [OpenAPI](../backend/openapi.json) 为准。
