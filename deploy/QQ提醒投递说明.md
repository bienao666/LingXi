# QQ 提醒投递说明

版本：v1.74。代码及隔离协议链路已验证，真实 NapCat／QQ 账号收发仍待验证。

## 设置与使用

1. 在「任务中心 → 待办提醒」创建一次性提醒。默认仍只存站内，不自动发送 QQ。
2. 点击该条提醒的「提醒投递」，选择已经确认、允许个人资料的 QQ 私聊绑定。不能选择群或任意 QQ 号码；没有目标时先完成「平台接入」中的实例和身份绑定。
3. 设置到期后的离线等待期限，范围为 1–24 小时，从提醒到期时间起算。
4. 点击「预览投递」，核对完整标题、正文、到期时间、接收账号和等待期限，勾选确认后保存。

预览最多有效五分钟，且不能越过提醒到期时间；固定当前登录、提醒版本和正文摘要、QQ 平台及绑定版本。内容或授权变化需重新预览。重复提交同一确认不会创建重复设置或重发消息。

这是用户指定的一次性提醒，独立于普通主动交流的开关、安静时段和每日联系额度。保存此条设置不授权发送其他记忆或聊天。关闭浏览器不停止服务器处理，不自动开启浏览器播音或通知。发送没有精确时刻保证，受 worker 调度、队列与 QQ 连接状态影响。

## 状态与回执

站内触发与 QQ 投递分别记录：站内到期成功后，即使 QQ 离线、失败或过期，仍显示真实站内回执。「标记确认」只确认站内提醒，不代表 QQ 已读。

| 状态 | 含义与处理 |
|---|---|
| 仅存站内 | 尚未配置 QQ，默认状态 |
| 等待到期 | 已逐条确认 QQ 设置，尚未到期 |
| 等待发送 | 站内已触发，等待原 QQ 私聊可用；不改变接收者 |
| 等待回执 | 发送意图已经持久化，等待协议结果 |
| 协议接受 | OneBot 返回成功和消息 ID；不表示送达或已读 |
| 结果未知 | 断线、回执超时或开始发送后停止，可能已经产生外部效果；不重发 |
| 协议失败 | 协议明确拒绝；不自动重发 |
| 投递停止 | 未发送时被用户停止，或来源／授权发生变化 |
| 等待过期 | 超过允许期限，不补发、不换人或改渠道 |

「刷新状态」读取实际结果。「停止投递」不取消站内提醒，已经开始的发送无法撤回。「核对投递 → 结束等待」仅记录人工核对，不伪造成功，也不重发；迟到的合法协议回执仍可保留。发送遵守平台节流及未决写操作屏障。

编辑提醒内容、时间或所属会话会使旧 QQ 设置失效。取消提醒、平台／身份撤权或第一方提醒能力停用同样停止未发投递；重新启用不会复活旧授权。已触发的提醒不能更改接收目标。

## 接口与持久化

| 接口 | 用途 |
|---|---|
| `GET /api/reminder-targets` | 当前所有者可用的 QQ 私聊绑定 |
| `GET /api/reminders/{identity}/delivery` | 单条实际状态、版本及协议回执 |
| `POST /api/reminders/{identity}/delivery/previews` | 固定来源及目标的预览 |
| `POST /api/reminders/{identity}/delivery/confirm` | 精确确认，需正确 acknowledgement |
| `POST /api/reminders/{identity}/delivery/action` | 按版本停止或核对，不重发 |

全部接口检查登录、所有者与工作区，写操作复用 CSRF。提醒与投递更新使用版本和数据库锁；worker 获取所有者锁后刷新提醒再检查版本，防止并发编辑时使用旧内容触发。到期站内回执与 QQ 排队在同一事务提交。发出前再次检查提醒来源、插件、QQ 平台和身份版本。

迁移 `0059` 增加 `reminder_deliveries`，每提醒唯一，保存最小授权元数据、版本、发送意图和回执，不复制正文。恢复检查点保留较新的去重及回执屏障，取消旧队列，开始发送但结果未知的记录不重放。有投递记录时拒绝直接降级，需使用升级前备份及配套镜像整体回退。
