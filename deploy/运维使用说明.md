# 灵犀运维使用说明

当前为单所有者、单工作区的运维基础功能。沿用管理员登录、会话、CSRF 和工作区检查；本说明不表示完整运维目标已经验收。

## 页面入口

| 页面 | 实际行为 |
|---|---|
| 系统设置 → 系统概览 | 查看 Core、数据库、索引和记忆配置；真实 worker 心跳、队列、最早到期待处理等待和运行卷容量 |
| 数据日志 → 执行追踪 | 按对话、基础任务、子助手及插件调用筛选；查看阶段、固定配置版本、实际关联模型调用 |
| 数据日志 → 系统日志 | 查询结构化作业失败、主动交流调度及商店同步事件；按级别筛选和游标翻页 |
| 数据日志 → 用量预算 | 最近 1／7／30 天、模型与用途分组、已知 token 下限、未知用量次数及 UTC 当日软告警 |
| 数据日志 → 操作审计 | 查看当前所有者的关键操作、目标编号和时间；支持游标翻页 |
| 数据日志 → 诊断导出 | 选择范围，生成服务端快照，核对并确认后下载 JSON |

worker 每 10 秒写入心跳，45 秒未续约视为不可用；空闲和队列为空不等于离线。系统概览每 15 秒刷新运行信息。容量检查仅覆盖运行卷所在文件系统，不证明独立数据库卷、备份或模型质量正常。心跳刚部署时可能尚未出现。

追踪只显示实际关联记录，不收集用户正文、提示词全文、工具原始输出或私有思维。历史没有关联时不补造；单份详情最多列出 200 条阶段和 200 条模型调用，并提示未完整展示。当前未实现跨全部渠道、记忆、媒体和投递的完整 trace 图。

## 运行事件与保留

运行日志是代码定义的事件，不是容器 stdout 浏览器。不会补采过去的输出，也不直接展示原始异常。日志或用量页面中的“运维配置”可预览并确认保留天数（7–365，默认 90）和 UTC 日 token 告警阈值（0 关闭）。修改采用版本检查；冲突后保留草稿，重新加载核对。

worker 每小时清理过期运行事件、已过期诊断内容、90 天诊断元数据及 7 天旧心跳。缩短保留期可能在下一轮永久清除超期运行事件。该设置不清理审计、模型账目、任务检查点、会话、记忆或独立删除记录。

## 用量边界

上游没有完整用量时显示未知，不作零处理；已知 token 是下限。费用暂未配置可核验价格，始终显示未知。日阈值按 UTC 统计，只显示告警，不拒绝请求；不等于硬预算或实际账单。单次统计最多完整读取 100000 条调用，超限拒绝并要求缩小窗口，不悄悄截断。

## 诊断导出

1. 选择最近 1／7／30 天与运行健康、模型用量、运行日志、操作审计中的范围。
2. 生成预览，核对完整 JSON 和摘要。编号采用摘要引用；不包含聊天、记忆、附件、录音、服务地址或账号凭据。
3. 勾选确认后生成下载入口。下载不发送给第三方，不自动上传。

快照有效 5 分钟，绑定生成时的登录会话。更换会话、内容摘要变化或过期都会拒绝下载，需重新预览。重复提交同一请求不会重建快照；每分钟最多生成 5 次。日志和审计各最多 200 条，超限在 JSON 明确标记；文件上限 1 MiB。临时预览内容过期后由 worker 清空，下载失败会在当前页面显示原因。
