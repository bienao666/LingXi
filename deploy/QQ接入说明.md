# QQ 接入与实测

当前代码支持 OneBot v11 数组消息格式的文字私聊／群聊、身份验证、固定模型生成、持久化队列和协议回执。它不是 QQ 官方机器人接口。v1.32 已增加显式授权的普通私聊主动联系；v1.33 增加默认关闭的图片／直链文档接收；v1.34 增加默认关闭的 QQ 语音识别输入；v1.35 增加独立默认关闭的短回复语音输出；v1.38 增加默认关闭的长回答 Markdown 文件输出；v1.39 增加文档文件 ID 取址；通用产物回传待开发，真实账号登录、媒体兼容与连续运行仍须后续验收；不要把协议夹具测试称为真实 QQ 收发通过。

## 安装协议组件

默认主 Compose 不启动 NapCat，不开放协议端口。协议组件使用独立叠加文件，并固定官方发布标签与镜像摘要。按项目既有方式在 Ubuntu 中手动拉取：

```bash
docker pull mlikiowa/napcat-docker:v4.18.41@sha256:b101b8968cc31ae428ec0f8e117386e4ced7773b2d8226ed9f7ddfcec55f1b7e
```

在服务器 `.env` 设置独立、随机的 `NAPCAT_WEBUI_TOKEN`，勿复用管理员密码或 OneBot 访问令牌。不要把 `.env` 或终端中的令牌发到聊天、日志或版本库。

```bash
docker compose -f compose.yaml -f compose.qq.yaml --profile qq up -d --no-build napcat
```

本机管理地址为 `http://127.0.0.1:6099/webui`。远程服务器使用 SSH 隧道访问该地址，不将 6099、3001 或 Core 的 8000 端口公开到公网。WebUI 使用上述独立令牌；QQ 登录由账号持有人亲自完成。卷 `napcat-qq`、`napcat-config` 保存登录资料与协议配置；不要随重启删除。

## 平台配置

1. 在灵犀“平台接入 → 平台实例”新建实例，填写机器人 QQ、至少 32 位的 OneBot 随机访问令牌，并在预览中明确启用。机器人账号不可在旧实例上替换。
2. 展开实例的接入说明，取得 `ws://core:8000/gateway/onebot/v11/ws/<实例 ID>`。在 NapCat WebUI 中新增 OneBot v11 反向 WebSocket 连接，填入地址与相同访问令牌；开启数组消息格式和心跳（建议 30 秒以内）。禁用不需要的默认正向监听。协议端应发送 `Authorization: Bearer ...` 和 `X-Self-ID` 标头，URL 不包含令牌。
3. NapCat 初次 `MODE=ws` 仅初始化缺失配置，已有配置由 WebUI 管理；后续不会靠环境变量覆盖现有协议配置。灵犀不自动登录、扫码或循环尝试登录。
4. 回灵犀查看实际连接、心跳、账号登录与组件版本。连接认证、QQ 在线和文字发送回执是不同状态；无回执时仍显示待验证。
5. 默认只响应已绑定私聊，群聊关闭。“渠道规则”可明确允许未绑定私聊（始终隔离记忆），或填写允许群号并开启群响应；群内只响应提及机器人或以 `/灵犀` 加空格／换行开头的命令。未触发的群消息不保存正文。

## 身份绑定

在“身份绑定”填写本人 QQ、选择平台，并决定是否允许本人私聊检索及保存个人记忆。申请只产生十分钟有效、一次显示的 `/bind ...` 命令。用对应 QQ 私聊机器人发送，回到 Web 刷新显示“QQ 已验证”，核对账号和权限后再次点击“确认绑定”才生效。命令不进入模型、消息历史或日志。

绑定不合并 Web／QQ 聊天历史、不允许管理操作或执行工具。未选择记忆共享时使用独立上下文；即使是已绑定所有者，群聊也不读取个人记忆或支持偏好。撤销后在途生成与未发送内容失效，原来明确保存的个人记忆保留。申请过期后先撤销，再重新申请。

## 投递与故障

- 同实例、会话目标、外部消息 ID 去重；同目标有序处理。默认单发送者每分钟最多接受 10 条，实例最多 100 条等待／运行，过一小时的排队输入不集中补发。
- 回复按每段最多 1500 字分页，总计最多 18000 字。超预算明确要求缩小范围；不悄悄截断并声称完整发送。OneBot 使用文本内容块，不解析模型输出中的 CQ 码。
- 先提交发送意图再发协议请求。只有带匹配 echo 和有效 message_id 的成功回执记为“协议已接受”，不标为送达或已读。协议错误只显示脱敏原因，不展示上游原始错误体。
- 丢失回执、断线或进程重启时，已开始的发送记为“结果未知”，不自动重发；相同目标暂停继续投递，其他会话可继续。用户在 QQ 核对后可在收发记录“结束等待”，保留未知／失败事实并取消剩余分段，不把人工结束标成成功。
- 浏览器关闭不影响服务器执行。Core／协议组件断线重连后继续未开始的有效作业；中断生成不自动重放，部分回答不投递。QQ 登录失效进入人工处理状态，Web 文字对话继续。
- 停用、换令牌或规则变更立即使旧配置作业失效；重连重新认证。禁止多个 Core 持有同实例有效连接。备份恢复与服务器迁移仍须停止旧实例和旧 QQ 连接。

## 主动联系（v1.32）

1. 先完成上面的双向身份绑定，并明确允许个人记忆；只有工作区本人、有效绑定、启用私聊的平台可作为目标。
2. 在“主动交流 → 联系偏好”选择 QQ 私聊账号，检查平台及 QQ 号码。第一次选择或更换目标时，在保存预览中明确勾选个人记忆与授权事件发送许可。平台配置或绑定版本变化后须重新选择。
3. 普通主动话题共用每天 2 次、间隔 3 小时、22:00–08:00 安静的默认设置。提醒／任务结果仍按原有独立站内规则，未接入 QQ 通知。目标离线等待，不切换账号或渠道；群主动发布关闭。
4. “联系记录”显示目标和真实状态。单条主动内容最多 1500 字，超过预算不截断；尚未发送内容不会写入 QQ 对话。有效 `echo`、整数成功码与消息 ID 才记为协议接受，并写入原私聊会话；此时可接续。
5. 结果未知或协议失败不自动重发，并阻止同平台后续普通主动联系。在 QQ 核对后用“核对投递”明确结束等待；这不是重试，也不标记成功。主动联系的未知结果不阻止用户主动提问得到正常回复。
6. “先别聊”等控制在对应私聊会话生效。修改偏好取消旧排队内容，来源纠正、删除、关闭、撤权或过期阻止旧内容发送；不承诺撤回已经发出的消息。QQ 联系不在 Web 再弹出一次主动提示，Web 仍可查看记录。
7. 恢复旧备份时保留最新回执屏障（不携带原文）、撤销 QQ 绑定和平台授权、禁用联系偏好，并复位 Web 目标，须重新确认后使用。已存在投递记录时禁止直接降级 `0027`；应使用升级前备份和配套镜像。

接口：`GET /api/proactive-targets`、`PUT /api/contact-preferences` 的 `delivery/qq_acknowledged`、`POST /api/proactive-contacts/{id}/delivery-review`。当前验证为隔离合成 OneBot，不能代替真实 QQ 验收；见[验证记录](./QQ主动联系验证记录.md)。

## 附件接收（v1.33）

在“渠道规则”编辑并预览开启“接收图片与直链文档”，逐项填写协议实际返回的完整域名，例如 `multimedia.nt.qq.com.cn`、`gchat.qpic.cn`。这些只是填写示例，不能据此宣称当前 NapCat 一定使用这些域名。域名按精确匹配，不能填协议、路径、通配符、IP 或端口。仅接受公共 HTTPS 的 443 端口，不允许内网或明文 HTTP；真实协议若没有可用链接，先使用 Web 上传。

接收的 OneBot 数组片段为 `image.data.url`，或 `file.data.url` 加 `file.data.name`。`file` 是协议端扩展，应按实际 NapCat 上报验证。不会把 `image.data.file` 缓存名、本地绝对路径或文件 ID 当成下载路径。只处理被触发、身份允许的消息，不采集文件上传通知。任何不支持的片段都会明确提示，整条消息不忽略部分内容去作答。

图片完成归一化且对话模型已通过视觉验证后进入聊天。文档沿用 Web 的 TXT／MD／CSV／文本 PDF／DOCX／XLSX 解析及来源引用。最多 10 个附件，单个 20 MiB、总计 50 MiB，下载总时限 120 秒；链接五分钟有效窗口，重定向、压缩传输、过大、过期、空文件、类型或解析失败均提示重新上传，不自动扩大权限或改用其他域名。

“收发记录”显示附件类型、大小及下载／解析／失败状态，不显示签名 URL、文件名或模型上下文。临时 URL 加密存储，完成、失败、撤权后清除；其他原始附件、解析和删除沿用统一生命周期。绑定者群聊仍使用独立主体，不能继承本人私聊记忆。停用或规则变更取消旧接收，删除附件影响生成及尚未发送的回复。

本批只输出文字，不回传图片／文档或播音。详见[QQ 附件验证记录](./QQ附件验证记录.md)。

## 语音接收（v1.34）

1. 在“语音配置”选择 ASR 模型、启用语音配置并完成真实接口验证，再在“渠道规则”预览开启“接收 QQ 语音消息”。此项与图片／文档下载域名分开控制，不需要语音 CDN 白名单。
2. 固定 NapCat `v4.18.41` 的 `record.data.file` 是上下文缓存键，首批只接收 32 位十六进制，可带 `.amr`、`.silk`、`.slk`、`.wav` 后缀。其他格式明确提示改用文字，不当成本地路径、URL 或搜索表达式。真实账号若上报不同格式，先记录脱敏样式再扩展适配器，勿放宽成任意路径。
3. 灵犀发送 `get_record`，参数为原缓存键与 `out_format=wav`；只读取同一认证连接、匹配未完成 echo 的 `data.base64`。忽略返回的 `file`／`url`。不向模型传缓存键，不读取 NapCat 卷，不访问音频直链。正常消息仍为 64 KiB 上限，大回执只用于有界音频转换；反向 WS 不公开到公网。
4. 每消息最多一段语音，所有附件合计仍最多 10 个／50 MiB。转换等待 60 秒；波形最多 6 MiB，16 位、1–2 声道、8–48 kHz、0.1–60 秒的完整 PCM WAV。超限、格式不符、混合消息中任一附件失败均停止整条问答。
5. worker 使用已验证的 ASR，浏览器与 QQ 共用每所有者每分钟 30 次音频调用预算。识别前写入持久化调用屏障；超时、断线或结果未知不自动重复付费调用，用户可重新发送或改用文字。ASR 配置／提供商变化使在途结果失效。
6. 音频是会话附件，转写来源显示“QQ语音转写（未经确认）”，可在有权访问的原会话和文件管理查看／删除。转写可能有误，含语音消息不自动抽取长期记忆；需要记住时请用文字重新明确表达。不据此执行工具，回复仅为文字，不启动浏览器录音或播音。
7. 身份绑定、群触发、去重、串行与协议回执沿用原规则。未经共享授权的私聊与所有群聊仍使用独立主体；不继承所有者私人记忆或资源权限。原会话或附件删除、渠道关闭、撤权使在途结果与未发送回复失效。
8. 本批迁移 `0029`；有语音记录时不能直接降级，恢复升级前数据库与配套镜像。浏览器关闭不终止后台转写；备份恢复隔离会取消旧转换、识别和未发送消息。

固定源码参考：[GetRecord](https://github.com/NapNeko/NapCatQQ/blob/v4.18.41/packages/napcat-onebot/action/file/GetRecord.ts)、[记录消息转换](https://github.com/NapNeko/NapCatQQ/blob/v4.18.41/packages/napcat-onebot/api/msg.ts)、[上下文缓存标识](https://github.com/NapNeko/NapCatQQ/blob/v4.18.41/packages/napcat-common/src/file-uuid.ts)。源码核对不是实际账号兼容证明。验证结果见[QQ 语音验证记录](./QQ语音验证记录.md)。

## 语音回复（v1.35）

1. 在语音配置启用并验证 TTS。跟随人格音色时还需验证所用音色；更换服务或音色后重新验证。
2. 在渠道规则勾选“附加 QQ 语音回复”，预览范围、服务额度与回退行为后确认保存。与语音接收独立，默认关闭；普通文字或附件问题也可获得短语音回复。
3. 完整文字照常发送；600 字以内的短回复可另发一条 `record`，包含服务器合成的 `base64://` WAV，固定 NapCat 版本负责转为 QQ 语音。最长 60 秒、6 MiB；不发送本机路径、下载地址或合成片段的公开链接。不混合 `at` 和语音；群内前一条文字会提及原发送者。
4. 长回复、不含可读文本、未验证音色、合成错误或限流，仅保留文字。收发记录显示语音合成阶段及真实失败原因，不承诺整段被读出，不自动重复付费合成。
5. 文字协议回执通过后才发语音；两条分别记录，发送前提交持久化意图。协议接受不等于用户听到或已读；断线或超时结果未知时不自动重发，可在 QQ 核对后结束等待。
6. 来源删除、身份撤销或配置变化会阻断新合成和失效结果发送。临时波形加密保存，在发送意图、失效或一小时过期时清理；worker 每 30 秒清理离线过期。已发生的协议外部操作不能撤回。
7. 不开启浏览器实时语音、不扩展工具权限、不为主动消息自动合成；群聊隔离和授权路由继续生效。
8. 迁移 `0030`；含语音回复记录不能直接降级。恢复升级前数据库和配套镜像，恢复流程先重放删除／撤销记录并隔离旧作业。

真实 NapCat 语音收发和音质仍待验证。已验证的固定版本源代码支持 `record` → `uriToLocalFile(base64)` → `encodeSilk`；这不是实际账号收发证明。详见 [QQ 语音回复验证记录](./QQ语音回复验证记录.md)。


## 长文文件（v1.38）

1. 进入“平台接入 → 渠道规则 → 编辑规则”，勾选“允许长回答转为文件”，预览后确认。默认关闭，与附件接收、语音输入输出各自独立；不更改真实模型、身份绑定或主动交流授权。
2. 超过 6000 字符的完整回答转为 UTF-8 Markdown，最多 512 KiB；先发说明，再上传文件。较短仍发文字；超过文件预算明确提示未完整发送。长文件不再附加 TTS，不发生额外文件生成模型调用。
3. 只输出当前已完成回答。不能要求此入口发送服务器路径或原始上传附件，不包含额外历史；群文件对原群成员可见。生成名称为 `lingxi-answer-<内部ID>.md`，不使用用户标题或模型给出的路径。
4. 固定 NapCat `v4.18.41` 的文件上传参数为 `file=base64://...`、`name`、原 `user_id` 或 `group_id` 以及 `upload_file=true`。不使用共享卷或公网下载链接。上传成功返回 `file_id`，与文字消息的 `message_id` 分开记录；返回空 ID、超时、断线时为未知，先在 QQ 核对，不自动重发。协议接受不等于对方收到或下载。
5. 发送前复查来源与权限。删除或纠正依据、撤销身份、停用／修改渠道和到期均停止未发送内容；无法撤销已经提交给 QQ 的文件。人工“结束等待”保留未知／失败事实，不重新上传。恢复旧备份保留新回执和去重屏障并停用旧授权，防止旧文件复活。
6. 迁移 `0033`。有文件投递记录时不能直接降级；回退使用升级前数据库、配套 Core／worker／Web 镜像及独立删除记录，按备份恢复流程隔离外部操作。
7. 本功能是回答文件输出，不代表通用任务产物、图片回传或文件 ID 输入完成。真实 QQ 私聊、群文件权限、下载、文件大小限制和运行稳定性仍待用户登录后的验收。

## 文档取址（v1.39）

开启既有“附件接收”并填写实际下载域名后，支持 `file` 片段的 `file`／`name` 文档名。无直链且提供有效文件 ID 时，使用原认证 OneBot 连接取址；文档类型沿用 TXT／MD／CSV／文本 PDF／DOCX／XLSX，单个 20 MiB、单条 50 MiB、最多 10 个。

固定 NapCat v4.18.41 协议：私聊 `get_private_file_url` 只传 `file_id`；群聊 `get_group_file_url` 传原 `group_id` 字符串及 `file_id`。只接受匹配回执、整数 `retcode=0`、`status=ok` 和合法 HTTPS URL。需 NapCat 文件／Packet API 可用；不可用时明确失败，不尝试本地文件或全局搜索。

取址等待最多 60 秒；收到地址后有五分钟下载窗口，下载总时限仍为 120 秒。URL 必须属于已允许的公共 HTTPS 精确域名；仅返回 HTTP 时提示使用 Web 上传，不自动改为 HTTPS。已声明大小必须有效且与实际字节一致。ID、URL 不进入模型或普通日志，其他返回的本地路径和 Base64 全部忽略。

同消息所有文档地址就绪后只创建一个下载作业，沿用统一解析、身份、来源及删除机制。来源删除、撤权、配置改变及恢复隔离停止旧输入。取址中断不自动重发；已完成取址可在有效期内续接。普通群上传和离线文件通知不自动读取，也不改为收集所有群消息。

迁移 `0034` 新增独立文档状态字段；有状态记录禁止直接降级。合成协议验证及真实 QQ 待验证范围见[QQ 文档接收验证记录](./QQ文档接收验证记录.md)。

## QQ 后台协作（v1.43）

QQ 私聊发送 `/协作 任务目标`；允许的群内先提及机器人，或发送 `/灵犀 /协作 任务目标`。只有明确文字命令建立请求，普通聊天、转写、引用和身份绑定不授权执行。请求等待“平台接入 → 渠道规则 → 后台协作”逐次确认；未确认不调用协作模型、不执行工具，24 小时到期。

管理员按本次请求选择最多八个候选助手、精确工具、相关记忆开关、明确共享子目录和模型调用上限。服务端预览展示完整人格／角色配置、模型、工具地址、数据范围、费用说明、附件与原接收者；核对其中私人资料后才确认。预览五分钟有效，与当前登录、版本和摘要绑定，变化后必须重看。群聊硬性禁止所有者私人记忆；已绑定本人且独立允许个人记忆的私聊，仍须本次明确勾选。共享服务器资料仅列指定子目录元数据，不允许根目录、越界路径或符号链接。

沿用持久化自动分工、八节点／三并发／一层委派、累计调用预算及逐次 API／MCP 确认。执行归所有者，来源与附件归原 QQ actor，分别核验，不能把隔离群身份当成所有者。只使用本次经审核助手配置，修改角色或人格版本即停止旧授权。工具预览额外显示 QQ 受众，群管理员不能代替 Web 所有者确认。子助手不各自发消息；待工具确认及最终结果由主助手经原目标统一投递，不改接收者、不转备用渠道、不播音、不消耗普通主动聊天次数。

每轮提示／汇总有独立持久通知记录。断线与结果未知不自动重发；协议接受不等于送达或已读。浏览器关闭不终止任务，Core／worker 重启后恢复已排队步骤，已开始却中断的计费步骤沿用人工核对／重试规则。来源、附件、记忆、身份或渠道授权失效会停止使用并阻止旧结果投递；有效期覆盖运行期。恢复备份隔离所有旧 QQ 协作授权、作业和待发结果，不通过重新启用渠道复活旧任务。已发生的外部操作不能撤销。

新增 `/api/channel-tasks` 查询及 `/{id}/preview`、`/{id}/confirm`、`/{id}/cancel`，复用所有者认证、CSRF、工作区、版本与幂等约束。迁移 `0037`；存在任务授权或通知记录时不能直接降级丢弃屏障，须恢复升级前备份与配套镜像。本增量是 QQ 后台协作，不开放语音协作或 QQ 普通聊天自动执行，也不将通用产物上传描述为已交付。真实提供商质量和真实 QQ 收发仍待验证。使用与证据见[QQ 协作验证记录](./QQ协作验证记录.md)。
