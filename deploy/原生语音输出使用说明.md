# 原生语音输出使用说明（v1.58）

灵犀的原生输出是可选的逐句合成适配。回复先由 Core 生成并保存，语音会话再按播放顺序把当前短句交给 Realtime；Core 缓存音频并核对返回字幕，核对成功后才交给浏览器播放器。模型不能改写聊天、记忆、工具权限或播放内容。

## 配置与验证

1. 在服务连接中配置支持 Realtime 会话和音频输出的 OpenAI 协议服务。根地址按供应商填写，Core 会在连接上追加 `realtime`，不会把实时协议当作普通 `/chat/completions`。
2. 在“语音配置”的“实时合成”选择独立模型。它可以与实时转写模型不同；普通 Chat Completions 可用不代表具备原生音频输出能力。
3. 保存后点击“验证实时合成”。服务必须返回 PCM 音频及与验证短句一致的音频字幕，才会显示“实时合成已验证”。验证可能计费，不写入聊天或记忆。
4. 在语音会话中继续使用原有“开启语音”流程。只有实时合成验证有效时，Core 才为每个短句调用原生输出；否则沿用已验证的普通 TTS。实时输出失败不会自动重复、切换模型或隐藏文字。

修改实时输出模型、供应商、连接版本、音色、语速或语音配置版本后，验证立即失效。输出使用当前回合已冻结的人格音色；人格变化、会话结束、来源删除或用户打断会使迟到音频丢弃。

## 数据和安全边界

- 浏览器只请求同源 Core，不接触服务密钥。Core 使用系统代理、目标地址授权、DNS 固定和 TLS 校验。
- 上游使用 `response.conversation=none` 的独立响应，避免把原生模型的输入或输出写入独立会话历史；仅传当前已确认的短句。
- 音频在服务器内存中有界缓存，转换为 24 kHz 单声道 PCM WAV 后返回；不保存原始音频、上游提示词或返回字幕。调用记录只保存模型、版本、状态、耗时和传输方式。
- 返回的音频字幕必须与原短句去除空白后完全一致。标点、内容或顺序不一致都会丢弃音频并保留文字。
- 返回前重新检查登录、语音会话、播放游标、消息来源、配置和供应商版本；未知状态不盲目重播。
- 停止播报先停止本地播放器，后续播放回执仍按已听完的完整短句计算；未播放内容不会进入下一轮语音上下文。

## 兼容性和故障处理

当前适配使用 Realtime `session.update`、`response.create`、`response.output_audio.delta`、音频字幕事件和 `response.done`。供应商若只支持转写、不支持音频输出，验证会失败且文字入口继续可用。模型返回音频格式、字幕事件或音色不兼容时，页面显示错误，不自动降级以免重复付费。

浏览器隐藏、离线、会话心跳失效和服务器迁移会停止当前播放。已缓存但未通过来源核验的音频不会播放；已完成的聊天回复继续保留。

参考 [OpenAI Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations) 和 [Realtime client events](https://developers.openai.com/api/reference/resources/realtime/client-events)。官方文档说明 `response.create` 可使用 `conversation: none`，音频通过 `response.output_audio.delta` 返回；实际模型、音色、格式和账号权限仍需逐服务验证。
