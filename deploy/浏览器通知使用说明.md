# 浏览器通知使用说明（v1.70）

## 开启与关闭

进入「主动交流 → 联系偏好 → 浏览通知」。默认关闭，只有点击「开启通知」才申请浏览器权限；拒绝后不反复申请，可在浏览器站点设置中调整。需要安全上下文和支持 Notification 的浏览器；不支持时仍可查看站内消息。

浏览器权限、当前浏览器的本地选择、服务器通知同意是三层独立状态。每个浏览器均需主动开启；关闭操作撤销服务器同意并提升版本，使其他浏览器原有选择失效。再次开启不会自动替其他浏览器恢复选择。系统权限不能由服务器修改。

通知检查器随已登录工作区运行，页面每 15 秒核对一次；只在标签页位于后台时尝试展示。浏览器关闭、标签页被挂起、登录退出、浏览器或系统限制均可能阻止展示。不使用 Service Worker 或后台 Push，不自动播音、开启麦克风或改投 QQ。

## 统一规则与隐私

只为开启后新建的 Web 主动交流登记候选，有效期最多 120 秒，并受话题自身有效期限制。不补发旧交流；QQ 投递及已选择主动语音的交流不再附加系统通知。

通知只是同一条站内交流的另一种展示，不新增联系或重复占用额度。核心仍检查联系偏好版本、安静时段、暂缓、关闭、话题范围、屏蔽、来源版本与删除、当前渠道及会话有效性。出现新用户发言、正在生成的对话或已有交流反馈时停止候选。模型、插件和子助手不能直接发系统通知。

系统通知使用固定标题和通用提示，不包含交流正文、记忆或附件；设置静音。点击后打开「联系记录」，不自动认定为有用反馈或已读。回到前台、本地设置变化、退出或核对失败时关闭本页打开的提示；远端失效由下一次成功轮询核对，浏览器调度可能延迟，不能撤回用户已经看见的提示。

## 去重、回执与恢复

领取前以所有者锁和唯一联系约束保存尝试屏障，HTTP 返回后不确定、浏览器构造失败或回执丢失都不重试。多个标签页、浏览器竞争同一候选时只允许一次尝试。展示前再次读取当前来源与偏好；历史尝试状态与当前是否仍可展示分别记录。

| 状态 | 含义 |
| --- | --- |
| 等待时机 | 尚未领取，仍须重新核对 |
| 结果未知 | 尝试已持久化，浏览器结果未知，不重发 |
| 请求展示 | 浏览器构造函数已返回；不能证明系统显示、送达或已读 |
| 展示失败 | 浏览器构造或异步展示失败，不自动重发 |
| 点击提示 | 收到本页点击回调，不等于交流反馈 |
| 已经失效／已经过期 | 未尝试候选不再展示 |

备份恢复保留当前尝试屏障和历史回执，取消未尝试候选、清除旧登录绑定、关闭通知同意并提升版本。需要重新由每个浏览器主动开启，不重放备份中的通知。

## 接口与数据

所有接口要求登录；主体和工作区由服务端决定，写请求沿用 CSRF 防护。状态只返回设置、回执元数据和固定说明，不含正文。

| 接口 | 用途 |
| --- | --- |
| `GET /api/browser-notifications/state` | 当前同意、最多 20 项最近回执及当前有效性 |
| `PUT /api/browser-notifications/preferences` | 版本检查后开启／关闭，要求确认仅运行中页面可通知 |
| `POST /api/browser-notifications/claims` | 后台页面使用同意版本领取一次尝试 |
| `POST /api/browser-notifications/{id}/ack` | 原登录会话报告请求展示、失败或点击 |

迁移 `0054 → 0055` 新增同意表和通知回执表。空表可降级；有同意或尝试记录时拒绝有损降级，应使用升级前数据库、运行归档及配套镜像整体回退。

## 验证范围

独立 PostgreSQL 相关回归 360 项通过，包含并发领取和备份恢复；前端全量 417 项、类型、静态检查和构建通过。HTTP→Nginx→Core→PostgreSQL 验证真实候选登记、两个登录竞争、历史回执、来源删除失效及重启不重放；迁移升级、空表回退和有数据拒绝降级通过。375／768／1024／1440px 无横向溢出，刷新、键盘顺序及记录展开通过。

浏览器通知生命周期测试使用替身，不申请真实系统通知权限、不发送真实通知、不调用真实模型或 QQ。真实系统展示、浏览器后台调度、操作系统限制及完整主动交流质量仍待验证。
