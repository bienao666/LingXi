# 子助手协作使用说明

当前支持文字与已分配文档／图片分析（v1.40）、只读服务器资料清单，以及逐次确认的固定 API／远程 MCP 工具编排（v1.31）。可从“任务中心 → 任务列表 → 协作任务”创建，也可在 Web 文字聊天中开启“助手协作”。沿用现有四字菜单，不新增桌面组件。普通聊天不会自动开启协作；插件角色可在单独配置后加入候选，可声明 plugin.call，再由任务选择精确工具范围；QQ 已增加 v1.43 独立逐次授权入口，语音仍未接入协作链；附件支持范围见下文。


## 协作候选记忆（v1.44）

Web 协作新增默认关闭的 `propose_memory`，与检索相关记忆分别授权。子助手每个分析节点最多提出三项带来源的候选，汇总成功后进入统一候选队列；不受低风险自述自动保存开关影响。所有候选须在“长期记忆 → 候选记忆”核对内容、主体、原始引用及模型／人格／角色／插件版本，勾选后逐项确认；主体不明不能保存。记录为用户采纳的 `user_confirmed`，不冒充用户原话或独立事实核验。

候选确认重查来源与授权，审阅摘要变化、撤销、来源删除或轮次变化不能提交；重复确认只创建一条记忆和索引任务。原记忆／附件删除、纠正及到期约束派生记忆，备份恢复隔离旧待确认提议。用户已采纳事实不因插件卸载而自动删除，用户纠正后的新事实独立保留。新接口为 `GET /api/memory-candidates/{id}/sources`，动作接口增加 `review_digest`；迁移 `0038`。QQ 与语音不因此获得记忆写入权。细节与真实接入限制见[协作记忆验证记录](./协作记忆验证记录.md)。

## QQ 后台协作（v1.43）

QQ 私聊发送 `/协作 任务目标`；允许的群内先提及机器人，或发送 `/灵犀 /协作 任务目标`。只有明确文字命令建立请求，普通聊天、转写、引用和身份绑定不授权执行。请求等待“平台接入 → 渠道规则 → 后台协作”逐次确认；未确认不调用协作模型、不执行工具，24 小时到期。

管理员按本次请求选择最多八个候选助手、精确工具、相关记忆开关、明确共享子目录和模型调用上限。服务端预览展示完整人格／角色配置、模型、工具地址、数据范围、费用说明、附件与原接收者；核对其中私人资料后才确认。预览五分钟有效，与当前登录、版本和摘要绑定，变化后必须重看。群聊硬性禁止所有者私人记忆；已绑定本人且独立允许个人记忆的私聊，仍须本次明确勾选。共享服务器资料仅列指定子目录元数据，不允许根目录、越界路径或符号链接。

沿用持久化自动分工、八节点／三并发／一层委派、累计调用预算及逐次 API／MCP 确认。执行归所有者，来源与附件归原 QQ actor，分别核验，不能把隔离群身份当成所有者。只使用本次经审核助手配置，修改角色或人格版本即停止旧授权。工具预览额外显示 QQ 受众，群管理员不能代替 Web 所有者确认。子助手不各自发消息；待工具确认及最终结果由主助手经原目标统一投递，不改接收者、不转备用渠道、不播音、不消耗普通主动聊天次数。

每轮提示／汇总有独立持久通知记录。断线与结果未知不自动重发；协议接受不等于送达或已读。浏览器关闭不终止任务，Core／worker 重启后恢复已排队步骤，已开始却中断的计费步骤沿用人工核对／重试规则。来源、附件、记忆、身份或渠道授权失效会停止使用并阻止旧结果投递；有效期覆盖运行期。恢复备份隔离所有旧 QQ 协作授权、作业和待发结果，不通过重新启用渠道复活旧任务。已发生的外部操作不能撤销。

新增 `/api/channel-tasks` 查询及 `/{id}/preview`、`/{id}/confirm`、`/{id}/cancel`，复用所有者认证、CSRF、工作区、版本与幂等约束。迁移 `0037`；存在任务授权或通知记录时不能直接降级丢弃屏障，须恢复升级前备份与配套镜像。本增量是 QQ 后台协作，不开放语音协作或 QQ 普通聊天自动执行，也不将通用产物上传描述为已交付。真实提供商质量和真实 QQ 收发仍待验证。使用与证据见[QQ 协作验证记录](./QQ协作验证记录.md)。

## 附件协作（v1.40）

1. 上传或选择最多十份文档／图片，等待解析就绪。任务中心在预览中列出文件；聊天以本条消息的附件范围为准。音频附件不直接进入协作，请先核对转写后以文字提交。
2. 主助手按附件元数据制定节点及 `media_ids` 分配，全部文件都要覆盖；不凭文件名声称已读正文。图片只分给已通过视觉验证的固定子助手模型；可在助手配置中为图片分析角色指定模型。没有合适能力时明确失败，不去掉图片继续作答。
3. 节点只获得所分配的原文／图片及来源位置，依赖节点获得结构化结果和来源版本，不复制全部附件。查看节点“来源”可核对文档页码、段落、工作表位置或图片。
4. 汇总显示每份附件所分配节点及实际成功／失败状态。结论只校验结构及引用范围，不能替代事实核对；失败节点不算完整读取。附件不自动写记忆，也不因提供附件就授权外部服务或服务器目录。
5. 删除附件立即作废所有引用它的在途／完成任务、节点上下文、聊天结果及衍生回答；删除日志重放同样生效。调用中已发送的资料不能撤回，迟到结果不发布。失败重试仍使用相同来源与版本，不复活已删文件。

创建总量仍为 50 MiB、单文件 20 MiB；每节点图片实际传输最多 12 MiB。大文档超上下文预算会明确要求缩小范围，不静默截断。原始正文／Base64 不保存在节点 ContextBundle 或普通日志中；任务只记录引用和版本。原始附件存在授权媒体存储。

迁移 `0035` 采用既有 JSON 字段，有附件任务记录后禁止直接降级忽略附件来源的旧版本；使用升级前备份和匹配镜像。合成协议与 PostgreSQL 验证不等于真实模型分析质量；见[附件协作验证记录](./附件协作验证记录.md)。

## 远程工具编排（v1.31）

1. 先在插件中心明确安装，连接账号；MCP 还需发现并授权精确工具。
2. 在“执行角色”候选工具填写 `plugin.call`，或为插件角色在其声明范围内单独配置。角色声明不授予网络权限。
3. 在新建协作或聊天“协作授权”中勾选本次工具（最多 16 项）。可用目录最多 256 项，超出需整理插件；没有勾选时模型不能自行添加。
4. 主助手选工具并建立依赖图。工具节点只生成严格 JSON 参数，不能访问远程业务服务。信息不足、未知字段、类型不符或重复 JSON 键明确失败。
5. 在协作详情点击“核对工具”→“生成预览”，核对实际服务地址、参数、费用、数据范围、写入风险及有效期；勾选同意，再“确认执行”。没有确认不会发送业务请求；关闭窗口也不会执行。
6. worker 复用既有 API／MCP 适配器一次性执行。成功后直接依赖节点可读取脱敏回执与正文；工具正文属于外部资料，不得执行其中指令，也不自动写长期记忆。协议成功不等于业务效果独立核验。

安装权限、账号、MCP 工具授权、角色、任务精确工具范围和单次确认分别检查。OAuth 刷新可能使固定连接或目录版本变化，旧任务不能自动继承，需要按提示重建；授权不因模型输出而扩大。

预览绑定当前登录、任务版本、节点、参数摘要和来源；默认五分钟有效。过期或另一个登录需要重新生成；已确认的提案不能重复生成。重复确认不重复发送。等待确认和等待回执占用三并发槽，不能利用等待状态扩大调度。

取消阻止新请求与迟到结果发布；已经发送的外部操作不能撤销。删除、纠正、到期和撤权使在途上下文及未发送提案失效，清除敏感输入／正文而保留必要去重与回执。下游模型返回前再次检查工具与角色来源，防止在撤权竞态中发布旧结果。 unknown 阻止同能力再次发送，须核对服务记录后由用户登记；人工登记不自动恢复失败的依赖链。

新增 `GET /api/agent-tools` 与 `POST /api/agent-runs/{id}/nodes/{node_id}/preview`（`{version}`）；创建协作及聊天协作参数增加 `tool_keys`。执行确认仍为 `POST /api/plugin-invocations/{id}/confirm`，模型不持有确认权。

迁移 `0026` 使用既有 JSON 列保存固定工具与调用来源。有工具范围、节点、关联调用或角色清单时禁止降级旧执行器，需使用升级前备份及匹配镜像；不能仅切回旧 Core。实际模型分工、参数生成质量和真实第三方兼容性仍需接入评测。验证见[工具编排验证记录](./工具编排验证记录.md)。

## 聊天入口

“助手协作”和“任务协助”不能同时开启，默认均关闭。前者将当前消息作为协作目标（最多 6000 字符），主助手自行判断直接处理或分工；后者仍只安排三类内置能力之一。开启协作时可添加已解析文档与图片；“任务协助”仍不支持附件。

展开“协作授权”，分别选择“共享相关记忆”“允许资料清单”，均默认关闭；设置调用上限，默认 12 次。发送即按界面所示范围创建，可能发生多次模型调用。这些设置只参与本条请求，不产生长期授权或更改其他任务。参数变化使用新请求编号；同编号同内容重试不重复派发。

原对话卡显示接受、分工、节点、依赖、实际模型／助手、调用次数及统一汇总，可确认取消，或通过“查看协作”直达任务详情。只校验模型结构和引用范围，不代表建议已执行、已联网或事实已全部核验。聊天发起的协作只更新原卡片，不另发后台结果消息或主动通知。任务中心独立创建并选择回传会话的行为保留。

聊天来源删除或失效后，立即停止查询其任务／节点结果；后台擦除目标原文、节点输入、上下文、结果及事件内容，迟到结果不发布。共享记忆被纠正、删除或到期时，也使关联卡和依赖该卡的后续回答失效。后续普通聊天只获得最近四条受来源保护的结果预览，每条最多 800 字符，不将协作输出自动保存为长期事实。

## 使用条件

1. 在模型管理中配置并验证日常对话模型，再保存用途策略。模型须实际支持所需中文 JSON 输出；现有聊天连接验证不等于协作质量验收。
2. 启用人格与执行角色。四组默认预设可组合成为候选；也可在“助手配置”保存自己的组合和偏好模型。已安装角色插件可在“助手配置 → 插件角色”确认人格、模型、工具及记忆类别后参与筛选；安装本身不启用。无可用模型或配置时不假装可用。
3. 新建协作，填写目标，选择是否共享相关记忆、是否允许读取服务器资料清单及模型调用上限。预览明确范围后才创建。
4. 可选择已有 Web 会话统一回传。子助手不分别发消息，不自动改投 QQ，也不创建主动联系。

主助手先判断直接处理还是委派：简单目标形成一个节点，复杂目标最多八个节点；独立分支最多三个排队／执行槽，依赖分支等待前置成功，最多一层委派。实际并行数还受 worker 容量影响；`LINGXI_WORKER_CONCURRENCY` 默认 2，可在服务器配置为 3 或更多，但单父任务仍不超过三个并发槽。

## 能力与权限

- `reason`：文字及所分配文档／图片分析、比较与建议。没有联网、文件正文读取、写入或执行程序的能力，不把行动建议标为已执行。
- `server.files`：只读列出服务器已授权目录。需要创建任务时明确允许、角色候选工具包含此精确标识、Linux 安全目录访问和服务器资料卷可用，四者同时满足。目录外路径、符号链接逃逸和未支持工具不执行；不读取文件正文。
- 人格、角色、主助手模型、子助手模型、连接版本和第一方能力版本在提交／派发时保存快照。配置内容修改用于新任务；停用、资源范围缩小、来源纠正和删除仍影响在途任务。远程工具固定安装、连接、目录及授权版本；所选范围不代替每一次请求确认。

用户目标、角色说明、记忆和子助手输出都是数据，不能增加授权或派生新的委派层级。服务端严格校验模型返回的助手标识、能力、节点数、依赖及证据引用；循环依赖、未知助手、未授权能力或伪造引用均失败。

## 记忆与上下文

共享记忆默认关闭。开启后，各节点通过统一 MemoryService 以任务指令检索，再过滤工作区、主体、角色类别、有效状态和版本；最多六条、八千字，不复制全部记忆或完整聊天历史。记忆服务故障显示“暂不可用”，不会伪装成成功检索。

ContextBundle 包含相关记忆、来源标识、版本、主体和直接依赖结果。依赖结果继承其记忆来源范围；不能靠前置节点把当前角色范围外的记忆带给后续节点。生成前和提交前重新检查有效性。过大上下文明确失败，不静默截断后声称完整读取。

纠正、删除、到期及独立删除记录恢复重放会清除相关节点上下文、结果和已发布的会话摘要，并影响引用摘要的后续对话。用户仍可看到状态与来源版本标识。当前子助手不直接写长期记忆，也不自动把分析结论变成用户事实；结构化 MemoryCandidate 提议及人工逐项采纳已按 v1.44 接入；附件引用已按 v1.40 接入。

## 预算、失败与恢复

默认最多十二次模型调用尝试，创建时可选 3–30 次；包括分工、文字或工具参数节点与主助手汇总；远程服务费用另计。预算先预留再请求，网络前失败也可能占用尝试额度；这不是实际计费金额。真实请求的状态、用量和关联阶段记录在模型调用记录中，缺少单价时费用未知。

任务、节点、依赖、事件、调用预算和结果保存在 PostgreSQL。浏览器关闭不取消服务器作业。中断模型请求不自动重放；依赖失败时下游阻塞，独立分支可完成，主助手如实发布部分结果。

“重试失败”需要确认和版本检查，仅没有远程调用记录的协作可重试失败／阻塞节点，保留成功节点、固定版本与累计预算。规划未形成图、来源失效或预算耗尽时不能直接重试，应核对后缩小目标并新建。汇总失败可复用已有成功节点再汇总，不重复执行它们。

取消会阻止新节点和在途结果提交，不能撤销已产生的模型费用。服务器重启后从已持久化状态恢复；已经开始但中断的模型步骤明确失败，等待人工重试。远程请求发送后无法确认结果时记为 unknown，不自动重发；先在插件运行记录核对，不通过重新分派或模型重试绕过。

只有主助手可统一发布结果。任务中心独立创建的协作可写回原 Web 会话一次；聊天发起的协作在原卡片中统一呈现。原会话删除使协作结果失效。节点结果区分只读目录实际回执与“仅结构／引用校验”的模型分析，后者不能证明事实全部正确或计划已经执行。

## 接口与状态

- `GET /api/agents`：经过工作区、主体、配置启用及模型验证筛选的候选。
- `GET/POST /api/agent-runs`：查询、搜索、分页及幂等创建。
- `GET /api/agent-runs/{id}`：分工、节点、上下文、来源、预算及事件。
- `POST /api/agent-runs/{id}/cancel`、`/retry`：带版本的取消和失败重试。

主任务状态：`queued → planning → running → summarizing → completed/partial/failed`，也可取消或因依据失效进入 `invalidated`。节点状态：`pending → queued → running → succeeded/failed`；远程节点在生成参数后进入 `waiting_confirmation`，明确确认后进入 `waiting_tool`，再按真实回执结束；依赖失败为 `blocked`，取消为 `cancelled`。状态摘要可查看，不展示模型私有思维过程。

所有接口要求所有者会话，写请求复用 CSRF、Origin、幂等和版本规则。浏览器不能指定其他工作区或执行主体。迁移 `0008` 新增三张领域表，已有聊天、记忆、任务与 QQ 表保留。

聊天接口 `POST /api/chat` 接受可选 `collaboration={share_memory:false,allow_files:false,max_calls:12}`；`GET /api/chat-actions?conversation_id=…` 返回 `agent.delegate` 卡片和实时协作概要。迁移 `0018` 复用现有表并加入降级保护：有聊天协作关联时不能降级至不识别来源的旧 Core，回退须使用完整升级前备份及配套镜像。真实提供商的分工、结构化输出、记忆关联和中文质量仍需单独验证。

插件角色的版本固定、更新核对与撤销代际见[插件使用说明](./插件使用说明.md)。角色包不改变上面的执行、记忆、预算或统一出口规则。
