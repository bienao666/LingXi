# 附件存储巡检说明

适用版本：v1.68；服务器 schema `0054`。入口：**系统设置 → 媒体配置 → 存储巡检**，沿用现有菜单和午夜蓝界面。

## 操作

1. 查看当前所有者的附件记录数、记录累计字节，以及附件运行卷的总量和可用容量。累计字节包含已删除记录，不代表物理占用；运行卷容量不代表数据库、备份或整个服务器的健康。
2. 设置最短保留天数（2–365 天），点击“开始扫描”。扫描为持久任务，刷新或关闭浏览器不取消任务；“查看巡检”可查看真实状态。
3. 核对候选存储键、大小、修改时间、扫描范围及保留计数。扫描不读取内容、不删除文件；预览有效期五分钟。
4. 只有确实需要删除时，勾选永久移除确认并点击“确认清理”。确认绑定当前登录、固定候选及完整摘要；更换登录、预览过期或摘要变化需重新扫描。重复确认复用执行记录。
5. 查看逐项结果。“取消后续”阻止未执行步骤，不能撤回已完成删除。不自动进行下一批清理。

这是无业务记录残留的**永久删除**，不进入回收站。请保留升级前备份；已有附件记录的闲置上传应使用同页“闲置回收”。本功能不会启用自动回收策略。

## 范围与保留规则

- 仅在受支持的 Linux 服务器执行；固定检查私有运行目录的 `media/` 第一层，不接收路径参数。
- 只识别 32 位小写十六进制 ID 加 `.blob`、`.preview`、`.json` 的单链接普通文件。未知名称、目录、符号链接和硬链接保留；不递归，不跟随目录链接。
- 修改时间及 inode 变化时间均达到保留期才可能成为候选。inode 变化时间不是跨平台通用的文件创建时间。
- 任意工作区的附件记录（包括已删除记录）、关联记录、保留记录，以及已知任务、会话、协作、插件、记忆、候选、QQ 来源和作业的历史引用均保留。宁可误保留，不尝试修复、认领或导入残留内容。
- 单次最多检查 10000 个目录条目、核对 100 个旧无记录文件的历史引用；候选最多 20 项、200 MiB。达到限制明确提示部分扫描、引用核对预算或剩余候选；不表示全卷已经检查，不保证多次扫描覆盖所有条目。
- 确认后清理作业一小时内有效。逐项在发出删除前重新核对登录、维护状态、目录身份、文件指纹、保留期及当前来源。新增引用、文件替换或变化时保留。
- 只移除当前目录项，不擦除底层介质；不遍历数据库、备份、服务器授权资料、其他挂载点，不承诺通用磁盘治理、配额或存储碎片回收。
- 私有运行卷应只允许服务账号与受信任管理员写入；本功能不把恶意宿主机管理员或被入侵的共享卷写入者作为隔离边界。

## 状态与故障

巡检：`queued → scanning → review`；预览超过五分钟按 `expired` 展示。

确认后：`confirmed → cleaning → completed / partial / unknown / failed`，可在执行前或执行间取消。逐项结果：

| 状态 | 含义 |
|---|---|
| `pending` | 尚未执行 |
| `deleting` | 已持久化删除意图，尚无确定回执 |
| `removed` | 本次成功移除了目录项，不等于释放等量物理磁盘空间 |
| `missing` | 复核时已经缺失，不计作本次删除 |
| `skipped` | 来源／指纹变化、过期、取消或其他保留条件成立 |
| `failed` | 文件操作明确失败，详细宿主机错误不返回浏览器 |
| `unknown` | 意图已持久化但结果无法确定，不自动重发删除 |

先持久化逐项意图，再进行文件操作。worker 重启、租约回收或崩溃后，不重放结果不明的删除；需人工检查。取消保留已有回执；未知结果不能通过再次确认原批次来重试。扫描可有限重试，清理失败不自动重试。

备份恢复／工作区切换保留最新巡检和删除回执，撤销旧登录确认、取消在途批次，保留已经完成事实。旧附件卷恢复后的残留由新扫描重新核对，不把旧确认当作新授权。已有巡检数据拒绝降级 `0054 → 0053`；回退须使用升级前数据库、运行卷和配套镜像。

## 接口

| 方法与路径 | 用途 |
|---|---|
| `GET /api/admin/media-storage` | 所有者逻辑记录统计与运行卷容量 |
| `GET /api/admin/media-storage/runs` | 最近 20 个持久批次及逐项结果 |
| `POST /api/admin/media-storage/scans` | `{request_id, days}` 创建幂等只读扫描 |
| `POST /api/admin/media-storage/runs/{id}/confirm` | `{digest, acknowledgement:"remove_untracked_media_files"}` 显式确认 |
| `POST /api/admin/media-storage/runs/{id}/cancel` | 取消未执行步骤，保留回执 |

全部沿用登录、工作区／所有者隔离及写请求 CSRF 检查；登录与身份从服务端确定，不接受客户端自报身份。返回数据不包含文件内容、绝对路径或内部文件指纹。

## 验证边界

验证使用独立 PostgreSQL、真实 Linux 文件系统和临时附件，通过 HTTP→Nginx→Core 与 worker 完成只读扫描、确认、重复确认、来源新增保留、取消及未知结果不重放；升级、空表回退及有记录拒绝降级单独验证。保留期测试推进测试 worker 的时钟，未实际等待两天；正常时钟下的新文件保护另有回归。

本增量 PostgreSQL 相关回归 399 项、前端全量 398 项与类型／静态／构建通过；375／768／1024／1440px、键盘勾选、焦点循环、Escape、关闭焦点返回及取消通过。Core 重启后回执仍在且不重放。2026-11-01 本机备份升级 `0054`，原 30 类业务计数与配置摘要不变，新增巡检表为空；各 219 个 Core／worker 文件、15 个 Web 制品及 11 类受保护入口核对通过。

不调用真实模型或 QQ，不扫描、确认或清理正式工作区的附件。测试结果不能代替生产容量评估、真实供应商兼容与全产品质量验收。总体状态见 [README](../README.md) 和[设计方案](../灵犀AI助手设计方案.md)。
