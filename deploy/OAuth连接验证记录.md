# OAuth 连接验证记录

版本：v1.30。日期：2026-10-30（Asia/Shanghai）。本记录区分实现、隔离协议验证与真实第三方兼容性，不代表全产品验收完成。

## 实现范围

“插件中心 → 账号授权”增加固定服务 OAuth 授权码＋PKCE S256 连接。支持公共客户端、client_secret_basic 和 client_secret_post；安装不自动连接，用户核对客户端、范围、固定地址及内网设置后生成授权入口，再明确前往授权。已有 API／MCP 的独立业务预览与工具授权继续生效。

服务器加密保存访问令牌、刷新令牌和客户端密钥；state 仅留摘要，临时 verifier 加密保存。回调绑定工作区、所有者、原登录会话、安装和连接版本，交换前持久化一次性边界。临期自动刷新支持轮换及范围收窄，未知请求不重放；撤销先清除本地执行权，再如实记录一次远端撤销请求。停用、卸载、依赖及信任变化阻止迟到结果，恢复旧备份清除旧令牌。

操作与限制见 [OAuth 连接说明](./OAuth连接说明.md)。

## 隔离端到端验证

使用独立 Compose 项目、数据库、运行卷、商店与合成 OAuth 服务，不使用真实第三方账号、付费模型或 QQ 登录。

1. 发布者提交声明 OAuth 的 API 包，独立审核员审核签名；Core 同步并经安装预览确认安装。
2. 实际 HTTP 授权入口生成 code 与 state，服务端以真实 PKCE verifier 交换令牌；回调返回站内结果，重复回调不再交换授权码。
3. 将合成令牌置于临期窗口，实际 worker 刷新一次并轮换令牌，逐次确认的业务请求各发送一次；Bearer 健康检查通过，普通结果不包含令牌。
4. 重新构建并重启 Core／worker／商店后，原加密授权及范围保留，仍能执行已确认请求。
5. 本地撤销立即生效，一次实际 RFC 7009 请求被合成服务接受；重新明确授权产生新流程，不重放旧授权码。
6. 页面填写、显式确认、生成入口、放弃授权及历史取消状态可用。375×667、768×800、1024×768、1440×900 与 768×420 检查无页面横向溢出，配置弹窗位于视口内且可滚动。取消后焦点返回“编辑授权”。
7. QA 与正式 Nginx／Core 日志均未出现特定合成回调标记或回调查询；回调使用 no-store／no-referrer。未登录管理返回 401，伪造事件回调 401、超限正文 413。

专项测试另覆盖错误 state／issuer／登录、到期、取消、迟到回调、客户端认证方式、响应大小／重复 JSON／重定向、范围扩大、刷新超时与并发、更新到手动凭据、MCP 独立工具授权、信任撤销和恢复隔离。恢复隔离在测试库验证，本批未恢复正式数据库。

## 本机发布与数据保护

正式入口 [http://localhost:8080](http://localhost:8080) 已更新至 v1.30／迁移 `0025`。升级前确认无运行中的任务和有效语音会话，保存并核验 PostgreSQL 备份，保留 pre-v130 Core／worker／Web 镜像。原 16 类业务数量与提供商、模型、用途策略、人格和语音完整配置摘要一致；Core／数据库／Hindsight healthy，worker 在线。

正式工作区未导入测试商店、信任根、插件版本、账号连接、OAuth 授权、事件或角色绑定。隔离测试结束后移除专属容器、卷及临时账号配置，保留测试脚本、验证记录与截图。升级备份不是可直接分发的公开文件，应按私密业务资料保护。

## 待验证与未实现

- 供应商专有授权查询参数、自动服务发现、动态客户端注册、设备码及其他 OAuth 流程。
- 第三方 API／MCP 自动工具链；目前仍逐次预览确认，不由模型代替安装和授权确认。
- 全损灾难恢复、真实 Hindsight 中文 150 题、语音质量及连续全功能试用。
