# 调用限额使用说明（v1.65）

在「数据日志 → 用量预算」设置每日请求上限和单次执行上限。保持午夜蓝主题、四字菜单及原有路由，不新增顶部介绍区。两项默认均为 `0`，表示不限制；不会自动改动现有模型、代理或 QQ 配置。

## 配置与计数

1. 填写每日请求上限（0–1,000,000）和单次执行上限（0–10,000）。
2. 点击「预览更改」，核对旧值、新值、已用次数和有效期。
3. 勾选说明后点击「保存限额」。预览绑定当前账号、工作区、登录会话及配置版本，5 分钟有效；发生冲突后重新加载、预览。

每日按 **UTC 00:00** 切日，即北京时间 08:00。单次执行按同一对话回合、WorkTask、AgentRun 或文字插件调用编号累计，跨天、重试和重新派发不重置。同一协作的规划、节点和总结共用协作编号；另行确认启动的任务或插件调用有独立编号，均受每日总限额约束。后台记忆与语音请求只使用每日限额；已有协作 `max_calls` 继续独立生效。

所有上游模型 POST 和实时语音 WebSocket 握手在发送前持久预扣。对话、视觉、模型验证、记忆抽取、嵌入、重排、ASR 和 TTS 都受每日限额约束；普通模型目录 GET 和健康检查不计入。实时语音按一次连接尝试计数，不按音频包或 token 计数。第三方 API／MCP 工具请求和提供商的其他服务不属于模型请求次数。

失败、取消、网络断开、未知结果、进程退出和重启都不退次数。关闭再开启限额、更换模型或调整配置也不清空次数；限制关闭时仍记录尝试。调低限额不会撤回已发送的请求，接下来超额请求在本地停止。未发送的超额拒绝不再消耗一次额度。

**次数限制不是 token、金额或实际账单封顶。** 一次请求可能消耗很多 token；实时连接的时长及上游计费规则也不同。模型单价只用于估算，token 告警只提示，均不能替代供应商账单或账户额度设置。插件服务费用仍需单独核对。

## 展示与故障

- 「调用限额」展示 UTC 日期、当日尝试、当前限额、未结束的尝试及最近 50 个执行分组。
- 未结束的尝试可能仍在运行，也可能在最终回执前中断；保守计入限额，不宣称仍在后台执行。
- 模型调用记录会记录本地超额失败及原因。因此调用记录数量可能大于真正获准发往上游的尝试次数；它不等同于供应商收费次数。
- 达限时保留 Web、历史记录与管理入口，相关模型动作返回明确错误。语音不自动更换模型、转用其他服务或重发。直接本地限额错误不会触发模型降级或 worker 自动重试；外部记忆框架的内部故障重试仍须通过同一预扣入口。
- 连接停用或版本变化在预扣前重新检查；无法可靠保存计数时停止发送，不按不限额放行。
- 升级前没有预扣记录，不伪造回填；旧调用记录仍保留。

## 接口、数据与恢复

| 接口 | 用途 |
|---|---|
| `GET /api/admin/model-budgets` | 当前规则、当日次数及执行分组 |
| `POST /api/admin/model-budgets/previews` | 检查版本并生成加密预览令牌 |
| `PUT /api/admin/model-budgets` | 确认令牌和 `request_attempts_not_money` 说明 |

所有接口使用既有认证和写请求保护；账号和工作区来自服务端。预览令牌不包含模型密钥或聊天内容，不作为授权凭据向模型发送。配套契约见 [OpenAPI](../backend/openapi.json)。

迁移 `0052` 新增 `model_budgets`、`model_dispatches`，只保存策略与请求元数据，不保存提示词或密钥。工作区锁串行检查及预扣，预扣事务独立于请求最终回执，支持 PostgreSQL 和 SQLite。记录可关联模型调用日志，但不会因日志、会话或任务删除而退款。

备份与服务器迁移的安全检查点保留最新限额和尝试记录；恢复合并尝试编号，不通过恢复旧数据库减少已用次数。恢复提高策略版本、清除旧确认并撤销登录。要求匹配 schema、所有者和加密密钥；不要只恢复数据库后直接开放模型请求。空表可以直接降级；已有规则或次数后拒绝有损降级，须使用升级前备份及配套镜像。

## 验证边界

本批通过合成 HTTPX 协议、并发预扣、UTC 切日、执行归属、失败／取消、语音握手、权限、预览及恢复验证；实际结果以 [README](../README.md) 最新记录为准。独立测试环境不导入个人模型配置，不调用真实付费模型或 QQ。真实供应商计费、中文记忆质量和完整产品验收仍待验证。
