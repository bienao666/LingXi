# 自动选模使用说明（v1.66）

在「模型管理 → 路由策略」保存固定对话模型后，选择自动选模，添加已验证候选、核对接收地址并预览确认。默认仍为固定模型；旧的自动配置继续按候选顺序，不自动改动现有授权。

## 比较依据

| 策略 | 依据 | 证据不足时 |
| --- | --- | --- |
| 候选顺序 | 第一个满足要求的授权候选 | 没有合适候选则报错 |
| 参考费用 | 同币种、同连接版本人工价格乘参考 token 数 | 任一适合候选缺价、价格失效或币种不一致，整组保持候选顺序 |
| 历史耗时 | 近七天成功普通聊天的请求总耗时中位数 | 任一适合候选不足三个有效样本，整组保持候选顺序 |

参考输入和输出默认各 1000 token，币种默认 CNY，也可选 USD。价格在「数据日志 → 用量预算」维护。使用十进制计算，不换汇、不计缓存优惠；缺价不是免费。参考估算不是本轮输入预测、实际账单或金额上限，不保证真实费用最少。

耗时按同工作区、所有者、模型名称、连接 ID／版本和协议匹配，仅使用已完成回合中的成功普通聊天调用。每个候选最多读取最近 200 条范围内记录，取其中最近 20 个有效样本；耗时须大于零且不超过一小时。失败、取消、验证、任务协助、子助手、插件和语音不作为测速样本。旧记录缺少确切连接 ID 时不用于比较。不额外调用模型测速，不代表首字延迟、模型质量或同等输出长度的性能基准。

## 授权与执行

1. 先过滤授权端点、范围、连接状态、验证、上下文和图片能力，再比较；便宜或快不能扩大接收范围。
2. 预览按最低上下文展示当时快照。新回合按实际需求与最新证据选择，预览首选不是所有请求的保证。
3. 确认绑定策略、参考用量、币种和接收者。动态价格／历史不进入授权摘要，变化不需要重新批准相同接收者。
4. 回合创建时固定首选、备用、证据与原因；执行中不重排。连接、用途、代理或授权变化仍按原机制失效。
5. 同分以候选顺序决定。固定模式不比较。受控降级独立开启，备用仅在满足原请求且上下文不小于首选的授权候选内比较，最多一个。
6. 已有文字、取消、来源删除、撤权和本地次数超限不触发额外降级；工具步骤不重放，请求次数限额仍在发送前检查。

每轮 `ChatRun.config.routing.selection` 保存策略、实际比较方式、原因、时间和证据，`fallback_selection` 保存备用快照。调用记录只公开白名单策略标签和尝试数量，不展开任意历史或完整路由内容。

## 接口与回退

- `GET /api/model-routing`：新增 `selection_strategy`、`reference_currency`、`reference_input_tokens`、`reference_output_tokens`，旧记录使用默认值。
- `POST /api/model-routing/preview`：返回 `selection` 与五分钟确认摘要。
- `PUT /api/model-routing`：编辑策略、币种或用量使旧预览失效。
- `GET /api/chat-runs/{id}`：返回本轮冻结依据；调用分页继续返回脱敏元数据。

不新增表，schema 维持 `0052`。旧代码可能忽略新增策略而退回顺序选择；回退应先停写、备份，使用兼容的 Core／worker／Web 整套镜像并核对行为。备份恢复仍保留最新删除、授权撤销和请求次数记录。

合成协议验证不能代替真实提供商费用／时延验收，价格由用户维护；中文记忆和真实环境质量保持独立评测。

## 本批验证记录

独立 PostgreSQL 较广范围 341 项、最终相关回归 240 项及前端 389 项通过，类型／静态／构建通过。HTTP、真实 PostgreSQL 与 worker 联调使用合成上游，验证选中实际请求目标、幂等提交、证据冻结和限额计数；费用与耗时预览、币种不匹配、四个屏宽及键盘确认通过。本机部署核对 213 个服务文件、15 个 Web 制品及原业务／配置摘要，schema 保持 `0052`。上述两组后端回归有重叠，不相加为独立场景总数。
