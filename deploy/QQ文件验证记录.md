# QQ 长文文件验证记录（v1.38）

日期：2026-10-30，Asia/Shanghai。代码和本机容器已更新；以下协议测试使用独立数据库、合成提供商和合成 OneBot 对端，未登录真实 QQ、未发送真实消息、未调用付费模型。不据此声明真实 QQ 文件收发验收完成。

## 本批范围

默认关闭的长回答 Markdown 输出：超过 6000 字符时先发送说明，再上传完整正文；文件最大 512 KiB。只输出本条已完成回答，无任意路径、公共下载地址、原始附件回传或额外文件生成模型。群内文件遵守原群受众范围；主动交流仍不发送文件。

NapCat 固定 `v4.18.41`；核对其 `upload_private_file`、`upload_group_file` 及 `uriToLocalFile` 的 Base64 处理实现。文件上传成功返回 `file_id`，不是文字 `message_id`。源码核对仅是协议实现依据，实际上传权限和兼容性须再实测。

## 验证结果

| 检查 | 实测结果 |
|---|---|
| 文件专项 | Windows 32 项通过；覆盖默认关闭、阈值、完整字节、私聊／群聊、元数据脱敏、错误回执及越权访问 |
| 渠道回归 | 最终 Linux 镜像＋独立 PostgreSQL，269 项通过，185.38 秒；包含文件专项、原文字、附件、语音、主动投递和备份恢复 |
| 前端 | 227 项通过；确认预览、独立开关、文件与文字回执区分、状态和大小展示 |
| 类型／静态／构建 | 通过；10 个四字一级菜单、47 条路由、10 阶段动画；保留既有打包体积提示 |
| 真实传输链 | 实际 HTTP 管理 API → 认证反向 WebSocket → 持久化输入 → 独立 worker → 合成流式模型 → 文字回执 → Base64 文件上传；逐字节核对 UTF-8 正文及持久化发送意图 |
| 重启与重复 | 两次问答仅调用合成模型两次；第二次上传丢回执后关闭连接，重启 Core／worker，再投递相同输入，仍是两个 run、两次模型调用，未知上传不重放 |
| 来源失效 | 正文变化、名称或摘要篡改、来源消息删除、会话删除、工作区／目标变化、记忆删除、规则关闭和绑定撤销均阻止后续上传 |
| 历史与在途 | 仅说明被接受时，不把完整文件回答作为已投递历史；文件协议接受后才可纳入。发送后来源删除保留真实外部回执，回答仍失效，不误称能撤回 QQ 文件 |
| 备份与迁移 | 恢复更旧数据库仍携带去重／回执屏障，无文件正文或摘要。空库 `0033 → 0032 → 0033` 通过；存在文件投递时直接降级被拒绝且 schema 保持 `0033` |
| 浏览器 | 375／768／1024／1440px 及 1024×480 检查；无水平溢出，矮屏弹窗可滚动；Tab 留在弹窗，Escape 关闭并返回触发按钮；身份确认门禁和深链接保留 |

空文件 ID、仅返回文字消息 ID、非整数返回码、错误连接 echo 或非严格成功状态均不能记为文件接受。未知结果不盲目重发；迟到有效回执可消除上传不确定性，但不能抹去此前的输入解析失败。新增权限不因文件入口扩大。

入口仍为 `http://localhost:8080`。更新 Core／worker／Web 并迁移至 `0033`，数据库和 Hindsight 健康、worker 在线。95 个运行源码哈希、OpenAPI 与数据库字段核对一致；19 类业务数量及模型／加密凭据／人格／语音／路由／QQ 规则与绑定配置摘要保持一致，未导入测试配置。
