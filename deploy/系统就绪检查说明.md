# 系统就绪检查说明（v1.69）

## 入口与依据

进入「系统设置 → 系统概览」查看「能力就绪」。保留原有 Core、数据库、Hindsight、记忆、worker、队列与运行卷容量，新增统一的模型、平台、插件、语音与商店证据。页面不恢复顶部介绍区，沿用午夜蓝主题、四字菜单及身份确认开场。

`GET /api/admin/operations/readiness` 必须登录，由认证上下文确定工作区和所有者。接口只读本地数据库与运行卷容量，不测试模型、不调用远程插件、不探测真实 QQ、不发送通知，也不重试作业或更改授权。没有新增数据库表或迁移，仍为 `0054`。

| 页面状态 | 含义与边界 |
| --- | --- |
| 配置已验 | 默认模型用途的验证对应当前连接版本；语音使用现有配置签名验证。不代表上游当前在线、音质或延迟达标。 |
| 协议在线 | QQ 认证连接租约有效且协议端最近报告在线；不代表消息送达、已读或账号当前一定可服务。 |
| 记录有效 | 插件启用且当前版本清单完整性／访问检查通过，或商店签名目录缓存尚未到期；不代表全部依赖、授权、账号或远端调用可用。 |
| 尚未配置／已经停用 | 展示缺失配置或关闭状态；未启用的可选语音和商店不被当作故障。 |
| 需要核对／状态未知 | 连接变更未复验、租约过期、待人工登录、清单异常、目录过期／同步失败或状态尚待确认。 |

模型仅核对四个默认用途：对话、抽取、嵌入、重排；自动路由、人格覆盖及任务固定模型仍以各自策略与执行检查为准。插件不递归探测依赖、连接或能力，执行时仍须完整验证。安装已卸载的不列入当前清单。平台与插件分别仅展示最近 20 项，并显示总量和截断提示；异常数仅覆盖已列条目。

响应不包含服务地址、密钥、原始远端错误、对话、记忆或附件正文。平台和插件的名称／编号仅向其所有者返回，模型策略误指其他工作区时不泄漏关联名称或标识。

## 刷新与异常

页面每 15 秒更新运行状态及就绪证据；「刷新状态」同时刷新原健康接口。每份证据显示快照时间，QQ 和模型等另显示已有依据时间。刷新失败时保留上次快照并明确标为旧数据，不当成当前成功结果。页面离开后停止轮询。

异常提示覆盖 worker 超过 45 秒未续心跳、到期 pending 作业等待至少五分钟、运行卷容量偏低／不可读，以及已列配置中需要核对的条目。等待时间从 `max(created_at, available_at)` 算起；未来预约不计入，刚到期的老预约不误报长期积压。worker 空闲不等于离线。

提示只出现在管理页面，链接到原有配置入口；不会主动给用户发消息，不绕过联系偏好。它不替代外部监控、值班告警或具体执行日志。原有 Hindsight／记忆状态继续独立展示，本快照无提示不代表它们正常，也不代表全部功能验收通过。

## 使用与故障处理

1. 根据快照与依据时间判断新鲜度；网络失败时先刷新。
2. 通过「前往核对」「查看详情」进入模型策略、平台实例、已装插件、语音配置或插件商店。
3. 在相应页面核对实际配置和最近记录；模型连接变更后需由用户发起验证，QQ 登录失效需人工处理。
4. 存储异常先检查运行卷和备份；本页面不会删除文件。来源失效、外部副作用未知等仍遵守原有恢复规则。

## 验证范围

后端专项覆盖认证、只读与无外部探测、用途／工作区隔离、连接版本失效、QQ 租约与登录状态、20 项上限、插件清单篡改及卸载过滤、语音签名失效与异常格式、商店缓存与脱敏、worker 心跳、预约队列与磁盘错误。前端覆盖证据标签、范围限制、入口链接、GET-only 刷新和失败旧快照。

独立 PostgreSQL、HTTP→Nginx→Core 与浏览器验证使用合成账号、配置和协议租约，不使用正式模型密钥、不登录真实 QQ。实测结果在 README 中记录；不据此声称真实模型、Hindsight 中文质量、语音体验或 QQ 真实可用性已经验收。
