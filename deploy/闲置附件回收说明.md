# 闲置附件回收（v1.63）

本功能管理有数据库记录的普通 Web 上传副本。默认关闭自动回收；升级不会删除已有文件，也不会修改模型、代理或 QQ 配置。

## 使用

1. 在“数据日志 → 文件管理”或“系统设置 → 媒体配置”找到“闲置回收”。
2. 点击“调整回收”，选择自动开关和 1–365 天规则；默认 7 天。预览规则、核对影响并确认后保存。
3. 保存不立即删除。启用满一小时后，worker 的小时巡检才可开始回收；调度、维护或故障可能使执行延后。
4. “回收预览”展示当前最多 20 个确切文件及总大小；勾选确认才能手动回收。更多文件需重新预览，不扩大上一次批准范围。
5. 单个文件可“长期保留”或“解除保留”。保留只排除闲置回收，仍允许手动删除；解除后可进入后续候选。
6. “回收记录”显示最近 20 批的时间、自动／手动、标记数量、大小及跳过数量。规则更新／巡检时间包含最近保存规则的调度基点，不表示保存时已经扫描或删除。物理清理状态和失败重试继续在文件卡中查看。

“天数”按上传时间计算，不根据下载行为、最近访问或文件内容判断价值。已删除副本无法通过产品恢复。

## 候选与一致性

只有当前身份及工作区下 `ready`／`failed`、上传已满天数且来源为空的 Web 文件才能候选。以下文件保留：

- 长期保留、QQ 附件、服务器文档快照、接收中或解析中的文件。
- 有任何消息附件链接或 QQ 附件记录的文件，包括历史记录。
- 会话运行、协作及节点上下文、任务、记忆及候选、插件调用或在途作业相关字段中出现其 ID 的文件。

引用使用数据库关联存在性及白名单来源字段的保守匹配；即使只是提到同一 ID 也保留，可能多保留，不以模型判断授权删除。先排除引用再限制批次，避免被历史文件阻塞后续候选。

预览五分钟有效，绑定身份、工作区、登录会话、配置版本及确切文件版本。确认时与附件提交、保留设置及规则变更共用所有者锁，再查询引用和可回收状态。新引用、新保留或版本变化的文件跳过；规则或登录变化拒绝确认。重复提交有效预览复用同一回执。预览本身不删除，确认也不新增其他文件。

实际删除调用已有 `forget_media()`：先写独立删除记录、停止内容读取与引用使用，再排队物理清理。清理失败可重试；禁止在 API 中直接删除服务器原始资料。自动巡检与既有运维清理分别隔离异常，维护或迁移停写期间不执行。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/media-retention` | 当前规则及自动巡检状态 |
| POST | `/api/admin/media-retention/previews` | 规则变更预览 |
| PUT | `/api/admin/media-retention` | 确认变更 |
| PUT | `/api/media/{id}/protection` | 单文件保留，提交独立版本及媒体版本 |
| POST | `/api/admin/media-retention/sweep-previews` | 确切文件批次预览 |
| POST | `/api/admin/media-retention/sweeps` | 确认回收，返回标记／跳过回执 |
| GET | `/api/admin/media-retention/runs` | 最近 20 批回执 |

写接口沿用 Cookie、CSRF、所有者及工作区校验。规则及回收确认要求固定确认值 `delete_old_unreferenced_web_uploads` 和预览 token。完整字段以 OpenAPI 为准；不提供模型自主确认入口。

## 升级、恢复与边界

迁移 `0051` 新增三张表，不写默认授权，不改变旧业务记录。无记录时可回退；已有配置、保留或回执时拒绝直接降级，使用升级前数据库备份和配套镜像回退。数据库、附件及删除记录必须配套备份，不能只备份数据库。

恢复检查点包含最新回收规则与文件保留设置。恢复／服务器迁移后自动回收关闭、版本提高、登录撤销、旧预览失效；删除记录先重放，已删除文件不能复活。恢复程序要求匹配 schema，不将 `0050` 旧检查点当作 `0051` 的完整授权状态。

本批不扫描没有数据库记录的磁盘残留，不处理 QQ／服务器来源的自动过期，不判断“已用但不再需要”的文件，也不提供全量容量配额或回收站。大规模历史引用扫描的性能仍需真实规模验证。
