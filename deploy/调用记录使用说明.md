# 调用记录使用说明

适用版本 v1.56；迁移 `0049`。入口为“模型管理 → 调用记录”。

## 查询历史

默认查询全部时间，每页最多 50 条。可选最近一天、七天、三十天，按结果和用途组合筛选；指定模型可从提示目录选择，或粘贴记录中的模型标识。历史模型已移除、模型目录不可用时，记录仍可查询。

修改条件后点击“应用筛选”，结果从第一页开始；“清除筛选”恢复全部记录。“上一页”“下一页”查看历史，“最新记录”回到最新结果。没有总数时只展示当前页和本页条数，不估造总页数。

每条显示记录时间、实际模型、用途、状态、耗时、已知用量和已保存的费用估算；“固定版本”可查看模型连接、策略与提示词版本等允许公开的元数据。“计价依据”使用调用时保存的价格，不以当前价格重算旧账。用量或费用未知不代表零消耗或免费。调用完成也不代表输出质量已验收。

ASR／TTS 使用 `voice:asr`／`voice:tts` 作为记录标识。时间范围是从服务器查询截止时间回溯的连续 24 小时／七天／三十天，时间显示按当前浏览器时区格式化。

## 分页与权限

新增 `GET /api/admin/model-call-pages`，参数为 `cursor`、`limit`（1–200，Web 固定默认 50）、`days`（`0`／`1`／`7`／`30`）、`status`、`purpose`、`model_id`；返回 `items`、`next_cursor` 和 `as_of`。

服务端按认证工作区过滤，以记录时间和 ID 共同排序。游标绑定用户、工作区、筛选条件、截止时间和上一条位置，24 小时到期；篡改、换筛选或跨身份复用会拒绝。正常翻页不追加入站的新记录，查看最新需重新查询；这不是整个数据库的事务快照。来源记录被移除时仍可从原位置继续向前查询。

原 `/api/admin/model-calls` 保留数组响应和最近 200 条上限，采用相同的公开元数据序列化；完整历史须使用分页接口。接口不返回完整配置、提示词正文、上游附带的任意字段或明文密钥。不提供模型调用删除、批量日志导出或调用重放按钮。

## 更新与故障

`0049` 仅增加 `(workspace_id, created_at, id)` 索引，不改写调用、价格、模型配置或记忆。服务器交接仍要求同版镜像；仅相同数据库 schema 不代表版本兼容。

网络失败可“重试加载”，保留当前查询位置；游标过期请“返回最新”。模型目录加载失败不会阻止历史查询。空结果明确显示，失败不伪装成空记录；浏览器断线不会重放模型调用。

实际测试、截图及本机部署状态见[调用记录验证记录](./调用记录验证记录.md)。
