# 长期记忆管理（v1.60）

入口为“长期记忆”，包含“记忆列表、候选记忆、导出记录、删除进度”四页。沿用现有午夜蓝主题及四字菜单。

## 查询与翻页

- 每页最多展示 50 条，支持上一页、下一页和返回最新；刷新状态会回到第一页。
- 记忆列表支持正文关键词和七类记忆筛选。候选记忆支持全部、等待核对、已经保存、已经拒绝。
- 导出记录和删除进度分别查询对应操作，不会因另一类操作数量较多而隐藏旧记录。
- 新增记录在刷新后进入第一页；旧页固定查询截止时间，但内容、删除和失效状态按当前数据库重新检查。
- 筛选或切换页面立即停止显示旧范围的数据。加载失败可重试；分页凭据过期时使用“返回最新”。

页面只读取当前栏目，不再同时轮询全部记忆、候选和操作。页面可见时每 5 秒刷新当前页，请求尚未结束时不会再次发起轮询；后台刷新不会清空同一页已有卡片。翻页和更换筛选使用新的范围，迟到响应不能覆盖当前页。

## 保存、纠正与删除

已有的手动新增、候选确认、自动保存低风险自述、来源核对、版本纠正、索引重试、导出及删除行为继续使用原接口。候选筛选不会自动确认或拒绝记录；导出记录分页不会生成新导出。

删除仍先禁止检索并失效关联内容，再由 worker 清理索引。旧分页凭据不是记录副本，不会重新显示已删除的记忆。操作与来源存在版本冲突时，刷新后重新核对。

## 召回规则

Hindsight 提供候选文档及相关性顺序；MemoryService 按该顺序去重，在业务数据库中核对真实用户、工作区、有效状态、到期时间、索引代次和事实版本，最多使用 12 条。索引返回的正文不能代替权威记忆。不存在、他人、旧版本或删除记录不会占据最终结果位置。

只读取索引实际提及的记忆 ID，按每批最多 400 个 ID 查询，不再加载用户全部记忆后进行筛选。无法识别的索引响应按记忆服务不可用处理，普通聊天继续且明确标记召回状态。

## 接口与兼容

| 新接口 | 参数 |
|---|---|
| `/api/memory-pages` | `q`、`category`、`cursor`、`limit` |
| `/api/memory-candidate-pages` | `status`、`cursor`、`limit` |
| `/api/memory-operation-pages` | 必填 `kind=export` 或 `kind=delete`、`cursor`、`limit` |

统一响应包含 `items`、`next_cursor` 和 `as_of`。每页默认 50 条，允许 1–100 条；分页凭据加密并绑定当前用户、工作区、栏目、筛选和有效期。旧数组接口保留兼容，不新增数据库迁移。接口以 FastAPI OpenAPI 和生成的前端类型为准。

这次改动改善记录可达性及召回顺序，不证明真实供应商或 150 题中文记忆质量已达到验收门槛。
