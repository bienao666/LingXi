# 话题收尾（v1.73）

## 使用方式

在「主动交流 → 待续话题」对等待或已建立联系的话题点击「结束话题」，核对后确认。在「联系记录」也可结束对应话题；历史展示「话题已结」，仍可主动接续对话。页面沿用原菜单、主题和无介绍区布局。

正常收尾保留原始记忆和交流记录，不把关联任务标记为完成，不改变其他话题或全局联系偏好。「关闭话题」仍用于屏蔽来源，可在联系偏好中管理；正常收尾单独记录，不占用屏蔽来源列表。

Web 文字或用户核对后手动确认的语音文字支持以下完整控制语句，末尾可带句号等终止标点：

- `这个话题结束了`
- `这件事已经结束了`
- `这件事已完成`

只有当前会话恰有一个已建立联系的话题时才执行；没有或多个时请到列表选择，不猜测指代。不把「演示顺利完成了」、引用、朋友转述或假设自动视为结束指令。QQ 输入和自动连续转写不执行此控制。这是明确控制功能，尚未实现通用的事件结果语义识别；处理控制语句本身不调用模型。

## 后续安排与正在投递

记忆／计划来源结束后，其后续版本不再自动生成话题。有新情况时，可明确选择有效的新版本重新安排；同一来源版本不重复建题。插件来源使用订阅 ID 加事件版本隔离，只结束本次事件，后续独立事件仍按原授权和联系偏好判断，不停止整个订阅。

结束时取消尚未发送的 QQ／语音候选，使模型构思失效，并阻止继续领取浏览器通知。已开始的外部发送无法撤回，未知结果仍需核对；迟到的真实协议回执会如实保留。正在播放的语音停止，不把未播完内容算作已听闻。历史记录不因此宣称用户已读。

## 接口与恢复

| 接口／字段 | 用途 |
|---|---|
| `POST /api/conversation-topics/{identity}/resolve` | 提交严格整数 `version`，认证、CSRF、工作区、所有者与版本检查 |
| `POST /api/proactive-contacts/{identity}/feedback` | `feedback: resolved` 结束对应话题，沿用联系版本检查 |
| 话题 `status: resolved`、联系 `topic_status` | 查询、筛选及历史展示 |

迁移 `0058` 新增 `topic_completions`，仅保存来源标识、版本和完成时间等最小元数据，不复制话题正文。备份恢复检查记录归属及格式，并将最新收尾屏障覆盖旧待发话题；原有隐私隔离仍可将历史标为来源失效。来源纠正、删除和撤权继续有效，不因收尾恢复失效正文。有收尾记录时禁止直接降级删表，使用配套备份与镜像整体回退。
