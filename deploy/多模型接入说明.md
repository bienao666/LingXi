# 多模型接入说明

当前提供三种明确选择的协议，不根据域名猜测，不自动补 API 版本，默认不切换供应商；普通聊天可显式开启限定候选路由，见 [模型路由说明](./模型路由说明.md)。真实账号授权、型号支持和中文质量仍需实际验证。

| 协议 | 根地址示例 | 已接入用途 | 未接入用途 |
|---|---|---|---|
| OpenAI 兼容 | 按服务实际地址填写，例如 `https://example.com/v1` | 原有对话、视觉、抽取、嵌入、重排及语音适配 | 兼容服务的实际能力仍须逐项验证 |
| Anthropic 原生 | `https://api.anthropic.com/v1` | Messages 文字、图片、流式对话、记忆抽取与严格 JSON Schema | 原生工具消息、嵌入、重排、语音、Bedrock／Vertex |
| Gemini 原生 | `https://generativelanguage.googleapis.com/v1beta` | generateContent／SSE 文字图片、抽取、严格 JSON Schema、批量文字嵌入 | 原生工具消息、Live、语音、重排、Vertex AI |

## 配置步骤

1. 在“模型管理 → 服务连接”新增连接，选择正确协议，填写完整 API 根地址及该服务的密钥。管理员可明确允许服务器内网地址；仍执行系统代理、地址与 DNS 校验。
2. “模型目录 → 添加模型”自动加载所选连接目录。原生目录遍历全部分页，异常、循环或预算超限会报错，不能把部分目录当成完整列表。没有刷新列表和手工模型标识入口。
3. 选择用途与目录中的型号。Gemini 会按供应商声明筛选生成与嵌入型号，目录声明不等于通过验证。上下文窗口按供应商资料填写。
4. 点击“验证能力”；对话验证真实流式协议，抽取验证中文原文证据，嵌入验证部署维度与有限非零向量。图片另外执行视觉验证。
5. 在“路由策略”选择已验证的固定用途模型。原生 Anthropic 需搭配其他连接提供嵌入、重排；Gemini 仍需单独配置重排。语音目前只接受已接入的 OpenAI 兼容连接。

修改连接会递增配置版本并使旧验证失效；切换协议必须填写新密钥，不复用原协议密钥。已有嵌入索引时不能直接改其连接地址或协议，更换嵌入模型仍须停写并重建索引。编辑冲突需重新加载。执行中的聊天检测连接停用或版本变化后停止继续消费输出。

## 传输与记忆

三种协议共用服务端加密凭据库、系统代理、内网授权、无重定向和无自动重试机制。Anthropic 使用 `x-api-key` 与固定 `anthropic-version: 2023-06-01`，Gemini 使用 `x-goog-api-key`；密钥不放查询参数，不返回浏览器。图片只使用核心已授权的内嵌附件，不在协议适配器任意下载 URL。

私有 Hindsight 网关继续提供 OpenAI 形状的服务端接口，固定为管理员所选实际模型，再翻译到原生协议；不把用户密钥交给 Hindsight。支持当前 retain／recall 路径所需的 JSON 对象、严格 Schema、输出 token 参数以及 float／Base64 嵌入。Gemini 嵌入禁止静默截断，按固定维度检查数量、顺序及数值；仅记录上游实际用量，缺失时保持未知。

不支持的工具、角色、请求选项或输出内容明确拒绝，不静默丢弃。Hindsight reflect 工具代理不属于当前接口范围，不能据此宣称所有框架能力已覆盖。原生私有思考块不作为答案输出；截断、拦截、未知工具、未完成 SSE、空回复均不能标成成功。本节原生适配层不自行降级或重放外部动作；普通聊天可通过核心显式授权路由进行有限跨连接降级。

## 升级与验证边界

迁移 `0016` 添加独立协议选择记录；没有记录的旧连接视为 OpenAI 兼容，不改写旧凭据。存在原生连接时禁止降回 `0015`，必须先显式迁移连接，避免旧 Core 把密钥发往错误协议。

已验证协议夹具、真实 TCP、独立 PostgreSQL 和真实 Hindsight 容器的目录、用途验证、图片、持久化对话、索引及跨会话权威召回；这证明适配链路，不证明真实供应商模型质量。真实 Anthropic／Gemini 账号、费用、限额和 150 题中文评测仍待验证；没有自动修改现有真实连接、密钥或用途策略。
