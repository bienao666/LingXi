# 资源授权使用说明

> 本文保留 v1.51 清单基线；v1.55 新增独立正文授权，操作与新迁移请以[文档读取使用说明](./文档读取使用说明.md)为准。旧清单授权不包含正文。

适用版本：v1.51，数据库迁移 `0045`。本功能管理服务器资料卷的**只读目录元数据**访问，尚不读取文件正文、写文件或执行程序。

## 配置资料卷

默认 Compose 为 Core 与 worker 挂载同一个只读 `server-resources` 卷，初始为空。已有服务器目录可以通过单独的 Compose override 提供：

```yaml
services:
  core:
    volumes:
      - /srv/lingxi-resources:/app/resources:ro
  worker:
    volumes:
      - /srv/lingxi-resources:/app/resources:ro
```

部署管理员须先准备目录并允许容器 UID 10001 遍历、读取目录。Core 与所有 worker 使用相同挂载和路径；不能挂载服务器根目录、账号凭据或数据库目录。浏览器不能配置任意宿主路径，也不能读用户电脑文件。

应用 override 后，在“系统设置 → 资源授权”查看资料卷状态。**挂载不等于授权**；升级后不自动开放旧挂载，须明确确认允许范围。

## 允许目录

在“相对目录”中每行填写一个目录，例如 `projects`、`shared/research`，最多 20 个。路径相对资料卷，不是服务器绝对路径。授权目录包含后代，但不包含父目录或同名前缀：`projects` 不允许列出 `.` 或 `projects-old`。

`.` 代表整个资料卷，预览中会明确标注。不能同时填写父目录与子目录；拒绝绝对路径、电脑盘符、`..`、控制字符、重复目录及符号链接。目录须在预览和确认时均存在且可安全打开；空目录可授权，不枚举内容来模拟“验证”。

点击“预览更改”，核对原范围、新范围和影响说明，再点击“确认授权”。预览五分钟有效，绑定账号、工作区、当前登录和版本；过期、登录改变、并发修改或重复确认须重新预览。

## 提交任务

“任务中心 → 任务列表”创建“资料清单”，填写授权范围内的相对目录。聊天的任务协助、助手协作和插件角色使用相同服务端检查；模型、角色说明和插件清单不能授予新权限。

实际权限为服务器挂载、工作区资源范围、第一方插件 `resources.list`、角色工具和本次任务允许范围的交集。清单返回当前目录最多 200 项元数据，跳过符号链接，不递归列出全部文件。结果只证明观察时刻的目录情况，不代表文件正文已读或文件始终不变。

QQ 后台协作还须在 Web 逐请求预览、确认明确共享子目录；不能共享 `.`。该共享范围必须位于当前资源授权内。QQ 的子助手看到相对共享子目录的结果，不会因绑定身份继承所有者其他目录。

## 更改或撤销

可将输入留空再预览，或点击“撤销全部”。资料卷离线时仍能撤销全部；新增或调整非空范围需要卷可用。

本版采用保守的版本策略：**任何范围变化，包括只新增目录，都使所有使用旧资源版本的任务与协作失效**。新任务使用新版本，旧任务不能因重新授权、重试或重启恢复执行。与服务器目录无关的任务不受影响。

确认后停止新目录访问与后续结果提交，取消旧资源任务，清除其结果及协作上下文，并使关联待确认记忆、后续回答、待投递 QQ 结果失效。已经发往模型或 QQ 的内容无法撤回。相关任务的状态、原因和操作审计仍保留；原始文件不变。

用户已经核对保存的长期记忆仍保留，但若它依赖失效资源版本，就不再用于召回、索引写入或新回答。单独重新授权不会复活该来源；用户核对后可通过“纠正记忆”建立新的独立自述来源。不要把资源撤权理解为物理删除第三方已收到的内容。

## 升级与恢复

`0045` 新增 `resource_policies`，默认没有授权。Core 启动时使旧的无资源快照任务及相关协作失效，不能继续复用旧目录结果。正式环境升级前先备份数据库和配套镜像；已有授权记录时拒绝有损降级。

备份恢复沿用当前安全检查，资源授权始终清空，版本高于恢复前及备份中的版本。确认服务器挂载后重新授权、新建任务；旧任务和旧 QQ 投递不重放。基础配置 JSON 导入、版本回退不会携带或恢复资源授权。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/resource-policy` | 当前版本、相对目录、挂载与可用状态 |
| `POST /api/admin/resource-policy/previews` | 校验目录，生成有期限的授权预览 |
| `PUT /api/admin/resource-policy` | 使用预览令牌和明确确认提交新版本 |

接口使用现有管理员登录 Cookie、CSRF 和工作区身份。无单独公开目录 API，也不返回宿主绝对路径。
