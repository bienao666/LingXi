# 记忆配置简化说明（v1.86／schema0061）

本批交付配置与索引生命周期代码。真实内置 CPU 推理和隔离跨会话协议联调已经验证；实际提供商抽取、150 题中文语义质量及完整产品验收仍待验证。

## 使用方法

进入「模型管理 → 路由策略」。新安装默认简单模式；升级前存在任一独立 extraction、embedding 或 rerank 策略的实例保留高级模式，不覆盖旧策略。

| 用途 | 简单模式 | 高级模式 |
|---|---|---|
| 对话 | 上方保存并验证的固定对话模型 | 相同 |
| 抽取 | 继承固定对话服务，另点「验证抽取」 | 单独登记、验证与选用 |
| 嵌入 | 服务器内置 BAAI/bge-m3，1024 维 | 外部已验证的 1024 维模型 |
| 重排 | 服务器内置 BAAI/bge-reranker-v2-m3 | 外部已验证的重排模型 |

简单模式无需再添加三条记忆模型记录。先配置固定对话模型，再点击「验证抽取」；这会发出一次测试请求，可能产生提供商费用。打开页面、健康检查和刷新状态不触发收费验证。抽取验证失败只影响记忆抽取，正常文字聊天仍可用。更换对话策略或连接版本后需要重新验证；自动选模、备用模型及人格指定模型不会改变抽取接收者。

界面分别显示继承关系及内置模型的等待下载、下载、加载、就绪、失败或不可达状态。失败时检查资源与代理，再点击「准备模型」。只显示「已配置」不能证明已成功推理或中文质量达标。后台抽取沿用已有来源校验、候选确认及敏感内容处理规则，不把模型回答当作用户事实。

模式与高级模型选择先「预览配置」，再「确认配置」。预览五分钟有效，绑定登录身份、工作区、配置版本、模型与连接及代理版本；变化后重新预览。切回简单模式保留旧高级策略。相同设置重复保存不重建；更换抽取或重排模型也不重建向量。

## 内置服务与资源

`memory-inference` 是独立 Python 3.13.15 CPU 容器。仅 Compose 内网访问，复用内部服务认证，不发布宿主端口。依赖锁在 `inference/requirements.lock`，模型修订与分块算法锁在 `backend/lingxi/builtin_models.py`；禁止远程模型代码。Hindsight 仍通过 Core 内部模型网关访问，权威事实仍在业务 PostgreSQL。

| 模型 | 固定修订 |
|---|---|
| BAAI/bge-m3 | `5617a9f61b028005a4858fdac845db406aefb181` |
| BAAI/bge-reranker-v2-m3 | `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e` |

嵌入使用 CLS、归一化及 1022-token 分块加权平均；重排使用 512-token 文档分块的最高 sigmoid 分数，查询最多 512 token。该实现不是上游模型的所有长文本运行方式。每段最多 20000 字符／16384 token，每批最多 100 段、合计 100000 字符，超过预算明确拒绝，不静默截断。向量只支持 1024 维 float/base64，不补齐或截短。

默认单并发、2 CPU、推理容器内存上限 8 GiB。此次 Linux x86_64／WSL 实测：

| 检查 | 结果 |
|---|---|
| 三条短中文嵌入 | 691 ms，1024 维、归一化与语义顺序正确 |
| 三文档中文重排 | 1191 ms，相关文档排首位 |
| 1407-token 长输入嵌入 | 5454 ms，确实进入多块处理 |
| 推理进程峰值 RSS | 3326.1 MiB，约 3.25 GiB |

这是固定小样本实测，不是 P95、完整检索延迟或中文质量评分。建议整机至少 16 GiB 内存、为数据库／Hindsight／Core 留出额外余量，空闲磁盘至少 15 GiB，模型缓存约 4.5 GB，首次构建还需要镜像和依赖空间。CPU、输入长度及其他任务会改变延迟，部署需重新测量。资源不足、超时或推理繁忙明确不可用，不静默转云；正常文字聊天保留。隔离副本在 192 MiB 限制下实测 OOMKilled／137；独立停止推理服务后确认页面报告不可用，合成模型的文字聊天仍完成。若进程被 OOM 杀死，检查 Docker 的 OOM 状态后增加资源并重启。

完整模型缓存位于 `lingxi_builtin-model-cache` 持久卷。下载遵循「系统配置」中保存的代理及 no_proxy；内部 Core 通信保持直连，不回退到未授权公网服务。已完整下载的固定修订优先离线加载，此行为已在不可用代理下重启验证。保留卷，不对现有部署运行 `down -v`。更换主机时可重新下载或安全复制缓存；缓存是可重建资产，不代替业务数据库与删除记录备份。

```bash
sudo docker compose build memory-inference core worker migrate web
sudo docker compose run --rm migrate
sudo docker compose up -d --no-build
sudo docker compose logs --tail 60 memory-inference
```

已有部署先按下节备份；不要重跑 configure 覆盖 `.env`。构建依赖下载使用 Docker 构建环境的代理，运行时模型下载才读取系统代理；不要把代理或密钥写入仓库。服务存活只表示 HTTP 进程运行，实际模型就绪以「路由策略」或认证健康页为准。

## 重建、失败与恢复

嵌入模型指纹包含固定修订、实现和维度。模型变更经确认后进入：`draining → rebuilding → ready`。等待旧调用时不接收新索引／检索，取得非阻塞数据库屏障后建立独立 bank 与新代际；旧请求迟到、旧作业重试和旧指纹不能混入。目标连接在等待期间改变时阻断切换，需要「取消重建」再重新预览。

重建期间正常文字聊天、记忆查看、纠正和删除继续可用；新事实和新版本进入新代队列，删除即时阻止检索。全部当前有效记录就绪后恢复检索，失败显示真实待处理与失败数，修复后「重试重建」。worker/Core 重启从持久状态继续，不退回旧代际。新代际建立后不能取消回旧代。

如果旧 Hindsight 请求超时或进程中断，不能证明服务端已停止，进入 `blocked`。先由管理员执行：

```bash
sudo docker compose restart hindsight
```

然后勾选已重启声明并「重试重建」。该声明只解决旧请求状态，不绕过服务或目标配置错误。尚未切换可取消本次操作；取消后若仍有未知旧请求，下一次切换依然会被阻止。已停用／删除／过期的事实不会因重试复活。

升级前备份业务与 Hindsight 数据库、最新删除记录、`.env` 和配套镜像。0061 迁移回填模式、代际及指纹，不修改已有模型、代理、密码或 QQ。非空配置不支持直接降级；需要升级前完整备份和配套镜像整体回退，并重放最新删除／撤销记录。正常备份恢复会保留最新模式、清空抽取验证与待切换状态，创建新代际，避免复用旧备份向量。外部连接仍须按恢复隔离流程重新授权。

## 接口与记录

所有 `/api` 写入复用认证、CSRF、工作区及版本检查；不信任浏览器自报主体。

| 接口 | 用途 |
|---|---|
| `GET /api/memory-settings` | 有效模式、继承、模型实际状态、代际与验证错误 |
| `POST /api/memory-settings/preview` | 变更影响及五分钟确认摘要 |
| `PUT /api/memory-settings` | 确认模式／高级策略变更 |
| `POST /api/memory-settings/verify-extraction` | 用户明确发起的继承抽取验证 |
| `POST /api/memory-settings/prepare` | 准备或重试内置模型 |
| `GET /api/memory-rebuilds` | 最近操作和当前有效记录进度 |
| `POST /api/memory-rebuilds` | `version`＋`confirmation: rebuild_current_index` 强制重建当前索引 |
| `POST /api/memory-rebuilds/{id}/retry` | 失败项重试，未知旧请求另需重启声明 |
| `POST /api/memory-rebuilds/{id}/cancel` | 仅取消尚未切换的操作 |

内部推理配置、模型接口不对浏览器公开。调用记录包含实际用途、继承／内置／独立来源、实际模型与指纹、策略和配置版本及服务器／提供商位置。token 用量仅记录实际返回值；无价格显示未知，不把本地 CPU 成本伪装成免费云调用。

## 验证边界

隔离环境使用真实 PostgreSQL、Hindsight 1.1.0-slim、内置两模型及本地合成文本协议服务，验证跨会话召回、纠正版本、重建跨重启恢复、未清理旧索引时删除立即生效、断线与故障隔离。合成文本服务不能证明真实 LLM 抽取能力。正式提供商未自动发起收费验证；用户完成「验证抽取」后，仍须在专门环境执行并人工复核 150 题，不能据此标记完整记忆产品已交付。
