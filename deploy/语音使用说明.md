# 浏览器语音使用说明

当前交付为 ASR → 灵犀核心聊天 → TTS 链式基线，保留手动核对并增加默认关闭的连续对话。QQ 异步语音输入已另行接入，须在渠道规则明确开启，见[QQ 接入说明](./QQ接入说明.md#语音接收v134)；QQ 短回复语音输出已另行接入，见[QQ 接入说明](./QQ接入说明.md#语音回复v135)；浏览器本地停顿分段及连续对话见 v1.37，手动模式原生实时字幕输入见[实时转写说明](./实时转写使用说明.md)，原生双向语音仍待开发。

## 配置服务

1. 在“模型管理 → 服务连接”添加 OpenAI 兼容连接。地址按供应商提供的根地址保存，系统不会额外添加 `/v1`。请求沿用系统代理和内网连接授权。
2. 在“系统设置 → 语音配置”选择转写和合成各自的连接、供应商模型，填写服务支持的音色和语速，保存。
3. 点击“录音验证”，说一句话，再点击“结束转写”。核对显示的结果；空响应或协议错误不能通过验证。
4. 点击“合成示例”，用播放器试听。示例为 AI 合成；请求可能产生服务费用。

转写协议为 `POST audio/transcriptions`：multipart `file`（PCM WAV）、`model`、`language` 和 `response_format=json`；要求 JSON `text` 字段。合成协议为 `POST audio/speech`：`model`、`input`、`voice`、`speed` 和 `response_format=wav`；当前只接受完整的 16 位 PCM WAV。兼容聊天接口不代表支持这两种音频接口。供应商模型目录必须包含需要选择的模型。

转写探测不声称识别正确，合成探测不声称声音质量合格。更换连接版本、音频模型、音色、语言或语速后，相关验证会失效；保存配置后需要重新检查。

## 使用语音

打开一个对话，点击“开启语音”，再点击“开始录音”；开启语音不会直接申请麦克风。录音后点“结束录音”，核对／修改文字，再“确认发送”。没有发送的临时转写可直接丢弃，不创建消息或记忆候选。

确认后调用统一持久化聊天；模型、人格和记忆配置仍与文字聊天相同。完整回复生成后逐句合成，当前未优化为边生成边合成。浏览器阻止自动播放时，点击“继续播报”；失败时保留文字。

- “停止播报”立即停播放器，保留文字回复与服务器任务。
- “打断录音”先停止播报，再明确开始下一段录音。不会持续监听抢话。
- “停止生成”属于原有聊天取消操作，和停止播报分别处理。
- “结束语音”释放录音和播放器，服务器已提交任务可继续运行，后续不会自动播报。

下一轮语音只带入前次已完整播完的短句，半句保守忽略。浏览器报播放结束并不证明用户真的听见。文字历史仍保留完整回复；文字新回合可以读取屏幕中的全文。消息或记忆来源失效时停止使用相应回复，已播放和已发给上游的数据无法撤回。

## 连续对话（v1.37）

1. 在对话窗口勾选“连续对话”，再点击“开启语音”。该选择只用于本次会话，默认关闭；会话开启后不能直接换模式，需先结束。
2. 阅读自动发送说明，再点击“开始聆听”并按浏览器提示允许麦克风。开启会话本身不申请权限。建议佩戴耳机；本地音量分段不能保证区分语音、环境声音和扬声器回声，不作身份或情绪推断。
3. 说话后停顿约 1.2 秒，浏览器生成临时 PCM WAV，调用配置的 ASR 并自动发送。持续静音不调用转写服务。等待识别、提交或聊天生成时暂停分段并清空缓存；回复完整生成后逐句合成，播报时可检测起声并打断，播报完成继续聆听。
4. 点击“暂停聆听”关闭麦克风；已提交的回复继续。点击“停止播报”停止声音并关闭聆听；均不取消后台任务。“继续播报”只恢复同一段声音，不自动恢复麦克风。“结束语音”关闭本次会话；文字内容保留。
5. 网络、转写、生成、合成、播放或音频组件错误后暂停，检查状态后手动恢复。发送结果未知时“重试发送”沿用原请求 ID 和未确认标记，原文不允许修改；不会再次识别或自动重新请求。丢弃草稿不代表取消已接收的回复。

自动转写在聊天显示“转写未核”，只用于对话，不执行工具、修改联系偏好或自动保存长期记忆。服务端不给它生成记忆抽取 outbox，抽取 worker 也再次拒绝这类来源；标记加入幂等摘要，不能复用请求 ID 改成已确认输入。需要记忆时可退出连续模式，用手动模式核对后发送，或在记忆页明确新增。文字输入框的“任务协助／助手协作”勾选不影响语音请求。

本地检测：约 300ms 前滚，听取时约 180ms 起声，播报时更严格、约 250ms，累计有效声音至少约 450ms；静音约 1.2 秒结束一段。单段超过 25 秒整段丢弃并暂停，请分段表达；静候 60 秒关麦，识别／聊天生成阶段暂停等待计时，播报阶段仍计空闲。会话仍限 15 分钟、不设固定聊天次数（回合计数只作记录，重投同一已接受请求不重复计数）。到期后需结束并明确重开。所有者共享每分钟 30 次付费语音请求限制，分句播报也消耗额度。

播报起声先在本地停止，服务器只记录已经完整播完且确认的片段，不估算未播完的字数；下轮不会把未听完的整句当作已经听到。精确识别为“暂停聆听”时只暂停本地聆听；“先别聊”还会关闭本次会话的主动开口；“结束语音”结束会话，不更改长期联系偏好。嘈杂环境下识别可能错误，屏幕按钮始终可用。

原始波形仅驻浏览器／请求临时内存；自动发送后的转写作为消息保存，不等于已确认用户事实。页面隐藏、离线、切换对话、退出、到期、配置变化或浏览器音频失效停止捕获，不后台续听、不自动重开。恢复备份关闭旧语音会话并撤销旧登录，不恢复麦克风。

接口沿用原族：会话输入／输出新增 `mode: manual|continuous`，返回 `automatic_turns`；语音消息输入新增 `automatic`（默认 false）。后端迁移 `0032` 给既有记录补为 manual／0，不修改真实模型、语音配置或权限。已有连续会话记录时禁止直接降级；回退须使用配套升级前数据库备份及 Core／worker／Web 镜像，不手工丢掉确认标记或回合记录。证据见[连续语音验证记录](./连续语音验证记录.md)。

## 主动开口（v1.49）

1. 在对话窗口明确勾选“主动开口”，再开启语音；已开启的会话也可随时切换。默认关闭，只对当前会话有效，不开启麦克风、不授予 QQ 或其他浏览器播音许可。
2. 在“主动交流 → 联系偏好”允许相应话题和 Web 目标。关闭主动交流、仅收结果、安静时段、暂停和拒绝来源继续生效；语音会话内不使用会话外每日次数和间隔，但仅沉默不产生新话题。
3. 来源话题到时后，核心为当前授权会话保存新候选，最多等待 120 秒，浏览器至少空闲三秒才领取。输入、说话、录音、转写、生成或已有声音时让路；旧联系、过期与已经领取的候选不再次播放。关闭开关后再开启不恢复旧候选。
4. 用户起声先本地停播，迟到的领取、合成及输出设备切换结果不能重新开声。连续模式识别“先别聊”会同时暂停聆听与关闭本次开关，长期联系偏好仍需在设置或明确文字指令中修改。
5. 拒绝、删除、纠正、权限或配置变化后停止后续片段；浏览器每秒检查主动播放状态，每段合成前后及手动继续前重新验证。已播放的声音与上游已接收的数据不能撤回，服务器不可达时结束语音，保留文字入口。
6. “主动交流 → 联系记录”区分等待、过期、播报与停止，并显示完整播完且收到回执的段数；不能据此声称用户实际听见。只确认的完整短句进入后续语音上下文，Web 完整文字不受影响。

首版使用同一条有来源主动联系的文字进行 TTS，不包含无来源自由闲聊或原生实时语音。TTS 与人格音色需事先验证，共用每分钟音频预算。静音／自动播放受限时暂停，手动继续不重新合成；重新核验失败不播放缓存声音。真实供应商、物理设备和自然程度仍待验证。迁移、证据与回退见[主动语音验证记录](./主动语音验证记录.md)。

## 人格音色（v1.25）

1. 在“助手管理 → 人格管理”编辑默认音色，例如 `nova`，留空沿用系统默认。标识须为 1–80 位英文字母、数字、下划线或连字符；按当前供应商支持情况填写。
2. 在“语音配置”选择“跟随人格默认音色”并保存。此开关默认关闭；既有配置不会自动开启。保存或修改语音配置会使已有语音会话结束，需重新开启。
3. 在“人格音色”选择人格并点击“验证音色”，可能计费。播放器只在主动点击后试听；这不会打开麦克风。仍须验证系统默认 ASR／TTS 后才能开启语音。
4. 回到对话显式选择人格，再开启语音。回复播报显示本轮音色及人格版本。修改人格用于新回合，已提交回合继续使用固定音色。

验证绑定 TTS 服务连接版本、模型、语速和音色；相同音色可共享验证，不要求每次编辑表达风格都重复请求。最多保留 100 项自定义音色验证；旧项被挤出需再验证。未验证／失效时明确提示且保留文字，不擅自用其他音色或提供商代替。人格未填音色使用系统默认；如果所选人格已停用，旧回合后续片段也停止合成。模型重试／重复发送不改变原回合的音色与已确认播放进度。

新增接口：`GET /api/voice/personas`、`POST /api/voice/personas/{id}/test`（请求体 `version`）。配置增加 `follow_persona`；回合配置增加 `speech`，播放计划与回执包含音色、来源、人格名称和版本。只复用既有 JSON 列，不需新数据库迁移，schema 保持 `0020`。旧 Core 会忽略新音色约束，使用本功能后不要仅切回旧 Core／worker；需要回退时按升级前配套备份和镜像操作。

2026-10-29 人格音色批次：Linux＋独立 PostgreSQL 完整后端 668 项、Windows 语音相关 62 项、前端 144 项通过；类型、菜单／开场静态检查与构建通过。隔离 HTTP 和浏览器验证手动音色探测、固定旧回合、新回合使用新版、重启保留及无自动播音；四档布局无横向溢出，矮屏可滚动与键盘提交通过。全部音源与模型为合成协议服务；真实音色质量、物理设备及延迟仍待验证。

## 环境与限制

麦克风须在 HTTPS 或 `localhost` 安全上下文使用，并获用户授权。输入设备可在浏览器可枚举后选择，输出切换依赖 `setSinkId` 支持；不支持时使用系统默认。识别语言仍使用语音配置；音色默认使用系统设置，可按下节显式开启人格联动。

录音在 AudioWorklet 中采集并转换为 16 kHz／单声道／16 位 PCM WAV，最长 58 秒；Core 限 60 秒、6 MiB、0.1 秒以上。浏览器临时转写仅驻内存，浏览器合成不落盘，日志不含原音频和临时转写。QQ 语音输入作为会话附件管理，输出波形短期加密保存并在发送或失效后清理，生命周期与浏览器不同。手动核对后明确发送的文字按普通聊天与记忆规则保留；连续模式自动转写只保留聊天，不自动抽取长期记忆。

语音会话最长 15 分钟，20 秒心跳；服务端 60 秒未续约不再受理音频请求。前端页面隐藏、离线、切换对话、退出或到期时停止。断线后不自动重开麦克风、不重播历史回复。每位所有者每分钟最多 30 次付费音频请求；同句明确重试可能再次计费，不自动重试音频服务。

## 数据库与验证

迁移 `0010` 只新增 `voice_config`、`voice_sessions`、`voice_playbacks`，不修改原会话表。升级前按 README 备份，执行 `alembic -c backend/alembic.ini upgrade head`，随后启动新 Core、worker 与 Web。

新增接口均使用认证 Cookie、CSRF、真实所有者及工作区检查；语音会话还固定登录会话与配置版本。返回音频前重新检查登录、配置、服务、会话及回复来源。服务密钥仍只存现有加密凭据库，模型上下文不包含密钥。

已完成协议测试服务与浏览器合成音源联调。真实供应商／物理麦克风、中文识别与发音质量、P50／P95 延迟和设计方案 30 正常＋10 打断＋10 断线／修订专项仍为待验证，不将模拟服务输出当作质量验收。

2026-10-29 本机部署验证：PostgreSQL `0009 → 0010` 保留已有会话；Linux 完整后端回归 330 项通过，新增播放历史投影用例后语音专项 33 项通过；前端 83 项通过，类型、菜单／开场静态检查及构建通过。隔离浏览器使用合成音源，验证采集、核对、聊天、分句播放和停止播报；375／768／1024／1440px 无横向溢出。Docker 入口已更新，Core、数据库与 Hindsight 健康，部署 OpenAPI 与发布合约一致；未修改真实音频配置，未采集物理麦克风。
