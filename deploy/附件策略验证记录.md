# 附件策略管理验证记录

版本 v1.47，2026-10-31，数据库迁移 `0041`。

## 使用方法

打开“数据日志 → 文件管理 → 附件策略”，点击“调整限制”。可设置每条附件数量、单个 MiB 上限、合计 MiB 上限，只能在 1–10 个、1–20 MiB、1–50 MiB 范围内调整，单个上限不能高于合计上限。先预览当前值与新值，核对影响并勾选，再确认保存。默认仍为 10 个、20 MiB／个、50 MiB／条。

设置属于当前工作区，适用于 Web 上传、新选择的既有附件、协作任务提交，以及该工作区 QQ 消息中的文档、图片和转换后语音。前端展示实际限制，策略无法读取时阻止上传并提供重试；服务端始终独立检查，不能通过绕过界面、伪造 Content-Length 或重发旧预览扩大范围。QQ 规则、音频格式／时长、图片、解析及模型上下文预算继续独立生效，采用更低上限。

## 生效与数据保留

- 新上传在读取前及每个分片检查大小，并在提交事务中重新读取策略；传输过程中下调上限可拒绝本次文件，不创建可用记录。
- 已有附件不会因上限降低而删除，仍能查看和下载；但新消息或新协作不得再次选择超限文件。已经提交的任务使用原附件，调限不撤销其授权或取消生成。
- QQ 先检查声明与附件数量，暂存及下载前再次检查。下载完成、入库前重新核对实际大小及最新策略，转换后的语音也受工作区上限约束。失败时终止该次接收，不忽略部分附件继续作答；未提交的暂存内容沿用已有删除清理流程。
- 保存复用登录、CSRF、工作区及版本检查。预览仅五分钟有效，绑定当前用户、工作区、登录会话、原版本与精确新值；修改配置、重新登录、过期、篡改或重复确认均不能沿用旧预览。审计记录标记“附件策略”。
- 升级对已有工作区创建原默认值，不改动文件。初始化所有者时也创建策略。恢复同版本旧备份时保留恢复前最新策略，并使旧登录与预览失效；已修改策略的有损降级被拒绝。

接口：`GET /api/media-policy`、`POST /api/admin/media-policy/previews`、`PUT /api/admin/media-policy`。业务层通过统一限制检查使用策略，配置不携带凭据或业务正文。

- 独立真实 HTTP 验证预览不保存、确认后上限生效、重复确认返回 409、超限二进制上传返回 413、重复上传复用记录、旧大文件仍可下载，以及独立 worker 解析新文件；无模型配置、付费请求或真实 QQ 消息。
- Core／worker 实际重启后，策略及版本、新文件解析结果、旧大文件下载均保持；未新增模型调用。隔离 Web 的 15 个资源与本次构建逐字节一致，未登录读取、预览、更新策略与管理健康均返回 401。
