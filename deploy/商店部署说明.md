# 独立插件商店

当前提供独立 FastAPI 进程、独立 PostgreSQL、独立商店账号、发布者命名空间、公开／私有版本、人工审核、不可变 JSON 制品、Ed25519 签名、在线签名密钥轮换及撤销同步。Core 只接收目录、制品和撤销信息；商店不接收对话、个人记忆或模型密钥。

当前可执行制品只包含声明式文字 Skill，不包含脚本、压缩包、进程或界面代码。API／MCP／角色／事件适配器仍待接入，清单可说明这些类型，但当前 Core 安装会拒绝不支持的适配器。目录同步与信任不替代用户安装确认。

## 初始化与启动

使用已有 Python 依赖，无新增 Python 包。示例在 Linux 项目目录执行，密码由终端隐藏输入，不放在命令行。正式 HTTPS 部署使用 `LINGXI_COOKIE_SECURE=true`。

1. 在独立目录生成密钥，记录命令输出的**根公钥**。通过可信渠道核对后才能在 Core 固定；不得自动信任从商店下载的新根。

   ```bash
   PYTHONPATH=backend python -m lingxi_store.cli init-keys --directory ./runtime/store-keys
   ```

2. 将 `offline-root.key` 移到离线安全介质。在线服务只挂载 `signing.key` 和 `trust.json`，不挂载根私钥。容器 UID 10001 必须能够读取这两个文件；由部署人员设置适当文件所有权与最小权限。

3. 在部署环境加入独立随机的十六进制 `STORE_DB_PASSWORD`、Linux 绝对路径 `LINGXI_STORE_KEYS_DIR`，以及现有准确的 `LINGXI_PUBLIC_ORIGIN`／`LINGXI_COOKIE_SECURE`。不要复用 Core 数据库密码或模型密钥。Compose 的 PostgreSQL 地址直接包含密码，使用十六进制避免 URL 转义问题。

4. 运行独立迁移并启动。首次部署先正常构建应用镜像；不要直接把未经迁移的开发中源码覆盖运行容器。

   ```bash
   docker compose -f compose.yaml -f compose.store.yaml build store-migrate plugin-store web
   docker compose -f compose.yaml -f compose.store.yaml up -d store-db store-migrate plugin-store
   docker compose -f compose.yaml -f compose.store.yaml run --rm plugin-store python -m lingxi_store.cli create-account --username publisher --role publisher --namespace example
   docker compose -f compose.yaml -f compose.store.yaml run --rm plugin-store python -m lingxi_store.cli create-account --username reviewer --role reviewer
   docker compose -f compose.yaml -f compose.store.yaml up -d --no-deps web
   ```

商店没有默认账号、公开注册或默认安装插件。发布者与审核员分开，禁止自审；`lingxi` 命名空间保留。管理员可用 `disable-account --username NAME` 立即停用账号并撤销会话。

## 发布、审核与安装

浏览器的“开发后台 → 我的插件”使用独立商店账号登录，提交指定命名空间的清单。公开版本进入审核队列，私有版本另需发布者账号具备对应 audience。界面先核对范围再确认，不上传私人资料或密钥。所有版本提交后不可覆盖；驳回后用新版本号提交。

“审核治理 → 审核队列”由审核员检查自动合约结果、权限、数据、费用、依赖和说明，再填写理由决定上架或驳回。自动检查只证明格式、命名空间和声明式制品边界，不证明内容可信或模型质量。上架前校验可访问的已发布依赖，公开版本不能依赖私有版本；循环／不满足版本范围不能上架。

Core 的“插件中心 → 插件商店 → 独立商店连接”填商店根地址（例如 `http://plugin-store:8001`）、可信根公钥；同机容器地址须明确允许内网。保存配置后“同步目录”，再重新加载列表。第一次安装及每次升级仍需完整预览与确认，AI 不能自行批准。

## 工作区私有目录

创建发布者时用 `--audience workspace-a` 授予私有发布范围。商店标识是独立的、不包含用户记忆的 audience；Core 将只读令牌与实际所有者／工作区绑定，浏览器不能在检索时临时指定工作区。

```bash
docker compose -f compose.yaml -f compose.store.yaml run --rm plugin-store python -m lingxi_store.cli issue-reader --audience workspace-a --token-file /app/runtime/store-reader.token --days 90
docker compose -f compose.yaml -f compose.store.yaml run --rm plugin-store python -m lingxi_store.cli revoke-reader --id READER_ID
```

上例令牌保存在商店持久卷的 `/app/runtime/store-reader.token`，由部署人员通过安全方式取出并填入 Core，核对引用后删除临时文件；不要打印到日志或共享终端。上述管理命令必须使用独立商店数据库环境；若在宿主机执行，先显式设置 `LINGXI_STORE_DATABASE_URL`，否则默认 SQLite 不是运行中的商店。

读取令牌仅能读取对应私有目录和制品，不能发布、审核或管理。命令只输出令牌 ID，令牌写入指定私密文件。Core 在凭据库加密保存，不回传明文、不写日志。公开目录两项留空；变更 audience、令牌、来源或根公钥会使旧来源授权暂时失效，重新同步核对。令牌无效／过期时新安装暂停；已知撤权在成功同步后生效，断网不能声称获知最新状态。

## 制品存储

默认使用独立持久卷保存受限、按 SHA-256 寻址的规范 JSON，并在写入后读取复核；没有解包动作。可设置 `LINGXI_STORE_S3_ENDPOINT`、`LINGXI_STORE_S3_BUCKET`、`LINGXI_STORE_S3_REGION`、`LINGXI_STORE_S3_ACCESS_KEY`、`LINGXI_STORE_S3_SECRET_KEY` 切换兼容 S3 的私有存储，使用 SigV4、固定端点、受限响应和校验和，不生成公开对象地址。Bucket 由部署人员提前创建，凭据仅允许所需对象读写。S3 实际厂商兼容性须现场验证；未设置外部 S3 时不宣称已验证云存储。

数据库和对象分别备份。制品先持久化并验证，后提交发布状态；中断可能留下未引用对象，但不会将未确认对象暴露为已发布版本。迁移不覆盖已发布版本。对象摘要一致但记录签名不一致、制品缺失或篡改时拒绝安装。

## 信任、撤销与离线

Core 验证固定根签名的在线公钥登记、单调信任 epoch、单调目录 revision、10 分钟快照、绑定 audience、制品签名和内容摘要。根私钥不进入在线服务；在线密钥泄露时停服务，使用离线根轮换并撤销旧 key ID：

```bash
PYTHONPATH=backend python -m lingxi_store.cli rotate-key --directory ./runtime/store-keys --root-key /offline/root.key --revoke OLD_KEY_ID
```

轮换时停止商店，原子替换两份文件后重新创建容器，避免单文件 bind mount 继续引用旧 inode。保留旧的有效公钥可验证历史制品；撤销公钥会使其签署的旧制品不可用，应以新版本重新审核发布。根轮换由 Core 所有者通过可信渠道添加新固定公钥后另行迁移，不从网络自动替换根。

下架停止发现与新安装，已有有效安装可继续；重新上架仍需版本检查。安全撤销不可逆，已发布和下架版本均可撤销。Core 每约 5 分钟尝试同步（worker 每分钟检查，独立后台槽不阻塞业务作业），也可手动同步；先应用已验证撤销，再下载其他制品，下载失败不会撤回已知撤销。已知撤销阻止新调用和结果提交，并影响依赖者及排队调用；不能撤回已外发的输入、模型费用或已显示结果。

商店故障不影响内置目录、正常聊天和仍有效的既有插件；新安装／更新必须有未过期且没有同步错误的目录。断网时不宣称已获知最新撤销。当前单快照最多 500 个可见已发布历史版本，超过时明确失败，不将截断目录当完整同步；大规模分页协议、公开运营、第三方漏洞响应和服务容量扩展仍待完善。审核页面每类显示最近 200 条。

## 接口与数据边界

独立商店：`/store/v1/auth/*`、`/submissions`、`/releases/{id}/decision`、`/catalog`、`/feed`、`/artifacts/{sha256}`、`/trust`、`/audit`、`/health`。商店 Cookie 的 path 固定 `/store/v1`，独立 CSRF 字段；反向代理只转发商店 Cookie，剥离 Core Cookie。Core 新增 `/api/plugin-store`（GET／PUT）及 `/sync`（POST）。内部令牌只读，不接受普通聊天身份进行平台同步。

独立迁移使用 `backend/store-alembic.ini`，Core 迁移 `0012` 只保存连接、固定公钥、加密读取令牌及范围化版本授权，不共享商店账号、会话或发布表。
