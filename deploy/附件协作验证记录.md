# 附件协作验证记录

版本：v1.40；日期：2026-10-30（Asia/Shanghai）。本记录针对 Web 文档／图片协作增量，完整产品与真实模型质量仍未验收完成。

## 已接入行为

- Web 聊天“助手协作”和任务中心“新建协作”接受已解析文档／图片；任务中心预览列出文件和授权范围。QQ、语音及普通单步任务入口未扩展。
- `DelegationInput.media_ids` 最多十项；规划节点 `media_ids` 必须是任务附件的唯一子集，所有提交附件必须被覆盖。原附件只分配给 `reason` 节点；目录与工具节点不能夹带原附件。
- 调度器只读取附件元数据，按已验证视觉能力选派图片节点。主助手可使用文字模型；未通过当前模型／连接视觉探针的图片节点明确失败，不丢图、不自动换模型。
- ContextBundle 记录附件元数据、版本及依赖来源。正文与图片仅在对应节点调用前展开，文档保留来源位置；持久化上下文不重复存储正文或图片 Base64。下游通过直接依赖获得结果，不自动获得全部原附件。
- 总量、类型、主体与工作区检查沿用媒体服务。每节点图片实际传输上限 12 MiB，图片另计保守上下文额度；超出文本上下文预算明确失败，不声称完整阅读。
- 数据锁按稳定标识排序，提交、规划元数据及汇总附件列表保留用户选择顺序，避免“第一份、第二份”的顺序变化。
- 汇总以 `attachment_coverage` 展示分配节点与真实状态。部分失败明确保留限制；结构／引用校验不等于事实全部核验。工具执行仍经原有精确范围、参数预览与单次确认。
- 删除、来源版本／范围变化及删除记录重放会作废在途节点、已完成汇总、聊天卡和后续衍生回答；返回前再次检查。已发送模型资料无法撤回，迟到结果不发布。

## 专项场景

全部模型返回均为合成协议答复，不调用真实付费提供商，不登录 QQ，不发送真实消息。

| 编号 | 验证重点 |

| AM03–AM06 | 遗漏附件、范围外标识、重复标识、工具节点夹带附件均阻断 |

## 验证证据

- Windows Python 3.13.15 专项：33 项通过。
- 独立 PostgreSQL 最终镜像：协作、附件、聊天协作、工具、插件角色、分支、上下文及备份相关回归共 295 项通过（202.23 秒），包含上述 33 项附件专项。
- 前端：232 项通过；类型、四字菜单、47 路由、十阶段身份门禁动画静态检查及生产构建通过。新增交互检查覆盖附件选择与预览返回、解析中禁止提交、来源弹窗焦点、聊天协作携带附件。
- 浏览器：375、768、1024、1440px，无页面或弹窗横向溢出；375px 长表单可纵向滚动，1024×480 矮屏可操作。Tab／Shift+Tab 在当前弹窗循环，Escape 关闭来源后返回文件入口，关闭创建预览返回原创建按钮。刷新保持服务器登录身份确认。
- 独立 HTTP／worker／PostgreSQL：真实上传、解析、六色块视觉探针；停止 worker 后提交两附件任务，重启 Core 后恢复，一次规划、两个按模态分配的节点、一次汇总。聊天附件协作重复提交只建立一条统一结果链。
- 删除竞态：合成节点响应延迟八秒，响应前通过真实 HTTP 删除附件；在途、既有完成任务和聊天结果失效，迟到正文不写回，没有额外规划或汇总重放。
- 最终镜像另以两份新附件验证选择顺序，真实独立 worker 完成一次规划、两节点、一次汇总，重复提交不增加调用。
- 迁移 `0035`：空数据 `0035 → 0034 → 0035` 可执行；存在 `media_refs` 的协作记录时拒绝降级，避免旧执行器忽略来源屏障。

本地证据保存在 `.preview/agent-media-*.log`、`.preview/agent_media_*.py`／`.sh`。初始化脚本只针对隔离 QA；清理后需重新生成独立配置，不应直接复用为生产操作。

## 实际接入限制

合成图片探针只能证明协议块与模型分配路径正确，不能证明真实视觉理解。真实供应商的中文 JSON 分工、引用准确性、延迟、费用和多附件长上下文仍待配置后评测；现有 150 题中文记忆评测、真实 QQ 兼容、原生实时语音及完整产品准入仍分别保留，不能用本次测试替代。

不自动写长期记忆，不扩展工具授权，不新增桌面组件，不修改现有联系偏好，不恢复顶部介绍区。远程工具可读取经授权依赖结果，实际业务请求仍需逐次确认。
