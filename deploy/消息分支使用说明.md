# 消息分支使用说明

适用版本：设计 v1.23，数据库 0019。功能代码已接入，实际提供商质量及完整中文记忆评测仍待验证。

## 编辑消息

在独立 Web 对话中，等待当前回答完成或停止后，点击用户消息下的“编辑消息”。修改文字，再点击“创建分支”。新分支保留这条消息之前的已完成原文和这条消息的附件；原消息及其后续回答继续保留在原会话。

编辑只影响新分支的提问，不会更新或删除长期记忆，也不会自动开启任务协助、助手协作或执行联系偏好命令。需要执行新任务时，在分支继续发新消息并明确开启对应模式。

## 重新生成

点击助手回复下的“重新生成”，确认后进入新分支。服务器引用原始提问并生成新回答，不重复创建原用户消息、不再次抽取其记忆，也不重新安排任务。原回复仍可从“返回原话”查看。

已安排的提醒、计划和协作继续保持原来的任务与回执。模型可以读取允许继承的真实任务记录，但不能通过重新生成再次执行。重新生成可能产生模型费用；模型不可用时显示真实失败，可从原会话另建分支。

## 历史、附件与删除

分支中的共享历史标为“引用原文”，通过原始 ID 访问，最多继承 1000 条已完成消息。父会话之后的新消息不进入已有分支。分支可再次分支，保留独立历史范围；搜索和导出遵守相同范围。

删除分支只删除其独有消息。删除原会话会清除其原文，并使依赖这些原文的分支回答失效。独立编辑产生的新提问如未引用原文，可继续存在。删除记忆、附件或任务来源同样使依赖回答失效，不能通过分支或重试恢复。

QQ 会话和有效实时语音会话暂不支持编辑或重新生成。停止播报不等于结束语音会话，请先显式结束。Web 分支继承的是 Web 中显示的已完成文字，不声称它们全部在语音中播放过；语音回复本身不提供重新生成。

## 管理与恢复

升级前备份业务数据库与独立删除记录；迁移 `0019` 后再更新 Core、worker、Web。存在分支时，降级会被阻止，因为旧 Core 不理解分支范围。回退应恢复升级前数据库及配套镜像，并先重放最新删除记录。

分支提交以 `request_id` 幂等，失败重试保持 ID，参数变化使用新 ID。浏览器关闭不取消已提交生成；恢复后查询相同任务结果。分支仅在当前所有者与工作区内访问，客户端不能扩展原文可见范围。
