# 系统迁移

此功能将一个服务器工作区交接到**同版、空的目标服务器**。网页只做目标预检、明确确认、记录和取消待导出的计划；数据库与文件由 Linux 主机终端搬运，不把 Docker socket、SSH 密码或主密钥交给 Web。系统迁移不等于任意版本升级、灾难重建、自动高可用或一键回切。

## 使用条件

- 源与目标为 Linux x86_64，数据库版本均为 `0047`，Core、worker、PostgreSQL 与 Hindsight 使用源端相同的镜像；运行器拒绝不同镜像。运行本项目随版本提供的 `deploy/backup.py` 和 `deploy/migrate_workspace.py`。
- 目标有自己的 HTTPS 公共入口，与源不同。`LINGXI_PUBLIC_ORIGIN` 须与实际入口一致；WSL 本机演练可以使用两个不同端口。
- 目标只允许一个初始管理员、原始第一方预设及认证／运行元数据。已有会话、记忆、文件、服务器资料、自定义人格、代理、模型、插件配置、授权、提醒或其他业务记录均拒绝导入；停用不等于空白。
- 目标使用与源相同的 `LINGXI_ENCRYPTION_KEY`，由操作员通过独立安全通道配置。不要把主密钥粘贴到迁移网页、命令参数、聊天或日志；不要照搬源 `.env`，两端数据库密码和公开入口分别配置。
- 提前完成源端备份，结束实时语音，完成或取消待执行的备份请求。确认目标磁盘足以容纳迁移包、自动回退包、两库及资料卷。
- 先停止备份运行器的常驻服务。备份与迁移按 Compose 项目加主机锁，即使使用不同归档目录也互斥；始终由**同一 Linux 账号**运行，并保持 Docker context 与项目名一致。迁移目录应使用原备份目录，避免分散中断记录。

## 1. 准备空目标

部署相同版本并完成初始管理员创建。以下命令中的项目路径、项目名及受保护目录须按实际环境填写；默认项目名是 `lingxi`。

```bash
sudo install -d -m 0700 /var/lib/lingxi/backups
sudo python3 deploy/migrate_workspace.py prepare-target \
  --project-dir /opt/lingxi --project-name lingxi \
  --migration-dir /var/lib/lingxi/backups --label 新服务器
```

此操作持久化唯一目标实例并暂停目标业务写入。注册结果保存在目录内的 `target-registration.json`，文件权限为 `0600`。只将其中的 `ticket` 复制到源端“系统设置 → 系统迁移 → 迁移预检”。票据加密、不含主密钥，但仍应私下传递。目标名称、入口和实例 ID 必须逐项核对。

目标注册七天内可用于新预览；网页预览五分钟有效，并绑定当前登录、工作区与目标。注册重复执行返回原票据，不自动轮换，以免破坏已经冻结源端的绑定。已合法导出的迁移包仍可在票据到期后向原目标交接；过期票据不能创建新的计划。若尚未建立任何源端计划而注册已过期，应重新准备独立空目标，不修改数据库绕过门禁。

网页明确勾选停写影响后点击“确认迁移”，只生成计划，不开始搬运。尚未开始导出的计划可以取消；版本变化、预览到期或目标更改需重新核验。

## 2. 源端停写与导出

在源服务器终端执行，用网页中的完整迁移编号替换占位符：

```bash
sudo python3 deploy/migrate_workspace.py export 迁移编号 \
  --project-dir /opt/lingxi --project-name lingxi \
  --migration-dir /var/lib/lingxi/backups
```

终端要求输入 `EXPORT 完整迁移编号`。确认后数据库持久化源端停写门禁，关闭旧 QQ 连接，阻止新业务请求、订阅触发与 worker 调度；等待已接受的工作结束，然后冷停服务。已经发出的外部请求可能生效，保留其回执，不假定可以撤回或重发。

归档包括业务数据库、Hindsight 数据库、运行资料卷、服务器资料卷；若已部署 NapCat，还包含其登录资料和配置。迁移包使用与备份相同的路径、类型、长度及 SHA256 核验，加密交接证明绑定精确目标、完整清单摘要、权威记录计数和最新安全检查点。主密钥、`.env`、独立插件商店、远程 S3 和模型缓存不在包内。

成功后仅恢复原本在线的 Core 和 Web，供登录与状态查看。**源端保持停写**，worker、Hindsight 和 NapCat 不自动重启；重启应用不会释放门禁。不要手动删除门禁或开启旧 QQ、订阅与任务。源端断点重试必须保留同一目录、容器和镜像，按同一编号重新运行 `export`；容器被重建或镜像变化时停止并人工核对，不盲目续传。

## 3. 传输与目标预检

由操作员通过可信通道复制**整个迁移编号目录**至目标的迁移目录，保留访问权限。不要复制源端 `latest-safety.json`、中断 journal、锁或其他迁移包。目标目录仍要求 `0700`。传输工具和远程凭据由操作员管理，本程序不连接任意远程地址。

```bash
sudo python3 deploy/migrate_workspace.py inspect 迁移编号 \
  --project-dir /opt/lingxi --project-name lingxi \
  --migration-dir /var/lib/lingxi/backups
```

预检确认归档完整性、加密证明、主密钥、schema、精确目标实例和公共入口，再次检查目标为空。不匹配时不替换数据库。不要手改清单、票据或数据库；保留源端归档重新核对。

## 4. 导入、核验及激活

```bash
sudo python3 deploy/migrate_workspace.py import 迁移编号 \
  --project-dir /opt/lingxi --project-name lingxi \
  --migration-dir /var/lib/lingxi/backups
```

需输入 `IMPORT 完整迁移编号`。程序固定本地辅助镜像，冷停目标，先创建空目标回退包，再替换两库与固定的应用资料卷。迁移专用解包在完整验证后替换卷内文件；普通历史备份回退仍沿用原来的覆盖行为，不混为一种操作。

导入后重放源端最新纠正、删除及撤销记录，核对权威计数和每份已提交附件的实际摘要。撤销旧登录，隔离旧作业、模型连接、QQ 身份与连接、插件账号与订阅、资源授权和主动联系。不会重新播放旧请求；外部执行结果未知的记录继续保持待核对。Hindsight 为衍生索引，按权威记录重建，不让旧索引决定事实有效性。

仅恢复 Core／Web，状态应为“待激活中”，业务仍不可用。核对入口、归档摘要、记忆与附件验证结果及源端停写状态后，在目标执行：

```bash
sudo python3 deploy/migrate_workspace.py activate 迁移编号 \
  --project-dir /opt/lingxi --project-name lingxi \
  --migration-dir /var/lib/lingxi/backups
```

输入 `ACTIVATE 完整迁移编号`。再次核对目标和附件后开放目标；使用**源工作区管理员**登录，源端的 TOTP 状态随工作区保留，目标初始管理员被替换。激活不会恢复外部授权。由操作员检查配置后手工启动目标 worker／Hindsight，再逐项重连模型、资源、插件和联系渠道；NapCat 保持停止，重新确认 QQ 后才启动。源端继续保持停写，不提供一键解冻。

## 5. 中断恢复

- 源端导出中断：保持归档目录与 journal，按原编号重试 `export`。不运行目标 `recover`，不重新放行源端业务。
- 目标导入中断：保持服务停止，保留自动回退包和 `migration-in-progress.json`，用同一操作员、项目及目录运行：

```bash
sudo python3 deploy/migrate_workspace.py recover \
  --project-dir /opt/lingxi --project-name lingxi \
  --migration-dir /var/lib/lingxi/backups
```

输入提示中的完整 `ROLLBACK 回退编号`。程序恢复原空目标、替换导入遗留文件、撤销其登录并保留原注册；随后可以核验并重试同一包。源端门禁不受影响。若回退也失败，继续保持停止，检查受保护目录中的 `runner-error.log`，不要清除 journal 后强行激活。

运行器或 Docker 主机可读到工作区机密。目录、数据库包、票据、交接证明、认证哈希与私有错误日志均不能公开分享。这里只支持已完成源端冻结交接的同版迁移，不能代替独立商店备份、全损恢复、跨版本升级或真实 QQ 迁移演练。
