# 灵犀安全验证说明

当前面向单所有者、单工作区。双重验证由所有者主动开启；升级不会改变现有账号密码，也不会自动绑定认证器。

## 绑定认证器

1. 在“系统设置 → 安全设置”选择“启用验证”，输入当前密码。
2. 在可信认证器中手动添加页面密钥，名称可填写“灵犀”，类型为基于时间的 TOTP，SHA1、6 位、30 秒。首版不提供二维码；接口同时返回标准 `otpauth` URI。
3. 输入认证器当前验证码，核对其他会话退出的说明并确认启用。
4. 将返回的 10 个恢复码离线保存在安全位置，确认保存后关闭。每个恢复码只能使用一次，使用时仍需账号密码；关闭后不能重新查看原码。

准备绑定有效期为 5 分钟，绑定当前登录会话。网络重试使用同一请求编号，不重复创建密钥；开启另一轮绑定会替换未完成配置。关闭页面不会自动启用。worker 每小时清理过期的待绑定密钥，不清除已启用的密钥。

密钥只在绑定响应中展示，服务器加密保存；恢复码只保存不可逆摘要。普通状态查询、审计及诊断不返回密钥、密码、验证码或恢复码明文，前端不将这些内容写入浏览器存储。

## 登录与验证

开机动画的“身份确认”增加“验证代码”。未开启时留空；已开启时同时填写用户名、密码和认证器验证码，或一个未使用的恢复码。有效登录会话仍只需点击“确认进入”，不重复验证。

服务器需保持系统时间同步。验证码允许前后一个时间窗口的偏差，同一时间窗口只成功使用一次，已接受的计数不会倒退。刚用于登录、绑定或管理操作的验证码不能再次使用，请等待下一组验证码。账号的验证尝试受持久化限流约束，更换 IP 不会重置额度。

停用验证、更换恢复码均需当前密码、未使用的验证码或恢复码、配置版本及影响确认。启用、更换和停用后撤销其他浏览器会话，保留当前会话；后台任务继续运行。更换恢复码使全部旧码立即失效，不改变已绑定的认证器。

## 网络失败与恢复

请求失败可能发生在服务端已经提交之后。不要连续重放验证码：关闭操作弹窗并刷新安全状态，核对是否已启用或是否发生版本变化。若确认启用或更换的响应丢失，原恢复码明文无法补发；使用下一组认证器验证码和当前密码重新更换并保存恢复码。旧版本请求返回冲突，必须刷新核对，不能覆盖最新配置。

如果认证器不可用，可使用一个未使用的恢复码登录。认证器和全部恢复码均丢失时，具有服务器终端访问权限的部署管理员可执行：

```bash
docker compose exec core python -m lingxi.cli reset-totp
```

按提示输入所有者用户名、当前密码，再输入 `RESET 用户名`。重置会停用双重验证、清除相关密钥与恢复码、撤销全部浏览器会话并写审计；不能绕过密码。重新登录后应绑定新的认证器。此命令不会自动执行，也不提供 Web 绕过入口。

## 迁移与回退

迁移 `0014` 新增 `two_factors` 表，升级前备份数据库及服务器加密主密钥，保留原镜像。密钥备份须按凭据保护，不进入普通导出或诊断。迁移后 Core、worker 和 Web 应同步更新。

存在已启用配置时，数据库回退至 `0013` 会被明确拒绝。**不得只替换成不支持 TOTP 的旧 Core**：数据库保护无法阻止旧二进制忽略验证。确需回退时，所有者必须先通过当前密码与有效验证代码确认停用，部署管理员再在维护窗口执行回退。回退会移除本功能配置及未完成绑定，不影响其他业务表。

## 本批验证与边界

Linux＋独立 PostgreSQL 完整后端 467 项、前端 114 项通过，包含并发验证码／恢复码单次消费、绑定幂等及过期、账号限流、权限、版本、终端重置与诊断脱敏；类型、菜单／动画静态检查和构建通过。独立数据库验证启用状态阻止降级、停用后回退再升级保留业务记录。真实 HTTP 验证绑定、登录、重放拒绝及 Core／worker 重启持久化；浏览器验证合成账号登录、状态与弹窗、375／768／1024／1440px 和矮屏键盘访问。测试未为真实账号开启验证。

这些结果不代表账号维护、自动备份恢复、服务器迁移或完整安全审计已交付。生产需使用 HTTPS 并保护服务器、主密钥和认证器；真实模型、QQ 与中文记忆质量仍需独立验证。
