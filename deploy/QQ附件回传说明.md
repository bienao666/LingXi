# QQ 附件回传说明

适用版本：**v1.67**；数据库迁移 `0053`。这是现有服务器版的增量，不新增菜单或桌面组件。

## 使用方式

1. 在「数据日志 → 文件管理」上传图片或支持的文档，等待解析就绪。
2. 在「平台接入 → 平台实例 → 收发记录」找到 24 小时内已完成的原 QQ 消息，点击「发送附件」。
3. 选择最多三项来源；可搜索文件名。可选当前所有者的受控文件，或原 QQ 发送者在原会话已完成消息关联的资料。协作汇总只能来自这条 QQ 请求本身。
4. 点击「预览附件」，核对接收群／私聊、文件名、完整内容、版本与期限。勾选分享确认，再点击「确认发送」。群成员均可见，不能修改接收者。
5. 展开「附件记录」查看各项真实状态。可取消尚未发出的项；已发出的操作不能撤回。协议接受不保证送达、已读或下载。

每批最多 3 项、单个 20 MiB、合计 50 MiB，取当前附件策略的更低限制；协作 Markdown 汇总最多 512 KiB。图片使用 QQ 图片片段，文档使用 NapCat 上传文件操作。出站文件使用系统生成名称，避免泄漏服务器路径与私人标签。

## 来源与确认

- 原消息、完成生成、会话、工作区、发送者、平台实例版本及身份绑定均需有效；不能从同名或其他会话继承权限。
- 预览五分钟有效，固定当前登录、原受众、文件版本和摘要；确认后最多排队一小时。确认及真正发送前重查来源、字节完整性和策略。
- 所有者确认的是向原受众披露所选完整文件，文件不会自动匿名化。服务器文件还需原有资源授权；删除、纠正、撤权、过期或变更后停止使用。
- 协作汇总保留「部分完成」及限制、依据节点和附件覆盖记录，不把计划等同于实际执行；群汇总不能携带私人记忆依据。
- 不接受任意 URL、本机路径、任意接收者、未经确认的自动工具执行或新生成图片。文件／图片生成属于其他能力，本入口只发送已有受控来源。

## 协议与恢复

发送意图在事务中持久化后才进行 WebSocket I/O。同一确认重复提交不会新建批次；失去 HTTP 响应可重试同一确认。图片保存有效协议消息 ID，文件保存协议文件 ID，缺失回执或断线转「结果待核」，不盲目重传。第一项失败／未知时后项不自动发送。

取消保留已接受、失败和未知的回执，只取消待发送项。来源失效会停止后续项，不声称整个批次送达。备份恢复安全检查点保留最新确认与发送屏障，旧登录确认撤销、待发送项取消，已知回执保留，未知操作继续待核对；不能依靠恢复或重启重新发送。

迁移 `0053` 新建 `channel_artifact_replies`。空表可降级，有确认记录时拒绝有损降级；使用升级前备份及配套镜像恢复，并遵循现有删除／撤销与副作用核对流程。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/channels/{id}/artifact-sources?origin_id=&q=` | 有界查询前 50 个匹配就绪文件及原请求汇总 |
| `POST /api/channels/{id}/artifact-previews` | 精确来源版本、请求 ID 与五分钟预览 |
| `POST /api/channel-artifact-replies/{id}/confirm` | 摘要与分享确认，绑定原登录 |
| `GET /api/channels/{id}/artifact-replies?origin_id=` | 最近 20 个批次及各项回执 |
| `POST /api/channel-artifact-replies/{id}/cancel` | 取消未发送项，保留已有外部事实 |

所有接口复用当前所有者认证、工作区与 CSRF。列表不返回文件字节、摘要内部字段或凭据。NapCat 继续连接 Compose 内网的 Core 认证入口，Web 反向代理不新增公开协议入口。

## 验证及边界

独立 PostgreSQL 相关回归 **402 项**通过，覆盖图片／文件及私聊／群聊、权限、CSRF、登录、来源变化、完整性、媒体策略、期限、取消、多项失败阻塞、部分协作汇总、并发确认和完整备份隔离。迁移实测升级、空表降级和已有确认拒绝降级。

前端全量 **392 项**、类型／静态／构建检查通过。隔离 HTTP→Nginx→Core→PostgreSQL 与真实附件解析器、内网认证 WebSocket 验证 PNG／Markdown 原字节、原群、重复确认、消息／文件回执、断线不重放和发送前版本失效。375／768／1024／1440px、分享勾选、嵌套弹窗焦点及 Escape 另行复查。

上述协议端是合成服务，没有登录真实 QQ、变更正式配置或调用付费模型；真实 NapCat 版本兼容、平台权限与真实模型质量仍待验证。整体产品仍未标记为全功能已交付。
