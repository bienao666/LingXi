# 记忆时间依据（v1.85）

## 主体与时间查询（v1.85）

在「长期记忆 → 记忆列表」展开「记忆筛选」，填写完整主体名称（`self` 表示本人，空白为全部），选择时间依据及选填的开始／结束日期，然后「应用筛选」。正文与类别可以继续组合。未应用的输入不改变查询；「清除筛选」清除主体与时间，保留正文和类别。错误日期保留输入并提示修正，切换「不限时间」会清空日期。数据仍按**记录时间倒序**，不是按事件时间排序。

| 时间依据 | 匹配规则 |
|---|---|
| 不限时间 | 不限制时间，旧文本和未注明记录仍可查看 |
| 记录日期 | 记忆的创建日期，不代替事件发生时间 |
| 事件日期 | 明确标注的事件时刻落在所选 UTC 日范围，带时区时先换算 |
| 事实期间 | 起止都有明确依据且顺序有效，与所选日期范围存在交集 |

日期上下界包含整天，按 UTC 日计算，不自动按浏览器时区或用户所在地推测；只填一端则仅限制该端。不填日期而选择事件／期间时，只筛出有对应明确依据的记录。未注明的期间端点表示未知，不视作无限或永久；旧自由文本、无时区时刻或无效日期不参加明确时间筛选，原数据保留，可切回不限时间查看并纠正。管理筛选不改变记忆保留期限、授权或自动判定当前事实，也不改变模型的语义召回逻辑。

### 分批查询与接口

`GET /api/memory-pages` 增加 `subject`（完整匹配，最长 150 字符）、`time_basis=all|created|event|period`、`since`／`until`（空或 `YYYY-MM-DD`）。日期无效、倒序或未选依据却填写日期返回 422；游标绑定全部条件，换条件须从首页重新查询，误用旧游标返回 400。原默认请求及候选／操作分页接口继续可用，工作区和所有者由认证确定。

旧时间字段为自由文本，不能用字符串大小直接排序／比较。先在数据库按所属范围、正文、类别及主体过滤，再每批最多 64 条解析时间，每请求最多检查 1024 条；不加载整个记忆库。`scanned` 为本次时间依据解析条数，`scan_limited` 为预算用尽且仍有候选未检查。后者为真时，页面说明仍需下一页；即使返回零匹配也不会误报整个记忆库为空。续查按最后检查位置推进，不能只按最后匹配位置循环。

游标只冻结顺序截止时刻，不能冻结内容、权限或删除状态。更正和删除在后续读取时重查；新的条件重置页码，迟到响应不覆盖新范围。不调用 Hindsight 或任何模型，不新增 schema 迁移，不改写已有日期或自动重新索引，当前 schema 为 `0060`。

## 操作

进入「长期记忆 → 记忆列表」，新增或纠正一条记忆。在「时间依据」填写：

| 字段 | 含义 | 示例 |
|---|---|---|
| 事件时间 | 事件发生日期或明确时刻 | `2024-02-29` |
| 生效时间 | 事实适用期间的起点 | `2024-01-01` |
| 结束时间 | 事实适用期间的终点 | `2024-12-31` |

也接受带时区的完整时间，如 `2026-11-01T09:00:00+08:00` 或 `2026-11-01T01:00:00Z`。日期必须真实存在；完整时刻不能省略时区。来源精度和原时区字符串保留，不补猜具体发生时刻。日期与完整时间混合比较时，仅为校验期间先后将日期锚定 UTC 当日零点；这不代表事件实际发生于零点。建议期间两端使用一致精度。

留空表示未说明，不表示永久有效。期间仅描述事实：过去记录可以用于历史问题，未来安排不能被说成已经发生。结束日期不是删除／保留期限，不会自动删除资料，也不自动覆盖同类事实；不承诺模型每次都能正确判断当前状态。

保存错误时表单保留输入，焦点移至错误提示，允许修改后重试。保存期间阻止重复提交，暂不可关闭弹窗。来源窗口展示当前时间和新版本保存的历史标注；升级前修订没有相应元数据时不补造。

## 接口与一致性

沿用 `POST /api/memories`、`PATCH /api/memories/{id}`，字段为 `event_at`、`valid_from`、`valid_to`，值是字符串或 `null`。PATCH 仍要求内容与版本；未提供的主体、类别、时间保留原值。显式 `null` 清除时间。只改一个期间端点时会与保留的另一端合并校验，错误返回 422，旧版本提交返回 409。

旧自由文本时间可读取；编辑器未改动时不重新提交它们。要更改期间且另一端为旧自由文本，须同时修正或清空该端。新值格式校验与历史读取分离，不因新规范导致旧记录无法打开。

修订保存旧主体、类别和三类时间。更改任一依据沿用统一版本、索引和回答失效链。删除记忆清除正文、主体、时间及修订；派生来源失效也清除新增的修订元数据。独立删除记录恢复重放继续有效。

## 索引与上下文

普通聊天和子助手使用权威记忆元数据，配合本回合服务器请求时刻的 UTC 参考，区分主体与事实期间。聊天保存 `memory_context_version=temporal-evidence-v1` 及参考时刻；子助手节点调用使用 `delegation-memory-time-v2` 提示版本。实际模型的语义判断仍需独立评测。

新建／纠正后的索引写入附带主体与时间标注；已有索引不因升级自动重建。召回仍以当前工作区、主体权限、版本与删除状态过滤，只接受框架的文档编号，不能把索引生成的文字当作权威事实。Markdown 和 JSON 导出保存当前标注，下载时按最新删除状态生成。

本批无数据库迁移，维持 schema0059；不更改正式服务连接、密钥、网络代理或 QQ，不触发既有记忆的自动重新索引。
