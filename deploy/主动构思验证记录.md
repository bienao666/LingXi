# 主动交流模型构思验证记录

版本 v1.45，2026-10-31。迁移 `0039`。本记录区分可执行功能、隔离协议验证与真实模型表达质量。

## 使用与范围

在“主动交流 → 联系偏好”开启“使用模型构思主动交流”，保存前核对来源会发送到当前已验证固定对话模型以及可能产生的费用。默认关闭，模板方式不额外调用模型；开启后的失败不以模板冒充成功。沿用既有四字菜单、午夜蓝组件与启动身份流程，不增加页面顶部介绍区。

仅发送当前话题的授权来源：有效的本人明确记忆、已生成项目计划或已授权插件报告。不会额外读取完整个人档案、聊天或附件，也不获得工具、安装、发送或长期记忆写入权。模型可选分享一条明确标为建议的下一步，或决定无新价值／背景不足而不联系；不以联系量或回复率为唯一目标。

事实引用须为指定来源的连续非空原文；计划和外部报告分别说明其性质。结构、引用及常见后台活动／结果／情绪断言检查只提供边界验证，不能证明建议全部正确；不能宣称已独立验证新发现或充分理解用户心情。

## 执行与恢复

- 调度器只入队，不等待网络；独立 worker 在持久化 `proactive_draft` 作业执行，固定模型、连接、策略及提示版本。没有跨模型自动降级。
- 同一用户同时最多一个等待构思／投递的话题；每日自动新话题构思次数最多为联系偏好的每日上限，失败及放弃同样占自动预算。显式重试另行确认一次模型调用，仍不得与其他构思重叠。
- 构思前核对时机，完成后核对来源／主体／话题／模型／联系偏好，实际投递前再次检查安静时段、最近发言、额度、间隔及授权接收者。QQ 离线等待，不改投 Web；未回应不催问、不自动播音。
- 失败或中断不自动重复计费；“待续话题”显示构思状态、模型、轮次与脱敏错误。点击“重试构思”查看数据范围与费用，确认时校验话题及构思版本，旧请求不能重复排队。
- 若入队后、模型尚未开始调用时变得忙碌，则保存为 `deferred`，合适时自动安排下一轮；这一路径没有发出模型请求，不属于重复计费。页面轮次包含未调用模型的等待调度，实际用量以调用记录为准。已经进入 `running` 的中断仍只能经人工确认重试。
- 纠正、删除、到期、插件撤权、话题关闭及联系设置改变阻止迟到结果并清理未投递正文。已发生的模型请求不能追溯撤销，已发送消息不能承诺收回。
- 最新恢复检查点只保留无正文构思屏障；旧备份恢复后关闭主动交流、隔离旧作业，按来源去重防止重新建立话题后自动重复计费。有屏障数据时拒绝直接降级到 0038，须使用升级前备份和配套镜像。

新增接口 `POST /api/conversation-topics/{identity}/generation-retry`，要求 `version`、`draft_version`、`acknowledgement=retry_one_model_call`；身份、CSRF、工作区与当前授权均在服务端检查。`TopicView.generation` 只返回状态和元数据，不暴露未投递正文。

## 实际限制

真实模型的建议质量、中文记忆 150 题、长时间主动交流的相关性／自然程度／打扰感仍待验证。当前支持来源引用加下一步建议，不包含无依据自由闲聊、后台自主研究、未经接入的日程发现或原生实时语音主动插话。构思失败不会阻断正常文字聊天；外部模型不可用时应核对服务设置或显式改用模板。
