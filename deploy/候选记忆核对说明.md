# 候选记忆核对（v1.77）

本增量补齐 MEM-03／MEM-05／MEM-07 的普通对话候选人工核对流程。不会自动判断事实矛盾，也不是实际模型抽取或中文质量评测。

## 使用流程

进入「长期记忆 → 候选记忆」，选择一项等待处理的普通对话候选，点击「核对保存」。子助手候选沿用原来的协作来源采纳流程。

1. 对照待存内容、事实主体和完整用户原文。引用、假设、临时例外不能仅凭提取结果当作稳定事实。主体不明时拒绝此项，再按正确主体手动记录。
2. 查看同一主体、同一类别的相关记忆。默认展示最新 20 条；可按正文关键词检索，显示总数、匹配数和未显示提示。同类不代表冲突，未显示的记录不代表已经核对；无需调用模型或 Hindsight。
3. 选择「新增记录，保留已有事实」，或明确选择一条旧项进行纠正。共用同一条原文的记录不能互相纠正，可新增保存。跨主体、跨类别和失效旧项不可选择。
4. 按新事实填写事件时间或适用期间。日期格式沿用[时间依据说明](./记忆时间依据说明.md)。留空表示未说明，不继承旧项日期；期间不会自动删除、结束或覆盖其他记录。
5. 点击「预览保存」，核对原有内容、确认后内容及影响，勾选确认后保存。不授予后续自动保存权限；关闭或返回修改不写入记忆。

新增只创建当前一条记忆，可保留历史事实和临时例外。纠正使用已有记忆的版本链，保存旧内容、主体及时间，关联新原文与本次人工确认，并使引用旧项的回答、衍生结果和主动候选失效。记忆索引状态与实际处理进度保持分离。

## 接口与一致性

| 接口 | 用途 |
|---|---|
| `GET /api/memory-candidates/{id}/sources?q=关键词` | 普通候选的原文、相关记忆及范围统计；协作候选仍返回原协作来源结构 |
| `POST /api/memory-candidates/{id}/review` | 明确选择 `keep`／`replace`，携带可选新时间，生成核对预览 |
| `POST /api/memory-candidates/{id}/actions` | 普通候选确认须携带 `review_token`；拒绝仍使用 `action: reject` |

纠正预览需要 `target_memory_id` 与 `target_version`，新增不能指定旧项。预览有效期五分钟，绑定当前工作区、所有者、登录、候选内容、原文和旧项权威版本；不包含可外用的服务密钥。新旧版本的时间均在预览展示。字段校验错误返回 422；过期、来源变化、旧项变化或主体不明返回 409；越权记录返回 404。

确认前重新校验原文、会话、渠道和记忆权限；自动转写或未确认的 QQ 音频不能借此成为事实。写入使用事务和行锁，同一候选重复或并发提交复用结果，不重复新增或纠正。来源在确认后删除时，仍沿用统一删除传播。新预览不改变旧项的独立保留期限。

普通候选旧式直接确认现在返回 409，需要先预览；第三方调用方须更新。子助手候选继续使用 `review_digest`，不增加自动纠正权限。确认错误会聚焦提示；冲突错误要求重新读取来源，连接故障可使用原预览重试。预览、返回和错误阶段均保留可用键盘焦点。

无数据库迁移，维持 schema0059；不更改真实模型、代理、QQ 或自动保存配置。本批不调用付费模型、不重建既有索引。
