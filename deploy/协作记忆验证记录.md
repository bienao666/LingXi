# 协作候选记忆验证记录

版本 v1.44，2026-10-31。迁移 `0038`。本记录区分代码、协议验证与实际模型质量，不把候选当成已核验事实。

## 使用方式

在“任务中心 → 任务列表 → 协作任务 → 新建协作”勾选“允许提出候选记忆”，或在 Web 文字聊天的“助手协作 → 协作授权”单独勾选。默认关闭，与“共享相关记忆”分别授权；旧任务、QQ 协作和语音不会因此取得写记忆权限。

分析节点可返回最多三项 `memory_candidates`，包括内容、七类之一、主体、理由和非空来源引用。只允许当前任务原文 `task-goal`、节点已取得的记忆、分配附件或直接成功依赖；不能发明引用，也不能在汇总中夹带写入。目录节点和工具节点不直接提议，分析节点可基于经授权依赖提出待核对内容。

节点结果在汇总成功后经 `MemoryService.submit_agent_candidates` 进入统一候选队列，始终为待确认。失败、取消、迟到响应、预算不足或来源失效不发布候选；已有低风险自述自动保存开关不适用于子助手提议。模型输出只能创建提议，不能确认或授予后续自动保存权限。

在“长期记忆 → 候选记忆”点击“核对保存”，检查内容、主体、原始引用、模型、人格、角色及插件版本；附件可打开原件解析预览。候选主体不明确时拒绝此项，按正确主体手动记录。勾选采纳后单独确认，保存为 `user_confirmed`，保留来源而不是标成用户原话。每次只保存当前一项，重复确认复用原记忆及索引任务。

新增 `GET /api/memory-candidates/{id}/sources` 返回候选快照与审阅摘要。既有动作接口增加 `review_digest`，协作候选确认必须匹配；普通用户消息候选保留既有行为。所有入口复用所有者、工作区、登录、CSRF 和服务端范围检查。

## 来源与失效

候选记录任务、节点、轮次、模型与服务版本、人格／角色、插件版本及第三方角色制品摘要，且保留实际引用。待确认时重新核验原任务、来源、附件、固定模型和角色授权；撤销、重试轮次变化、来源纠正或删除使待写入内容失效并清理正文。相同节点同一提议已拒绝后不自动重建。

已采纳记忆是用户资产，停用角色或卸载插件不自动删除它。相关记忆和附件依赖仍携带权威版本：依赖到期立即排除召回；纠正或删除则删除派生记忆、清理候选与索引，并写入删除记录。派生事实的派生事实同样传播。用户主动纠正记忆后，新版本作为独立用户事实，旧派生修订在原来源删除时清除正文。删除会话可沿既有选项保留或联动删除用户已确认记忆，不擅自改变选项语义。

备份检查点携带最新权威记忆及其来源依赖；恢复隔离旧待确认提议，不重放确认。存在来源数据时禁止降级丢弃 `origin`／`provenance`，回退使用升级前备份和配套镜像。
