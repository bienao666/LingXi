# 记忆索引恢复说明

适用版本：v1.83，数据库版本仍为 `0060`。

## 操作

在「长期记忆 → 记忆列表」选择一条记忆的「索引状态」。窗口显示当前索引代际与实时作业状态，每次查询完成后约五秒更新，手动更新不与轮询叠加。

- 可以检索：当前代际已就绪，无需重试。状态不承诺某次检索一定命中。
- 等待处理／正在索引：继续使用原作业，展示本轮尝试次数及适用的自动重试时间；浏览器断线不取消作业。过期租约交由 worker 接管，不由浏览器另起作业。
- 处理失败／等待恢复：先检查记忆服务、代理和模型连接，再确认重试。只重建这一条，不改变记忆正文，可能产生模型费用；每轮最多尝试五次。重复点击不生成并行作业。
- 记忆失效：已删除、到期或派生来源失效，不能重试。正文已被纠正时关闭旧窗口，在最新卡片重新查看。

作业次数只表示本轮已认领次数，不是模型计费次数。缺失作业显示零次；就绪状态不虚构累计次数。上游私密响应、网络地址、凭据与原始异常不进入状态响应。重试后焦点进入处理状态；失败时聚焦可恢复错误，关闭返回原入口。

## API

所有接口要求正常登录与当前所有者／工作区范围。POST 同时要求 CSRF。先调用：

```http
GET /api/memories/{id}/index
```

响应包含 `version`、`epoch`、`status`、`attempts`、`retry_at`（Unix 秒或 null）、`can_retry`。可恢复时，明确确认后提交所看到的版本：

```http
POST /api/memories/{id}/retry
Content-Type: application/json

{"version": 1, "epoch": 3}
```

`version` 至少 1，`epoch` 至少 0；均为必填，不再接受旧版空请求体。返回更新后的状态。事实版本、代际或有效性变化返回 409；无范围权限返回 404。等待／执行／已就绪请求只返回真实状态，不重新执行。

## 执行与兼容边界

新建、纠正、CLI 重建与备份恢复通过共同 outbox 入队，写入时固定索引代际。恢复根据记忆 ID、版本、工作区及代际查找作业，不再依赖只有新建记忆才有的固定键。失败作业重新排队会清除旧错误与租约令牌；无作业时使用稳定恢复键，配合记忆行锁避免重复创建。

旧版 `reindex:{epoch}:...` 作业从键中恢复当时的代际。旧版新建／恢复作业若未记录代际，无法倒推历史；在首次执行的事务中记录当前代际后才发出请求，以后自动重试沿用。配置变化前必须按现有 CLI 要求停止服务并等待租约到期；本次没有提供在线更换嵌入模型或改变向量维度能力。

worker 发起与发布前检查当前事实及代际。旧代任务不写入新代，迟到成功按原代清理；失败终结不得把新事实、新代或当前已就绪状态改成失败。删除屏障与独立删除记录继续生效，索引重试不能恢复已删除事实。无法收回已发送给上游的数据，物理清理由服务与网络可用性决定。
