# 聊天任务协助

当前批次支持在独立 Web 文字对话中安排一项内置任务。实际模型的意图识别质量仍待验证；本功能不是通用工具执行器。

## 使用

1. 在模型管理中验证并选择对话模型，启用内置插件对应能力。
2. 在聊天输入框开启“任务协助”，填写完整请求后发送。开关默认关闭，不写入浏览器持久存储；开启时附件入口不可用。
3. 可提出“帮我规划一次项目演示”“列出服务器资料根目录”“明天下午三点提醒我带提纲”。提醒按联系偏好中的时区解析，回执显示绝对时间，请核对。
4. 灵犀自动选择项目规划、资料清单或一次性站内提醒；每条最多一项。缺少信息时不创建任务，提示补充完整请求。普通聊天继续使用正常回复链路。
5. 原对话中的任务卡展示等待、执行、失败、取消和真实结果，也可进入任务中心查看详情。关闭浏览器不取消已提交工作。取消需确认，已产生的模型费用不能撤销。

项目规划只生成步骤和完成条件，不执行计划。资料清单只读取服务器授权卷目录元数据，不读取用户电脑或文件正文。提醒到期更新站内记录与原卡片，不发送 QQ、浏览器推送或播音。未开启任务协助的消息不会因此自动创建任务。

## 调度与一致性

- 兼容 OpenAI、Anthropic、Gemini 的文字 JSON 意图解析；复用既有模型网关、密钥、代理、网络边界和调用审计，并非供应商原生工具消息链。
- 每次开启的消息通常增加一次模型解析调用。项目规划会再调用其固定模型。未配置价格时费用仍为未知。
- 解析器只接收当前用户原文、可用能力 ID、当前时间和时区；不读取附件、人格提示、私人记忆或完整历史。跨回合补充尚未自动合并为任务，需提供完整请求。
- 服务端固定允许能力及插件版本，最终派单重新校验现有授权、版本、输入、目录范围、提醒时间、主体和工作区。模型不能安装插件、扩大授权、执行脚本、删除资料或选择任意工具。
- 同一聊天请求编号包含任务协助开关的语义；同编号不同内容或开关冲突返回 409。聊天关联、任务、队列和接受回执在同一事务提交，断线或重放不重复派单。
- 意图解析失败不伪装安排成功；标记“理解暂不可用，本条未安排任务”，正常文字链路仍可继续。授权变化或参数无效显示真实失败，不自动换能力执行。
- 接受回执只表示任务已创建；卡片状态及核验结果才反映实际执行。近期后续聊天最多读取四条任务事实，每条结果预览最多 800 字符并标明截断，不声称完整阅读。
- 原对话、原消息或关联生成依据失效时，立即停止结果查询；异步清理关联任务输入、输出和提醒正文，并阻止迟到结果重新发布。此类任务以动态卡片呈现，不再另建一条可能失效的后台结果消息或主动话题。

## 接口与迁移

`POST /api/chat` 增加可选 `task_assist: boolean`，默认 `false`，保留原文字请求的幂等摘要。`GET /api/chat-actions?conversation_id=…` 返回本人当前工作区的关联卡片，复用登录及会话访问检查；取消沿用 `/api/tasks/{id}/cancel` 或 `/api/reminders/{id}/cancel` 的版本检查。

迁移 `0017` 新增 `chat_actions` 来源关联，不改已有聊天、模型、凭据或手工任务。存在关联记录时拒绝降级，以免旧程序绕过来源检查；需回退时恢复完整升级前备份及配套镜像。只回退界面不能撤销已创建任务。

QQ 入口、语音提交、带附件消息、第三方插件自动选择、多步工具链与外部写操作尚未接入本批。“任务协助”不自动转交子助手；另选“助手协作”后，主助手可自动决定分工，独立授权与边界见[子助手协作说明](./子助手协作说明.md)。真实提供商、自然语言时间及意图质量需要单独评测，协议夹具通过不等同于这些质量达标。
