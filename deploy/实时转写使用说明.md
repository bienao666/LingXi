# 实时转写使用说明（v1.57）

支持边说边显示临时字幕，结束录音后返回最终修订稿。输入走原生转写连接，回答仍由灵犀核心生成，再用现有合成服务播放。未包含原生模型直接回答和连续模式原生输入。

## 配置与验证

1. 在服务连接中配置支持原生转写 WebSocket 的 OpenAI 协议供应商。根地址按供应商填写，Core 只追加 `realtime?intent=transcription`，不再添加 `/v1`。普通 Chat Completions 兼容不意味着支持实时转写。
2. 在“语音配置”中启用语音，配置并验证普通转写与合成模型。
3. 在“实时识别”选择供应商与实际支持的转写模型。按供应商协议选 `language` 或 `languages`；例如 `gpt-live-transcribe` 使用 `languages`。模型名称只是示例，不保证账号权限或供应商可用。
4. 保存配置，在“实时验证”点击“实时转写”，允许麦克风并说一句话，点击“结束转写”。收到有效定稿才标记验证通过；只连接成功不算通过。验证可能计费，不创建聊天或长期记忆。
5. 打开智能对话，关闭“连续对话”，显式“开启语音”，然后点击“实时转写”。检查最终稿后点击“确认发送”；可以编辑或丢弃。

配置、供应商版本变化后需重新验证。修改默认音色不影响实时转写验证，但会结束旧语音会话；语言与实时模型变化会使实时验证失效。界面上的“接口已验证”只说明协议通过，不证明识别质量。

## 连接与数据

- 浏览器使用 HTTPS 或 localhost 的安全上下文，并通过 `LINGXI_PUBLIC_ORIGIN` 配置的同一协议、主机和端口访问；本机当前入口为 `http://localhost:8080`，不要混用 `127.0.0.1`。Windows／macOS 无需安装本地组件；允许麦克风后只采集明确开启的片段。
- 浏览器只连接同源 Core，不接触供应商密钥。Cookie 与短期单次票据共同认证，票据在首帧发送，不进入 URL。签发使用现有 CSRF 校验；跨来源连接被拒绝。
- Core 复用已配置的系统 HTTP／HTTPS／SOCKS5 代理、目标地址授权、DNS 固定与 TLS 验证，不在代理失败时私自直连。
- 每段最长 58 秒、24 kHz 单声道 PCM16；输入、字幕及上游消息均有预算。每人最多一个实时片段，共用每分钟 30 次音频请求限制。
- 临时字幕可以修订，不是已确认事实。定稿需匹配本段音频回执，不接受其他片段定稿。音频和字幕不持久化；调用记录仅保存模型、版本、状态、耗时等元数据，用量未提供、价格缺失时费用未知。
- 迁移 `0050` 的短期票据表仅保存授权哈希、关联范围、版本与状态。超过一天的过期授权随新授权清理；备份恢复取消旧授权。

## 取消与故障

“取消转写”、页面隐藏、断网或离开页面立即关闭本地麦克风和连接，晚到字幕不提交。票据消费一次；错误后须手动重试，不自动重连、重复计费或切换模型。取消不保证上游未计费。

服务器会持续复查登录、语音会话、配置、供应商、系统代理及迁移状态，返回定稿前再核验。撤销或变更后丢弃结果；取消只影响转写，不取消已经确认提交的聊天任务。

连接失败先检查服务确实支持 GA 转写协议、模型授权、语言字段、容器代理与反向代理的 WebSocket 升级。生产反向代理为 `/api/voice/realtime` 单独配置 Upgrade；Vite 开发代理启用 WebSocket。失败时普通文字聊天继续使用，普通上传转写需手动选择。

## 资料与验收边界

协议依据 [OpenAI Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription) 和 [WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets)。供应商兼容性以实测为准，不自动换用其他模型。

本地协议服务及合成音源用于校验安全、代理、字幕与恢复行为。实际供应商、物理麦克风、中文准确率、声学回声和延迟仍待验证，详见[验证记录](./实时转写验证记录.md)。
