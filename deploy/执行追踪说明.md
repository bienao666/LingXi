# 执行关联追踪

本说明对应 v1.62。入口为“数据日志 → 执行追踪 → 查看追踪”。

## 查看关联

在详情中的“执行关系”选择一个节点，仅查看与该节点直接相连的关系；选择“全部关系”可查看本次返回的全部关联。关系两端按钮用于切换当前节点。节点显示编号、类型、当前记录状态及可用的版本或尝试序号，原有阶段记录与模型调用继续展示。

| 记录 | 关联依据 |
| --- | --- |
| 对话与任务／协作／提醒 | `ChatAction` 的真实执行目标及一致的会话归属 |
| 协作节点及其依赖 | 已保存的父执行、节点 ID 和依赖键 |
| 子助手与插件 | 节点调用 ID、插件来源中的父执行和节点 ID 双向一致 |
| 模型调用 | `run_id` 或已保存的任务／协作／插件关联字段；节点调用另核对节点 ID |
| 记忆及附件 | 执行或节点已保存的版本化引用，不进行新的记忆检索 |
| 会话消息 | 实际所属执行、上下文消息 ID 或结果消息 ID，并通过会话证明归属 |
| 执行尝试及提醒回执 | 实际任务或提醒 ID |
| QQ 收信、协作及投递 | 实际入站执行 ID、协作请求 ID 和投递所属入站 ID |

相同会话、相近时间或相同模型不代表执行关联，不据此连线。只有当前身份与工作区可访问的记录进入视图；QQ 隔离主体的私人消息和附件不会因所有者能查看协作执行而继承到图中。缺少可访问关系时显示暂无关联，不补造历史。

记忆节点显示当前记录版本和状态，关系单独显示执行当时引用的版本；旧引用不表示记忆当前仍有效。已删除记忆仅显示编号、状态和版本等元数据。协议 `accepted` 仅显示“协议接受”，不推断送达或已读。图不展示用户正文、人格提示词、记忆内容、文件名、路径、密钥、工具输入输出、回执正文或上游错误。

## 接口与预算

沿用只读接口 `GET /api/admin/traces/{kind}/{identity}`，`kind` 为 `chat`、`task`、`agent` 或 `plugin`。新增的 `graph` 包含 `root`、`nodes`、`edges`、`truncated` 和说明，具体字段以 [OpenAPI](../backend/openapi.json) 为准；前端类型由同一契约生成。

每图最多 200 个节点、400 条关系、100 次查询，每次查询最多返回 50 条。查询与引用列表均受限，去重并防止循环展开；预算耗尽时设置 `graph.truncated`，前端明确提示“当前关系不完整”。原阶段和调用列表的 200 条限制独立显示，不混用完整性标志。页面加载失败可原位重试；读取和节点切换不会重新执行模型或工具。

本批没有数据库结构变更，迁移保持 `0050`。当前是基于现有记录的执行关系视图，不代表所有后台事件已采用统一 trace ID，也不补建历史记录。主动交流、全部记忆 outbox／索引内部步骤和原生语音传输的完整跨服务追踪仍需后续完善。

## 验证边界

SQLite 运维与关联专项 47 项、独立 PostgreSQL 运维／关联／费用／聊天派发／协作／工具／渠道专项 215 项、前端全量 370 项通过；类型、菜单与动画静态检查及构建通过。新增覆盖四类根记录、双向关系、依赖、状态／历史版本、跨主体与跨工作区隔离、非互认工具来源、同会话不推测、循环和各预算上限、空关联、重试和节点切换。

独立 PostgreSQL、Nginx 和 Core 的 HTTP 测试使用合成持久记录，分别从对话、协作和插件入口得到同一组 9 个节点、13 条关系，正文未出现在响应。它验证查询和关系合约，不证明这些合成任务曾通过真实模型、工具或 QQ 执行。浏览器另检查四个标准断点、节点选择、历史引用与当前删除状态；未在正式工作区增加测试账号或业务数据。

本地证据位于 `.preview/v162-backend.log`、`v162-pg.log`、`v162-frontend.log`、`v162-build.log`、`v162-http.log` 和 `v162-traces-*.png`；日志、截图与测试环境凭据不提交 Git。真实供应商、真实 QQ、物理音频及 150 题中文记忆质量继续保持待验收。
