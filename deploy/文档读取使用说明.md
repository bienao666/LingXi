# 文档读取使用说明

适用版本 v1.55、数据库迁移 `0048`。这是服务器只读文档快照，不是用户电脑访问、执行脚本或自动同步。

## 准备与授权

1. 依照[资源授权说明](./资源授权使用说明.md)为 Core、worker 提供同一只读资料挂载；容器 UID 10001 须可读取。不要挂载凭据、数据库或系统目录。
2. 在“插件中心 → 插件商店”找到“文档读取”，核对第一方 `lingxi.documents:1.0.0` 的 `resources.read` 权限，预览并确认安装。仅浏览、推荐或预览不会安装。
3. 在“系统设置 → 资源授权”填写“相对目录”和单独的“正文目录”，先预览再确认。例如清单范围 `projects`，正文范围 `projects/docs`。正文目录必须位于清单范围内，可留空关闭；每类最多 20 个，不能同类重复或互相包含。

已有挂载、清单授权、角色或 QQ 身份绑定均不自动授予正文读取权。正文路径不能离开授权范围，不能使用盘符、绝对路径、`..`、符号链接、硬链接、管道或设备。首版只接受普通 TXT、Markdown、CSV、文本 PDF、DOCX、XLSX，大小及类型同时遵守当前附件策略，上限 20 MiB。

## 读取与聊天

在“任务中心 → 任务列表”新建任务，选择“文档读取”，输入如 `projects/docs/readme.md` 的相对文件路径；可选将完成提示写回已有 Web 会话。浏览器关闭不停止服务器作业。

任务详情的“执行成功”表示已保存当时的只读快照，不代表文档解析成功。在“预览文件”查看等待解析、正在解析、可用或失败状态及具体来源位置，也可到“数据日志 → 文件管理”查看。扫描 PDF 等不能解析的内容明确失败；不会以截断内容声称完整阅读。

聊天中点击“选择文件”，选中可用快照并发送问题，才会把解析内容交给当前模型。协作任务也可显式选择该附件并按原模态与上下文范围使用。此次新增不允许子助手直接任意读取服务器正文，也不扩大 QQ 的目录权限。

快照记录原相对路径、读取时间、修改时间、SHA-256、任务和插件／授权版本。原文件后来修改不影响既有快照，也不会触发后台同步；读取新版本请新建任务。相同请求重复提交返回原任务，不重复导入，也不复活已删除快照。

## 撤销、删除与恢复

修改任何资源范围，包括只增加目录，均使旧资源版本的任务、快照和派生上下文停止使用。插件停用、卸载或撤销会停止新读取、取消旧读取任务并清理旧快照。重新授权或启用不恢复旧快照，须新建读取任务。

删除附件只删除受控快照及解析结果，不改动服务器原件。关联在途回答、子助手上下文及依赖来源一并失效，已经发给外部模型的资料无法撤回。旧备份恢复后先清空清单和正文授权并递增版本，不能把历史快照当成新授权。

升级前保留数据库备份及配套镜像。`0048` 为旧记录增加空正文目录和空媒体来源，不扩大旧权限；已有正文授权或来源快照时拒绝有损降级。服务器迁移仍要求同版镜像，不能仅凭相同 schema 任意互换版本。

## 故障处理

找不到能力时先检查插件安装／启用和正文范围；资料卷离线时不读取，可撤销全部授权。文件在读取中变化、格式不支持、超限、无权限或解析失败均明确报错。任务重试保留原插件及授权版本，不绕过撤销。备份与恢复操作参照[备份恢复说明](./备份恢复说明.md)。
