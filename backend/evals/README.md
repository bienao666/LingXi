# 中文记忆评测（v1.75）

`memory-150.jsonl` 包含 150 个不同问题：事实偏好 30、事件项目 25、更新时态 25、主体引用假设 20、未知争议 20、删除 15、重启重投递 15。`dataset.py` 为可复现源文件。

## 实际运行

必须在**独立且为空的评测部署**初始化 `eval-lingxi` 所有者，配置真实模型与 Hindsight，并关闭该专用账号的自动保存记忆。账号不能有可见会话、记忆或候选；不要把日常部署改名用于评测。脚本只读预检，条件不满足不会创建业务数据或代为改配置。

`run.py` 依赖后端环境中的 `httpx`。以下命令会调用该隔离部署已经配置的模型／嵌入／重排／抽取服务，可能计费；只有明确指定 `--allow-model-calls` 才会登录和运行。不要对正式入口执行。

```sh
python backend/evals/run.py --base-url http://localhost:8081 --allow-model-calls --limit 1 --output .preview/memory-eval/smoke.json

# 小范围验证并核对清理后，用新输出执行完整150题。
python backend/evals/run.py --base-url http://localhost:8081 --allow-model-calls --output .preview/memory-eval/results.json
```

密码和可选 TOTP 交互读取，不写入参数、检查点或报告。非本机入口须 HTTPS，不接受带凭据、参数或子路径的地址，不跟随跳转；客户端直连管理入口，模型请求仍由 Core 的统一网络配置处理。运行结束尝试退出本次登录。

检查点默认位于 Git 忽略的 `.preview/`，包含合成夹具的实际回答、当前模型／配置版本白名单、检索记忆版本及清理回执。不要提交原始结果或复核文件到公开仓库。每次创建／写操作前落盘意图，取得可追踪回执后记录编号；原子更新检查点。输出已存在时拒绝覆盖，**不提供自动断点重放**。

发生连接异常、索引失败、取消或清理不完整时保留证据并停止后续题。只清理本题已取得编号的会话、记忆及执行，等待明确的删除清理状态；不按标题扫描删除，不忽略失败。结果未知的创建或删除不盲目重试；须在隔离部署按检查点核对，清理完成后再开始新一轮。中断文件保留全部计划题号，未执行题为 `not_run`，不能被省略后算成满分。

重投递题使用同一幂等请求，检查执行 ID 相同；不同运行使用不同请求前缀。重启题需要操作者实际重启后填写说明，但该说明只标记为人工确认，不能替代容器及系统运行证据。来源检查区分普通漏召回与跨题／失效版本：漏召回降低正确题数，失效或外来来源阻断准入。

## 离线复核与报告

`report.py` 只依赖 Python 标准库，不连接服务器或模型。它只接受当前固定数据集的 v2 原始结果；早期文件不能直接当作完整证据。先生成复核模板：

```sh
python backend/evals/report.py prepare .preview/memory-eval/results.json --output .preview/memory-eval/reviews.json
```

在本地 JSON 中填写顶层 `reviewer`，逐题核对实际回答、原始夹具及记录中的来源，填写以下字段。模板不会预填通过，也不自动采用模型判分；本工具要求逐题复核，高于设计中至少抽查 20% 的最低要求。

| 字段 | 填写方式 |
|---|---|
| `correct` | 来源支持、主体和时间均正确时为 `true`，否则为 `false` |
| `unsupported_assertion` | 有任何无依据断言为 `true`；没有为 `false` |
| `blocking_issue` | 严重主体误归、泄漏、删除复活等阻断问题为 `true` |
| `reason` | 具体判分依据，不能留空 |

`null` 表示未复核；字符串 `"false"`、数字和没有理由的勾选不算有效。题号、题目、答案和结果摘要必须保持一致；回答、模型、来源或清理状态一旦改变，原复核失效。修订判分须重新生成新的汇总文件，旧报告不覆盖。

```sh
python backend/evals/report.py summarize .preview/memory-eval/results.json --reviews .preview/memory-eval/reviews.json --json .preview/memory-eval/summary.json --markdown .preview/memory-eval/summary.md
```

汇总固定基线分母，不只统计已运行或已复核题：前五类 120 题至少 108 题有依据且正确，未知争议 20 题最多 1 题存在无依据断言。缺题、来源或清理证据不足、执行错误和未复核不能判通过；单个严重问题不能被高平均分抵消。未齐全时显示的无依据断言计数不能视为已达标。

退出码：`0` 为模板已生成，或完整回答门槛通过；`2` 为已生成报告但仍未齐全、未通过或存在阻断；`1` 为格式、摘要绑定或文件输出失败。**即使汇总退出 0，也只表示 `answers_passed_system_checks_pending`，不表示完整系统验收通过。**

本数据集测量用户确认资料的检索、来源、更新和生命周期。抽取质量由独立的原文／主体／引用回归测试及人工样本审查检验，不能用检索得分冒充抽取质量。重启场景要求操作者实际重启服务；未知、争议和删除后的自然语言回答须人工审查，不能仅靠关键词判断无依据断言。

报告按题保存实际回复与状态；`needs_review` 不是通过。删除缓存、在途任务、重试、备份恢复后的删除重放和数据隔离，需要另外的确定性系统验收；不能只凭“我不记得了”的自然语言回答判定。`full_product_verified` 固定为 `false`，自动抽取与系统生命周期门槛明确为 `not_covered`。完整质量门槛仍按设计方案执行，没有真实模型、实际系统证据或人工判分时，保持待验证。
